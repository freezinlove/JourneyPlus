# 模型调用耗时诊断

每次模型请求结束后，以 `model.timing` 事件写入现有 `agent_delivery_events`，通过 run_id、attempt 关联当前用户工作区及调用轮次。服务重启后保留，随会话 24 小时过期或新会话清理一起删除。诊断事件不进入模型上下文，不复制正文、工具参数或凭据。

记录内容：

- context_prepare_ms：上下文加载、投影、输入估算及调用前存储准备，直到开始模型适配器调用。
- marks：相对适配器开始时间的请求准备完成、响应头、首个 SSE 数据、首个文字、首个工具片段、响应结束、工具参数校验完成时间。未发生的节点缺省，不以零冒充。
- transport：HTTP 客户端的 TCP 建连、TLS、请求头/请求体发送、响应接收等事件名称和相对毫秒数。连接复用时没有新的建连事件。连接池、DNS 等未被单独暴露的阶段不能凭空拆分。
- elapsed_ms / harness_elapsed_ms：适配器及 Harness 观察到的请求总耗时。
- usage：供应商返回的输入、输出、缓存创建和命中 token 等用量；没有返回就保持缺省。另记录输入字节量、工具定义字节量、工具返回字节量。
- 模型、协议、思考开关、显式缓存开关、HTTP 状态、结束原因、错误类型和取消标记。

发送请求体完成到响应头的间隔包含网络往返及供应商处理等待，不能分辨供应商内部排队与推理。首个 SSE 数据也不一定是文字或工具输出，因此分别记录。流式响应耗时可能包括本地消费和事件持久化，并非纯模型生成速度。非流式 JSON 协议只能在完整响应返回后观察文字及工具，不能推断真正的首 token 时间。

工具执行继续使用现有 ToolCall.started_at/completed_at 和 tool.started/tool.completed 事件，与模型事件一起查看即可定位每轮链路。没有增加模型调用或限制。

## 验收

- 请求并发的诊断隔离、无文本工具调用、缓存用量、超时保留部分计时、无传输敏感字段、数据库重新读取及诊断不进入上下文均有测试。
- 37 项模型/Harness/多用户相关测试通过，另补充超时测试通过。已有模型测试 `test_wire_container_decoding_preserves_values_and_canonical_validation` 使用当前已移除的 allow_challenge 字段，单独运行仍失败；本次未修改该业务契约或将其算作通过。
- 正式服务、正式库、第三方 qwen3.8-flash 只读会籍请求成功：第一轮 1966ms，TCP 30ms、TLS 30ms、发送后等待响应头约 1829ms；第二轮 1542ms、缓存命中 14036 token。此样本不代表之前慢请求的原因或稳定延迟。
- 原始本机验收记录位于被 Git 忽略的 `.local/multiuser/timing-live.json`。

## 开关

环境配置 `JOURNEYPLUS_AGENT_MODEL_TIMING_ENABLED=true` 开启持久化模型耗时事件，改为 `false` 关闭；默认开启。修改 `.env` 后重启服务生效。关闭只停止新增 `model.timing` 诊断事件，不删除已有记录，也不关闭正常会话、工具执行记录或缓存。当前正式服务配置为开启。
