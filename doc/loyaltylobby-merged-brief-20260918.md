# LoyaltyLobby 标题摘要合入事实提取

## 变更

- 普通文章每个机会的 title、summary 与事实在同一次 ArticleInterpretation 中返回。新输出缺标题时提取失败，不发布不完整简报。
- 简报由程序绑定机会 ID、事实签名和来源链接后保存；没有独立 Brief 模型调用，也没有简报模型重试。程序组装的 AnalysisRun 标识 provider=program、model=none。
- 新格式 article-short-brief-1 与旧 Brief、官方 StatusMatchBrief 同时可读；映射、费用、个性化关系继续由事实读取层生成。
- 发布事务包含简报记录和当前指针。发布失败回滚，重试复用已保存的事实提取结果。
- v11 已发布文章在默认每日扫描中保留，不因版本升级重新调用模型。v11 未完成文章复用已有提取；缺少标题时用原文标题（上限120字符）兼容，不生成假中文标题、不重新扩写摘要。同文档新版本、不同模型配置仍按既有版本规则处理。
- 没有数据库表结构变更，没有重跑历史采集，没有修改服务器或启用定时器。

## 验证

测试覆盖单机会和多机会零额外简报调用、提取文案原样保存、产品列表及详情读取、历史格式兼容、升级不重跑、旧未完成结果复用、新提取缺标题拒绝发布、保存失败回滚与零模型重试。

扩大回归发现产品和官方简报测试中的6项旧失败；对照 HEAD 源码复现相同失败，涉及旧静态页面标记、未登录 API 请求、未知费用误期望 FREE。本次不修改这些无关业务语义。

改动尚未提交或部署。云端现有容器仍运行旧逻辑，需经过用户手动发布流程更新后生效。
