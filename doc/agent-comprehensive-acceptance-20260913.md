# Agent 正式链路验收与缓存实测（2026-09-13）

本次结论：正式服务可以完成多种真实会话，匹配读取、费用标记、卡片和数据库写入的已核对部分正常；不能判定整套 Agent 验收通过。优先缺口是过期会籍被模型改成假设起点继续使用，以及原文读取结果与模型自称读取范围不一致。

## 实测方式与范围

- 从正式 `/workspace` 页面逐轮输入自然语言，使用正式 PostgreSQL、现有 harness 和真实 qwen3.8-flash（native 协议、非思考）。未编排模型工具调用、未替换模型回答、未建立隔离数据库。
- 共 5 个真实会话、25 轮用户输入：19 轮多样业务验收，加两组三轮缓存对照。85 次实际模型请求、61 次工具调用尝试；25 轮均在运行层标为 COMPLETED，但这不代表语义全部正确。
- 用现有 `scripts/observe_agent_product.py` 临时旁路记录真实模型输入、工具定义、HTTP 请求正文、流事件及服务商 usage；未记录认证头。另只读保存正式库工具参数、结果材料、查询、展示材料、检查点及业务表前后快照。
- 主验收不改工具/提示词/业务逻辑。唯一永久实现改动是本次授权的 token 预算；缓存 B 只在临时启动脚本中移除历史缓存标记，其余仍使用正式服务。验收后已恢复正常 `python -m journeyplus.agent.server`，关闭完整请求观察，保留原有系统＋历史缓存。
- 原始 JSON 留在 Git 忽略的 `.local/agent-audits/comprehensive-20260913/`，不放进 doc 或提交。会话和正常操作回执按产品原有机制留在正式库。

## 需要修的实际缺口

1. **优先：过期后的“已保存会籍”查询被错误改成假设查询。** 第 18 轮真实更新到期日为 2026-09-12。saved 搜索返回空，`stopped_reason=SOURCE_IDENTITY_REQUIRED`；默认 holdings.read 也因过期过滤返回空。模型没有读 include_expired，而是回读创建回执，随后使用旧 tier_ref 发起 explicit 查询，并称“以当前保存的会籍重新查询”。数据库改期正确、过期过滤正确，工具没有清楚说明空结果来自过期，模型也改变了用户指定的来源模式。实际系统消息没有独立的当前日期说明。
   建议：工具明确返回没有有效会籍、排除过期项的数量/原因及判断日期；按 ref 读取时可明确告诉模型该记录已过期。提示模型不要把 saved 无结果自行改成 explicit。仍允许用户主动要求假设查询，不增加地区/金额等筛选规则。
2. **优先：请求原文后返回结构过于绕行。** 第 9 轮 activity.read 指定 document 片段后，原文存入 material，但给模型的是 source_sections_ref 和数量。模型用多关键词查材料无结果，再无关键词读取得到 646 节中的前三节，最终转读 option-route-0/1 中的结构化价格及程序生成 locator。它没读取 FAQ/terms 的实际原文片段，却声称已核对全部相关原文。价格正确，读取范围声明错误；不能记为“原文读取验收通过”。
   建议：模型已明确请求 document 片段时直接返回所请求的少量正文和后续入口；目录仍保持简短，不必默认塞整篇原文。让结构化字段、程序生成定位说明和原文正文在返回值上易于区分，无需恢复逐字段引用校验。
3. **模型解释有无依据推断。** 第 5 轮工具联盟归类正确，模型反而说肯尼亚航空不属于天合；第 6 轮最高等级选择正确，模型误称低等级来源没有映射。第 1 轮只读概要，却宣称全部活动进行中并自行排序门槛。应减少这些超出已读结果的断言，优先用清晰的选择范围说明，而不是叠加复杂输出协议。Kenya Airways 联盟归属另对照了[官方页面](https://www.kenya-airways.com/en-nl/plan/travel-information/skyteam-alliance/)。
4. **宽泛检索和引用使用还不够顺手。** 第 1 轮空选择器不支持浏览，多关键词查询为空，分页误拿结果材料当 activity_ref，活动卡误用 comparison；第 2 轮旧项目名 Executive Club 无法直接绑定，模型额外查询后恢复。建议补直接的分页浏览用法和必要别名、改善错误返回指向正确引用，保持模型自主选工具。
5. **图展示反馈破坏历史缓存前缀。** 实际双缓存请求 011→012，工具定义相同，第二条 system 消息由 capability_availability 变成 Client rendering reports，发生在历史对话之前。新一轮只命中 5,464 token 固定前缀，历史重建 10,583 token。这个差异来自真实 HTTP 请求，不是推测。可将动态渲染反馈放在靠近当前轮的位置，避免每次在历史前插入新内容；不应为了缓存删除有用反馈。

## Token 预算实际改动

- 每次上下文输入预算：500,000 token。单轮累计模型输入硬上限：500,000 token；软收尾阈值：450,000。两者是不同维度，累计预算包含同一历史在多次请求中的重复输入，也包含缓存命中的部分。
- 本地原 `JOURNEYPLUS_AGENT_CONTEXT_WINDOW=32768` 会提前压低上下文预算，现按当前模型容量改为 1,000,000；实际上下文目标仍是 500,000。官方 [qwen3.8-flash 参数](https://help.aliyun.com/zh/model-studio/qwen3-8-flash) 支持该窗口。替换模型时仍应遵守其真实容量。
- 默认值已同步到配置、组合入口、上下文投影和运行预算；本地 .env 已生效。85 次正式请求的最终累计 usage 与持久化预算核对相等：输入 1,536,215，输出 14,924。单轮最大累计输入 210,463，未触发 500,000 上限；没有做填满 50 万的极限请求测试。
- 未增加单次输出额度；请求次数、工具次数、时间等原有预算没有改变。

## 缓存实测

当前双缓存的 22 轮（主验收 19＋对照 A3）共 75 次模型请求：输入 1,403,395，命中 1,161,103，新创建 241,692，其余 600；输入 token 加权命中率 **82.74%**。因此实际命中的不仅是固定系统消息，连续工具调用的历史确实被复用。

三轮相同输入的对照，均使用已热的固定前缀，没有清空服务商缓存。所有模型决定由真实模型自主作出，因此两组请求数不同，这不是等请求数的随机性能基准：

| 指标 | 系统＋历史缓存 A | 仅系统前缀 B |
|---|---:|---:|
| 用户轮数 / 模型请求数 | 3 / 8 | 3 / 10 |
| 输入 token | 94,596 | 132,820 |
| 命中 token | 68,093 | 54,640 |
| 新建缓存 token | 26,439 | 0 |
| 未缓存输入 token | 64 | 78,180 |
| 输入加权命中率 | 71.98% | 41.14% |
| 输出 token | 1,703 | 2,292 |
| 按官方原价估算本组调用费用 | ¥0.0445 | ¥0.0742 |

B 每次只命中 5,464 token 的固定前缀；对话增长后的第三轮命中率降为 26.20%。A 第三轮即便因图反馈导致首个请求丢失历史前缀，轮内后续仍能复用历史，整轮命中率为 64.08%。本次样本支持继续保留双缓存；不能把两组费用差全部归因于缓存，因为 B 多了两次模型自主 inspect 调用。

费用按[模型官方北京原价](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)计算：普通输入 0.8、输出 2.7、显式创建 1.25、命中 0.1 元/百万 token。25 轮共约 ¥0.5270，不含启动探针、优惠、其他服务调用；这是 usage 计价估算，不是已读取阿里账单。缓存有效期及标记规则参照[官方缓存说明](https://help.aliyun.com/zh/model-studio/context-cache)。本次没有做超时过期/跨很久重开会话的缓存寿命实测。
