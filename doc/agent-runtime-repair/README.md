# Agent 运行存储修复与真实双视角验收

2026-09-12。用户授权实施四步修复：运行存储、迁移入口、就绪与网页错误处理、会籍记忆与等待适配，然后只替换第三方模型，重跑真实生产链路。

## 实施结果

正式 PostgreSQL `journeyplus` 已升级到 `0019_original_agent_runtime`，共 39 张表。新增的 8 张表全部是 Agent 运行存储。原活动、FactSet、简报、原文快照与来源、价格、会籍等 28 张非 Agent／非迁移版本表，列清单、行数与行内容指纹前后完全一致。

- 新增 `agent_workspace_messages`、`agent_turns`、`agent_run_checkpoints`、`agent_artifacts`、`agent_tool_calls`、`agent_operation_receipts`、`agent_delivery_runs`、`agent_delivery_events`。
- `agent_interactions` 补回现有 Harness 所需的 3 个字段。
- `agent_wait_goals` 补回现有等待实现需要的运行字段；保留旧表约束，没有新增更严格的 singleton 约束。
- `status_holdings` 不加字段。新适配器只映射原有列；原话与授权保存在已有 Agent 操作回执中。版本由实际行内容及更新时间派生，避免产品表单修改后 Agent 仍接受旧版本写入。
- 会籍保存、读取、更新、删除沿用现有工具协议、授权消息校验、事务围栏和幂等回执。等待工具不再触发弃用的统一模型操作重放日志。
- 产品原会籍表单同样支持原表，避免表单保存时偷偷建立另一套目录。

旧迁移 `0019_activity_knowledge` 至 `0028_agent_business_provenance` 原文件逐字移入 `migrations/retired_unified/`，不再属于活跃升级链。没有执行其中任何迁移，没有将版本号伪装 stamp 到尚未执行的版本。

当前活跃链是原 `0001–0018` 加新 `0019_original_agent_runtime`。产品启动仍执行正常升级，目标已是当前选定模型。Alembic 自动生成元数据也已明确限定为当前业务与运行表，正式库 `alembic check` 通过；再次 `upgrade head` 不产生修改。历史统一模型库仍保留备份，不能直接套用这条新链。

就绪接口现在检查运行表和列是否存在及能否读取。缺失时返回 `AGENT_STORAGE_SCHEMA_MISMATCH`，不会仅凭模型 echo 成功就声称 READY。模型禁用状态保持禁用。网页在会话创建／恢复失败后禁止发送并给出重试说明，不再访问空会话。

实测另发现图卡详情接口仍读取弃用活动表，已把活动列表、详情、历史接到同一个原模型读取适配器。详情渲染使用原字段；路线节点按实际 mapping_ref 和原始价格索引，只展开该步骤的映射与费用。AIWorkflow 的生产格式没有为页面改变。

## 真实验收方式

使用正式 `product-api` CLI 启动流程、真实 Uvicorn 服务、正式数据库和实际浏览器。`bridge.py` 只在进程中替换 `AgentModel.stream`，每次请求写出完整模型上下文与工具定义；Codex 收到后当场选择工具或回答，再交回 Harness。没有预设业务调用顺序、假工具结果、测试数据库或隔离运行存储。

原模型初始化 echo、配置、预算、工具执行、持久化、上下文装配、交付检查、网页事件、后台维护均保留。两次服务启动各完成两轮原有 echo 探测。实际模型配置的上下文窗口 32768，累计输入软／硬预算 90000／120000，运行硬上限 180 秒，联网关闭；本次没有修改这些配置。第三方模型 API 调用为 0，token 记录为原估算逻辑，不能当作供应商账单。

| 会籍写入 | 通过网页明确授权保存一条命名的临时测试会籍，模型保存、读回、删除；真实操作均有回执，当前会籍表仍为空。 |

完整输入、工具定义、结果和人工响应见 `exchange/` 与 `exchange-2/`。末尾无 `014.response.json` 是网页主动取消，不是漏交回答。

## 第三视角：结论和边界

- 先前阻断正常使用的运行存储缺口已解决，不需要改变 AIWorkflow 业务模型。
- 模型可以直接按名称查询路线，没有被迫先查目录；简介只调用摘要工具，具体问题才读取结构化条件，渐进式披露在本次对话中成立。
- 路线查询保留原资格文字及未知状态。EUR 199 对应希腊 Gold 的原始价格记录，预算变化没有把原等级、居住地或目标偷偷改变。
- 模型发出工具调用后，由原 Harness 负责执行和保存；保存、删除、等待取消有正式回执。最终网页结果与数据库运行状态相符。
- 当模型被替换时核心循环不需要重写。本次未修改 `agent/harness/`、`agent/instructions.md`、工具输入 Schema、AIWorkflow 合同或生产逻辑。
- 原有交付信封、字段引用、条件变更原话引用、重复调用保护和资源上限仍在。这些会增加模型使用负担，本次未修改其规则，也不把系统描述为“完全没有限制”。
- 历史简报中的费用概括问题依然保留。读取和展示忠实不等于生成文案本身全部正确；本次没有改写这条业务数据。
- 未验证第三方供应商 API 的传输兼容性，也未开启网络检索；因此不声称联网工具已做线上验收。工作区笔记等未在本次网页场景逐一调用，相关回归另行覆盖。
- 独立 explore 页面及仍保留的其他历史统一模型 API 不属于这四步的全量改造范围。不能把工作台通过等同于所有历史页面都已迁移。
