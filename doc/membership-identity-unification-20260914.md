# 会籍名称统一：实施与验收

实施日期：2026-09-13 至 2026-09-14。

## 已实施

建立一份本地、可维护的名称目录，供 AIWorkflow、Agent 和程序化匹配共用。完整可读表见 [会籍名称对照目录](membership-identity-directory.md)，运行时数据在 `src/journeyplus/membership/identity_directory.json`。

- 收录 122 个计划或来源标签、484 个等级。其中 82 个航空计划、34 个酒店计划，另外 6 个为已有的其他来源标签；包含旧制计划，不等同于当前经营的公司数量。
- 三大联盟现有成员目录中的 60 家航司都能解析到有等级的计划。
- 正式库当前和历史事实导出的 119 种计划写法、615 组计划/等级名称全部能识别。库内历史标签与公开资料确认的等级分开标注；没有把观察到的名称全部宣称为当前官方等级。
- 目录记有来源链接。部分较早资料、旧制度和邀请等级仍需随业务更新复核；这是名称目录，不是实时权益数据库。

资料包括各联盟和计划公开页面，例如 [oneworld 成员](https://www.oneworld.com/members)、[Miles & More Senator](https://www.miles-and-more.com/de/en/program/status-benefits/senator-status.html)、[Marriott 等级](https://help.marriott.com/s/article/marriott-bonvoy-elite-status-tiers)。每个计划对应的具体资料在完整表中列出。

## 接入位置

| 入口 | 处理方式 |
|---|---|
| StatusMatch 官方活动 | 原提取及程序表格解析完成后、保存 FactSet 前，统一计划、源等级、目标等级及价格表目标等级 |
| 普通文章 | 原模型解读完成后，在机会记录与 FactSet 落库时统一名称 |
| 通用事实合并 | 合并完成后统一；读取旧分析缓存时也按同一规则解析，避免复用缓存导致回退 |
| Agent 保存及读取会籍 | 同一目录解析中文、英文和已登记别名，返回实际标准名及稳定引用 |
| Agent 名称查询 | 只返回相关候选；支持“万豪白金”“汉莎金卡”这样的连写查询 |
| 匹配及费用计算 | 共用名称解析，费用等级同步；既有最高等级顺序也识别规范化后的名称 |
| 原有产品会籍入口 | 同一解析，不要求先有活动图节点才能保存已知会籍 |

没有增加 AIWorkflow 模型调用、额外模型步骤、数据库表或字段。没有把目录注入 AIWorkflow 提示词或 Agent 系统上下文。模型拿到当前查询的结果和必要候选即可。工具参数说明补充了可直接提交原名称，不必自行翻译等级。

未知名称仍保留；有歧义时不硬猜。颜色别名只在所属计划内使用：汉莎金卡对应 Senator，不把所有 Gold、Platinum 或联盟 Gold 当成同一等级。共用计划中已有的航司活动范围保留，不凭共享计划名称扩展活动资格。名字改变不自动推断新旧制度等级相等。

## 正式库处理

使用 `scripts/normalize_membership_names.py` 先生成 dry-run，再备份后在事务中执行。脚本默认只报告，`--apply` 必须给出新的备份路径；遇到同一计划的会籍冲突会终止，而不会删除用户记录。

备份保存在本机 `.local/identity-unification-20260913/database-before-backfill.json`，权限为 0600；业务备份和模型对话审计文件已排除 Git 跟踪。

正式库仍保留 7 条活动、13 个事实版本、1 条文章机会、2 条用户会籍。名称转换涉及 1 条活动的目标等级、13 个事实版本、1 条文章机会及两条用户会籍。机会事实签名相应重算；ID、版本号及原文关联未改。

两条已保存会籍现在为：

| 原输入 | 保存的计划 | 保存的等级 |
|---|---|---|
| 万豪白金 | Marriott Bonvoy | Platinum Elite |
| 汉莎金卡 | Lufthansa Miles & More | Senator |

逐项比对数据库列结构，及 `source_items`、`document_versions`、`briefs`、`article_briefs` 的行数和全行摘要，均保持不变。转换前后使用新解析器构建的活动图节点一致。再次 dry-run：零待变更记录。

## 验收

最终回归：**226 passed**。覆盖目录成员和别名完整性、615 组原始名称、未知与歧义处理、名称转换幂等、费用等级一致、最高等级选择、原始数据库读取、产品会籍保存、StatusMatch、普通文章和事实合并。价格金额、币种、地区、条件、链接和映射行顺序不因名称转换改变。

随后补齐七个已核实的基础会员等级，目录专项复核 **75 passed**。最后服务切回无旁路日志的正常启动方式，状态为 READY，可查询正式库路径。

第三方模型：**qwen3.8-flash**，正式数据库、正常 8013 服务与原有 Harness；通过 `/v3/agent/workspaces/.../runs` 发送自然语言，未预写工具调用，模型自主选择工具。旁路日志仅记录请求与返回，未替换模型或数据。共 4 轮真实对话，22 次业务模型调用、19 次工具调用，显式缓存开启。最高单次输入 26,829 tokens，完整名称目录未进入请求。

本机完整工具参数与工具返回在 `.local/identity-unification-20260913/audited-tool-calls.json`，各轮模型请求/响应另存同目录。以下边界如实保留：

- 第一轮暴露中文连写搜索不认别名，已修正并通过真实复测。
- 第一组对话中，“肯尼亚航空 Asante”组合别名未收录，已加入并有测试覆盖。
- 复测时模型另把 `Asante` 放进 `tier_name`，工具没有把计划名硬当等级；返回相关候选后模型自行纠正，后续匹配成功。这不是目录缺少 Asante。
- 一轮出图过程中模型漏写活动版本、又误用活动引用作为路线引用，发生三次参数错误后自行纠正并成功出图。未改这套展示协议；不能据此声称每次模型调用都一次成功。
- 模型的自然语言说明仍可能作额外推断；本次确认的是名称、引用、真实映射与付费结果，不把模型关于完整权益或资格的所有扩展说明都视为已验证事实。

验收期间未新增或删除用户会籍。代码与文档保留在工作区，未创建 Git 提交。
