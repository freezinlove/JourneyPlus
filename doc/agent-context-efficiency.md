# Agent 上下文精简

会籍和等待任务原先将完整前后快照、重复用户原话及参数回显作为模型观察反复携带。当前改为程序生成的精简视图，后台完整结果和操作回执仍保留，数据库模型、AIWorkflow 与业务写入逻辑不变。

## 实现范围

- `tools/projection.py` 提供工具自己的模型视图：操作返回 outcome、entity、变化、必要版本；删除明确标记 deleted，取消任务保留 CANCELLED。列表保留业务字段、真实条件、身份确认状态、版本与分页。
- `holdings` 原话、提取留档及重复身份标签默认不回传；`workspace.read` 显式展开完整结果仍能读到。错误和 PARTIAL 结果不做这类内容精简。
- Harness 先保存完整结果再应用视图；旧历史也应用同一视图。视图不会改变操作回执、幂等恢复或 UI 的完整记录。
- 移除固定 12 条可见消息门槛。`JOURNEYPLUS_AGENT_CONTEXT_TOKEN_BUDGET` 默认 100000，是提示词、工具定义、历史和笔记合计的单请求输入目标。区别于模型实际容量 `CONTEXT_WINDOW` 和整轮累计调用预算 `INPUT_TOKEN_LIMIT`。
- 实际模型适配器的输入估算用于历史取舍。当前轮保持完整调用配对，可超过上述软目标但不能超过模型容量与输出预留；超出真实容量时明确报告资源限制。
- 仅在预算压力下进一步缩减旧大结果，再移出完整旧轮次；原始记录始终可回读。重复读取保留回读引用，等待任务的 list 与写入按各自效果区分。
- 工具定义保留所有工具、字段和服务端校验；精简重复说明，移除无信息的 null 默认注释，以等价的类型数组表达简单可空类型，保留复杂对象分支和校验边界。
- 模型消息不再重复 call_id、内部 turn_id、空元数据和同一个完整结果引用；协议调用配对、用户消息定位、焦点、未知值和检索范围保留。原生工具和 JSON 适配均保留调用定位。

自由笔记仍由模型自主使用。本次没有新增摘要模型、业务状态汇总层、数据库迁移或固定工具流程。操作摘要表示当时状态，模型需要当前状态时应读取最新对象。

## 对比口径

真实验收的历史样本在相同 5 轮范围下，紧凑请求文本从 57,438 降至 47,397 字节（约 17.5%）；工具定义从 21,810 降至 19,350 字节（约 11.3%）。这是 UTF-8 文本体积，不是供应商实际 token 或费用降幅。

上述验收使用当时的 24000 输入预算。取消固定条数限制后，该预算内还可保留原来被移出的第 1 轮路线资料：相同历史样本保留全部 6 轮时为 65,229 字节。因此不能宣称新策略的每次总输入都更少；它同时改善了有效历史保留。

原始审计材料仅在被 Git 忽略的 `.local/agent-audits/context-efficiency-20260912/`，不追踪请求 JSON、日志或数据库快照。

## 验收结果

- 回归：`pytest tests/test_harness*.py tests/test_agent*.py -ra`，204 passed、10 skipped。跳过的是需要显式配置隔离 PostgreSQL 的并发/边界测试，不能视作通过；另有一条既有 Starlette/httpx 弃用提醒。
- 新测试覆盖：超过 12 条对话的保留、配置与实际输入估算、物理容量边界、更新/清空值与删除摘要、重复删除 NOOP 不误标存在、等待条件与取消状态、错误/PARTIAL 不丢信息、原始回执展开、协议配对与焦点。
- 真实正常产品页面连接正式 PostgreSQL、`qwen3.8-flash`、native tools、显式缓存开启；模型响应和工具顺序没有替换或预编排。共 11 轮用户对话、32 次工具调用，29 次成功、3 次失败；两次服务启动合计 4 个探针，47 个实际模型请求，无传输协议错误。
- 会籍创建、更新、读取和删除成功；等待创建取消的最终复测一次完成；当前笔记仅记录给定进度；重新查询后成功展示真正的 route_graph；页面刷新后恢复会话、操作与图卡。
- 39 张表的名称/列名与验收前一致；28 张非 Agent 业务表的行数与内容指纹一致（另有 alembic_version 也一致）。临时会籍无残留，两个本次等待任务均 CANCELLED，库内无 ACTIVE 等待；正常对话、操作回执与取消历史保留。

### 保留的失败与限制

第一次等待创建有两次参数组合错误；模型纠正创建后尚未执行取消就误述已取消。补清工具说明后，通过普通纠正对话实际取消并回读；随后新建、取消、列出的完整复测没有参数错误。没有改变服务端业务校验或增加审核模型。

长对话回到早期路线时，模型逐页读取归档导致整轮预算收尾，未读到有效期，并用代码代替图卡。纠正后 activity.read 正确返回 12 个月；随后模型把 step 引用交给需要 route 引用的展示工具，得到第三次工具失败。最终通过重新查询拿到路线对象并展示成功。首次展示还选择了比较表，部分进度输出为英文。

这些失败没有删除或润色。本次精简与预算策略通过实现层验证，但真实模型语义验收不是全通过；旧归档的回读效率、模型对引用类型的选择以及整轮预算下的多步完成仍有优化空间。本次没有扩大累计预算、增加事实汇总状态或固定业务工具流程来掩盖这些问题。
