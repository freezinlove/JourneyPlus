# 数据模型归档与六项约束调整

本目录的 `schema.sql` 是调整前 PostgreSQL 的完整结构导出，包含表、字段、默认值、索引、约束、函数和触发器，不包含任何业务行，也不包含 `alembic_version` 的记录值。导出时数据库版本为 `clean_0003`；此前价格说明默认空字符串的调整已包含在归档中。

`manifest.json` 记录导出时间和 SHA-256。已将此归档实际恢复到临时空库，并验证六项变更及其撤销脚本；临时库已删除。完整结构文件仅用于空库结构恢复，不应直接覆盖现有数据库，也不能恢复业务数据。

## 已执行的调整

执行文件：`migrations/manual/relax_workflow_constraints.sql`。

1. 价格不可用时仍可保留已知金额；继续保留原有状态取值检查。
2. 删除知识版本对 `analysis_run_id` 的唯一限制，保留非空和外键。
3. 简报状态不再仅限 `READY`。
4. 简报不再受已发布知识子记录的禁止增删改触发器限制。
5. 文章补充不再限制为发布后插入或禁止修改、删除；保留外键和去重。
6. 等待条件格式版本不再锁死为 `3`；默认值仍保留，未强制升级旧数据。

未增加表或字段，未修改原文、申请链接、业务数据或用户记录。44 张表的行数和内容指纹在同一事务中核对一致，列定义、主键和外键均未变化。已发布正式事实与原文快照的保护触发器保持有效。

这是针对现有新库的手动增量 SQL，不是重新引入旧业务模型。当前工作区的旧 Alembic 迁移链尚未对齐，故本次没有改写 `alembic_version`；实际基线为 `clean_0003` 加已执行的手动补丁。后续建立正常迁移链时应纳入这项结构变化，不能仅依据版本字符串假定补丁尚未执行。

## 验证与撤销

运行 ` .venv/bin/python scripts/verify_relaxed_database_constraints.py` 可从本归档恢复临时库，执行升级、撤销、再次升级以及行为检查，全程不复制业务数据。验证包括新允许的行为，以及原文不可变、正式事实不可变、外键、非负金额和状态取值约束仍能拒绝不合法操作。

`verification.json` 记录本次实际执行结果。

撤销文件为 `migrations/manual/restore_workflow_constraints.sql`，只恢复原限制，不修改业务行。如果以后写入的数据已不满足旧限制，撤销事务会失败并回滚，不能为了撤销而删除数据。两个 SQL 文件均按一次执行设计，不是幂等补丁。

本次只调整数据库结构，未修改 AIWorkflow 或 Agent 的应用层契约、校验及读写逻辑，未创建 Git 提交。
