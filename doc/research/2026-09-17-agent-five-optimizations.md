# 五项优化实施与验收

范围：状态轻量读取、上下文复用、指定保存会籍的一次路径查询、最小按需展开说明、独立读取并发。不实现目标反查。

## 改动

1. SessionStore.load_workspace_state 不加载历史消息或渲染反馈。初次/恢复上下文仍读完整历史。
2. 单次 run 内缓存准备后的上下文及 token 估算；消息（含 ID、元信息）、状态、笔记、焦点、资料有效性、能力与工具契约变化均重建。容量检查与下一次模型调用复用相同消息对象。访问有效性检查不跳过，缓存不持久化，结束清理。JSON schema 展开按结构有界缓存，返回副本避免污染。
3. sources.mode=saved 可选 saved_program，按目录名称/别名过滤保存会籍；仅有效记录参与查询，多个不同有效等级返回歧义。省去模型单独调用 holdings.read。省略筛选仍查询全部保存会籍。
4. 保留 overview 原摘要，补充未读范围、已有字段章节引用、字段已知/未知状态与已有 caveats/limitations/conflicts。没有把完整 facts/options、矩阵、原文塞入概览，也没有新增读取模式。工具说明区分概览、详情、矩阵、原文，模型自主按问题展开。
5. 保留读取并发上限3，补充独立已知对象可同批读取的说明；通过同步门测试证明执行器真实并发、结果调用配对正确。

## 验证

- 44项针对性测试通过：新增准备/保存选择测试，加原运行时、进展、结果解释回归。覆盖状态不读历史、缓存命中、状态及访问变化失效、缓存清理、schema隔离、并发、有效期及多等级歧义。
- compileall / git diff --check 通过。
- 模型协议测试扩展中有1个已有失败：旧用例传入已删除的 constraints.allow_challenge。此次没有修改此约束或为了通过而更改旧断言。
- 真实模型：指定保存汉莎查免费路径，直接 routes.evaluate(saved_program=汉莎) → display.present，无 holdings.read；2轮模型，12.4秒，第二轮 context_reused=true。
- 真实模型：比较两个活动时，先读取概览，再读取所需详情，没有读取 original；独立活动读取同批发出。整个回答48秒，不能据此声称所有请求变快。
- 真实无结果场景仍出现模型发起空展示，另一次混用 query 和 patch 后修正；耗时12.3/20.1秒，均记录为行为验收不足，未声称已消除所有多余调用。说明已明确空展示不是结束信号，但未新增harness业务强制流程。
