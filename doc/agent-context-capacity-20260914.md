# Agent 上下文与映射表调整验收（2026-09-14）

## 实施范围

- 保留 500000 token 单次上下文容量；累计输入/输出只统计，不再据此提前结束。
- 去掉固定模型请求数、工具调用数、单批工具数上限；仍按并发度排队执行。
- 保留整轮 180 秒和单次模型请求最多 45 秒超时，以及工具自身超时。
- 移除工具即时返回的 12/24 KB 和批次 32 KB 裁剪。记录回读按完整业务章节分页；网页按请求的字符页长返回，不叠加小字节裁剪。
- 保留渐进式披露、列表分页、上下文真正不足时的历史压缩，以及明确的容量不足反馈。
- 同一读取、参数和快照未变化时复用成功结果，不因重复次数强制结束；刷新请求和写操作不使用该复用。
- 去掉应用额外的输出 token 额度与展示回答字数限制。当前 Qwen3.8-Flash 使用模型自身 131072 输出能力；其他模型可配置其实际能力，未声明时请求不强行设置输出额度。能力依据：[阿里云官方文档](https://www.alibabacloud.com/help/en/model-studio/qwen3-8-flash)。
- 工具说明引导模型在成功率、拒绝经历、审批速度等问题下考虑 StatusMatcher；仍由模型自主选择。
- 增加完整映射表读取与展示：来源项目为行，目标等级为列；保留全部映射和条件。纯展示由程序按活动版本直接读取全表，模型不必抄录全部映射。

数据库结构、AIWorkflow、会籍数据和等待功能开关未调整。技术存储边界、引用校验、写操作幂等和超时仍保留，不能理解为所有资源与正确性检查均被取消。

Asante 的模型读取按 50 个来源项目分页；展示端按活动版本独立读取全表，实际呈现 69 个来源项目、207 项映射记录。另用浏览器正常输入请求验收，DOM 为 70 行（含表头），前端无 console error。

## 验收限制与发现

- 工具链正常并不保证模型配文句句正确。浏览器那轮模型把 Asante 错称为 Alaska 的项目；由程序生成的映射表未受影响。本次没有加入特定航司纠错硬规则。
- 社区比较那轮模型第一次将网页 URL 填进展示引用参数，收到错误后自行修正；仍有额外往返，没有宣称每轮都固定两次模型请求。
- 表格实测有一次额外模型尝试，工具执行仅约 0.18 秒；不能把这一轮近一分钟耗时归因于数据库或表格渲染。
- 回归集合：83 passed、6 skipped、1 failed。失败是已有等待测试仍传入旧的 max_amount/currency 字段；另一个等待快照测试也依赖旧 max_amount。等待功能本次不改。
- 前端既有简报/图/步骤测试 17 项通过；新测试覆盖 30 次工具调用、累计输入超过 50 万仍继续、10 项大结果批次、重复读取复用、完整记录回读、条件不同不合并、映射表读取与直接展示。

机器日志与完整 JSON 保存在被忽略的 .local/agent-audits/context-capacity/，不放入 doc 或 Git。改动保留工作区，未创建提交。

## 后续修正：路径默认完整返回

取消路径候选默认 8 条及约 9 KB 的提前分页；省略 limit 时返回全部精简候选，显式 limit 仍可用于主动选择较小页面。存储分片由读取端连续加载，不再强迫模型按存储分片翻页。

只有总上下文实际不能容纳时，运行时才调用路径工具的容量分页处理，按完整候选减少本页数量，并返回剩余数量和继续游标。单个候选仍不能容纳时明确报容量不足，不裁剪字段。候选数量、路径算法、费用判断和数据库均未修改。

同时移除上下文超容量时的 3/6 KB 历史裁剪：只按完整旧对话轮次移出，并保留历史回读入口；当前轮次装不下时明确反馈。相同读取结果复用保持原状。

本轮针对性回归 42 项通过，覆盖默认 25 项大结果完整返回、容量不足分页、跨存储分片连续读取及游标无遗漏、历史完整轮次保留和现有运行时/业务读取。原文和完整映射表的既有业务分页不属于路径候选限制，本次未改。

修正后正式服务与第三方模型自然对话验收：已保存会籍查询一次完整返回 6 条，coverage.complete=true、未读数量 0、无下一页；随后成功展示一张图。共 2 次模型请求，约 16.9 秒，最终 COMPLETED。服务已重启并 READY，改动未提交。
