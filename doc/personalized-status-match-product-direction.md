## 1. 产品定位

JourneyPlus 收敛为一个默认面向中国地区用户的个性化常旅客会籍匹配与挑战工具。

用户录入自己已经持有的会籍，系统基于当前仍然有效的会籍映射和公开活动，持续向下计算所有可达会籍关系，并展示每项机会的申请路线、不同等级价格、地区提醒、资格条件、挑战要求、期限、证据和申请入口。

产品采用“AI Workflow + 单会籍策略 Agent”：

- AI Workflow 负责已有的文章识别、事实提取和简报生成；
- 会籍路径遍历、闭环检测、个性化匹配、地区提示和结果组装全部由确定性程序完成；
- 现有目录、匹配图、简报和详情页面继续保持确定性读取，不因增加 Agent 而调用模型；
- 一个会籍策略 Agent 负责理解用户的自然语言目标和取舍、必要确认、候选选择、受限的 StatusMatcher 经验调查、无方案时的一次最小调整，以及用户明确同意后的一个等待目标；
- 不建设多 Agent 编排，也不把采集、图遍历、定时任务等普通程序包装成 Agent。

Agent 的自主性只存在于“根据当前上下文选择下一步动作”，不能代替确定性程序创造事实、计算路径或执行申请。完整边界见 [会籍策略 Agent 产品方针](./personalized-status-match-agent-direction.md)。

## 2. 产品范围

### 2.1 纳入范围

用户侧只接收 `OpportunityKind = STATUS_MATCH` 的机会。这里的 `STATUS_MATCH` 是广义产品名称，包括：

- 免费或付费的直接会籍匹配；
- 会籍挑战；
- Fast Track；
- 先获得临时会籍，再完成任务延长会籍；
- 通过公开合作方资格获得明确目标会籍。

系统不再为直接匹配、会籍挑战和 Fast Track 建立额外业务类型。界面可以根据现有 `status_mappings`、`target_status` 和 `challenge_requirements` 生成说明文案，但这些文案不形成新的分类字段。

### 2.2 排除范围

以下机会统一记为 `OpportunityKind = OTHER`，不进入个性化匹配图及其个性化结果：

- 联名信用卡直接赠送会籍；
- 双倍定级积分、精英夜、MQD 或 Status Credit 促销；
- 普通消费升级；
- 买分、转点；
- 只介绍会籍权益的文章；
- 不能直接取得明确会籍等级的其他活动。

`OTHER` 继续沿用现有简报链路，照常生成、保存和展示简报；`OpportunityKind` 不改变简报生成范围，也不作为简报发布条件。`OTHER` 不继续扩展为新的个性化匹配模块。现有买分模块保留代码、数据和历史文档，但退出默认产品页面和每日自动调度。

## 3. 复用现有能力

下列已有实现继续作为产品底座，不另建平行系统：

- 来源采集、增量更新和正文保存；
- 文档去重、版本管理和幂等处理；
- AI 文章识别、证据化事实提取和中文简报；
- StatusMatch 官方项目解析；
- `FactSet`、事实冲突和人工审核；
- 申请开始时间、截止时间、生命周期和软归档；
- `status_mappings` 会籍对应关系；
- `application_routes` 申请路线；
- 统一会籍图及其来源追溯；
- 每日自动化、运行限额和故障隔离。

现有统一会籍图是唯一的路径计算底座。个性化能力只能在该图及其 provenance 上组装，不建立第二套匹配树或重复保存传递边。

## 4. 最小新增数据结构

### 4.1 OpportunityKind

只允许两个值：

```text
STATUS_MATCH
OTHER
```

StatusMatch 官方项目确定性设为 `STATUS_MATCH`。普通文章在现有正文理解调用中同时输出该字段，不增加独立 AI 阶段。

现有数据回填时应保守处理：无法可靠判断的普通文章先归入 `OTHER` 或人工审核，不得为了扩大结果数量自动归入 `STATUS_MATCH`。

### 4.2 StatusHolding

`StatusHolding` 是当前确定性个性化底座用于记录本地单个用户已有会籍的数据：

```text
StatusHolding
- id
- program_key
- tier_key
- program_display_name
- tier_display_name
- valid_until，可空
- created_at
- updated_at
```

当前约束：

- 不建设用户注册和登录；
- 不增加 `user_id`；
- 不建设 `TravelerProfile`；
- 同一个会籍项目默认只保留一个当前等级；
- 用户可以向 Agent 自然描述已有会籍，但 Agent 只能形成候选理解；项目和等级经过用户确认并由现有规范化目录校验后，才能正式写入 `StatusHolding`。

除 `StatusHolding` 外，Agent 只允许在用户明确选择等待时保存一个当前等待目标；普通聊天、本次临时取舍和外部申请报告不形成长期用户画像。该边界以 [会籍策略 Agent 产品方针](./personalized-status-match-agent-direction.md) 为准。

### 4.3 RoutePrice

现有 `ApplicationRoute.cost` 原始文本继续保留，同时增加路线内按目标等级表达的结构化价格：

```text
ApplicationRoute
- scope
- eligibility
- region
- cost
- prices[]
- action_link
- evidence
- conflict
- conflict_note
```

```text
RoutePrice
- target_tier
- amount，可空
- currency，可空
- availability
- raw_text
```

`availability` 用于表达可用、有条件、不可用或未知。示例：

```json
{
  "target_tier": "Gold",
  "amount": 299,
  "currency": "USD",
  "availability": "AVAILABLE",
  "raw_text": "Gold: USD 299"
}
```

价格结构化遵循以下原则：

- 一条路线可以包含多个目标等级和不同价格；
- 不同地区路线可以使用不同币种；
- 不进行自动汇率换算；
- 不自动选择最低地区价格；
- 结构化失败时继续展示原始 `cost` 文本；
- 价格和可用性必须保留相应证据；
- `RoutePrice` 在现有事实提取过程中同时生成；Agent 和用户查询不得临时生成、猜测或改写价格。

## 5. 默认中国地区规则

当前不保存用户地区，系统固定使用：

```text
DEFAULT_REGION = CN
DEFAULT_REGION_NAME = 中国
```

系统可以在读取时根据路线原始地区条款生成以下提示状态，但不为此增加持久化业务实体：

```text
EXPLICITLY_INCLUDED
EXPLICITLY_EXCLUDED
NOT_EXPLICIT
```

含义如下：

- `EXPLICITLY_INCLUDED`：条款明确包含中国或全球地区；
- `EXPLICITLY_EXCLUDED`：条款明确排除中国地区；
- `NOT_EXPLICIT`：条款没有明确说明中国地区是否适用，或无法可靠判断。

地区处理必须满足：

- 地区只提醒，不过滤机会；
- 不隐藏任何申请路线；
- 不阻止用户打开申请入口；
- 不影响图遍历和结果排序；
- 不把“未提及中国”推断为“不适用”；
- 展示所有地区路线及其原币价格；
- 不默认采用其他地区的最低价格；
- 不提供虚假申报、规避资格审查或其他绕过地区规则的建议。

对于“其他所有国家和地区”等无法简单判断的表述，应显示原始条款并标为 `NOT_EXPLICIT`，不得过度推断。

## 6. 路径遍历规则

### 6.1 不设置业务深度上限

系统从每个 `StatusHolding` 对应的会籍节点出发，沿现有统一会籍图持续向下遍历，直到分支没有后继节点、遇到闭环或指向已经展开过的节点。

产品不得把路径人为限制为一步、两步或三步。分页、分批加载、节点数量保护和前端按需展开只属于技术保护，不得被解释为用户不能继续查看后续路径。

### 6.2 闭环处理与产品投影

遍历时维护当前路径的节点集合。如果下一条边的目标节点已经存在于当前路径：

- 保留并展示该边；
- 将目标标记为循环引用；
- 停止该分支继续递归。

例如：

```text
A → B → C → A
```

`C → A` 保留在后端可达响应中，但不会再次从 A 展开，也不会绘制到用户匹配图中。

### 6.3 重复节点与最近路径展示

同一节点通过不同路径到达时，后端响应继续保留所有到达边，但其后续子图只完整展开一次。用户匹配图在该响应上执行多源广度优先遍历：同一会籍卡片只绘制一次，只显示从所有当前持有会籍出发跳数最少的到达边；最短距离相同时按响应中的稳定顺序保留一条。额外汇入边、交叉引用占位和闭环边均不进入匹配图。

例如：

```text
A → B → D
A → C → D
```

两条到达 D 的路径都存在于后端响应中，但匹配图只绘制一张 D 卡片和其中一条最短到达边。

该方案输出从用户会籍根节点可达的有向子图，而不是枚举并重复保存所有简单路径。

## 7. 统一结果规则

用户侧不再区分“可直接匹配”“有条件匹配”和“公开挑战”。所有 `STATUS_MATCH` 机会进入同一个结果集合。

统一结果至少包含：

```text
MatchResult
- opportunity_id
- path，可空
- target_program
- target_tier
- application_routes
- challenge_requirements
- deadline
- status_validity
- region_advisory
- conflicts
- evidence
```

有明确会籍映射的机会显示从用户已有会籍出发的完整路径。没有来源会籍映射、但确属 `STATUS_MATCH` 的公开挑战同样进入结果集合，其 `path` 为空。

附加资格、挑战要求、地区限制、冲突和不确定性只是结果中的事实，不用于把结果拆成不同专区或不同业务类型。

## 8. 产品页面

当前确定性产品底座包含四个页面，并增加一个会籍策略 Agent 交互入口。四个既有页面继续承担结构化录入、浏览和证据核对；Agent 入口承担自然语言目标理解、取舍式推荐和需要用户确认的动作。

### 8.1 我的会籍

用于：

- 搜索会籍项目；
- 选择当前等级；
- 填写可选有效期；
- 修改或删除已有会籍。

### 8.2 个性化匹配图

用于：

- 以用户已有会籍作为根节点；
- 每个可达会籍只展示一张卡片；
- 只展示到每个会籍的最近到达路径，不绘制闭环、交叉引用占位或额外汇入边；
- 连线表达最近到达关系；有明确费用时显示目标等级对应的费用小标签，不在图中重复展示“可匹配”“有条件匹配”或依据卡片；
- 多条申请路线存在不同费用时并列展示全部明确金额和币种，不选择最低价；费用不明确时不显示标签，也不推断为免费；
- 资格、条件、费用和证据统一从下方机会列表进入机会详情查看。

### 8.3 机会简报

简报页复用现有 `BriefRecord` 和 `ArticleBriefRecord`，不增加新的 AI 生成阶段。所有现有机会均照常生成、保存和展示简报，不因 `OpportunityKind` 是 `STATUS_MATCH` 或 `OTHER` 而改变。

每张简报卡片展示：

- 标题和核心摘要；
- 目标会籍；
- 主要资格和挑战要求；
- 价格摘要；
- 截止时间；
- 中国地区提示；
- 是否能从用户已有会籍到达；
- 发布时间和最后更新时间。

简报页支持：

- 按更新时间浏览；
- 搜索会籍项目；
- 只看与用户已有会籍可达关系相关的简报；
- 查看已过期历史简报；
- 对存在会籍映射的简报跳转到机会详情；
- 对存在可达关系的简报跳转到个性化匹配图中的对应节点；
- 其他简报继续展示现有简报内容和来源。

简报页不按直接匹配、条件匹配或公开挑战分区。

### 8.4 机会详情

用于完整展示：

- 完整匹配路径；
- 来源会籍和目标会籍；
- 所有申请路线；
- 各路线中目标等级对应的价格和币种；
- 中国地区提醒；
- 资格条件和挑战要求；
- 申请截止时间和会籍有效期；
- 冲突与不确定性；
- 事实证据和原始来源；
- 申请入口。

### 8.5 会籍策略 Agent

用于：

- 接收用户对已有会籍、目标和成本/挑战取舍的自然语言描述；
- 信息充分时直接查询，存在会改变结果的关键歧义时主动提出一个确认问题；
- 展示一个首选和最多两个具有明显不同取舍的备选；
- 对最终候选展示受限的 StatusMatcher 实际申请经验信号；
- 无合适路线时提出一个最小条件调整，并让用户确认、修改或拒绝；
- 仅在用户明确同意后保存一个等待目标，并在首次出现符合条件的新机会时恢复处理。

Agent 入口不是一套新的事实库或匹配引擎。持有会籍、候选路线、价格、资格、期限和活动状态仍由现有确定性底座提供，详情和证据仍回到既有页面核对。完整工作方式见 [会籍策略 Agent 产品方针](./personalized-status-match-agent-direction.md)。

产品入口之间的关系：

```text
会籍策略 Agent ──理解、选择与确认──┐
       ↓                           ↓
   我的会籍                    机会详情
       ↓                           ↑
个性化匹配图 ←────── 机会简报 ─────┘
```

## 9. 确定性产品 API 底座

当前面向产品的确定性接口为：

```text
GET    /v1/membership-catalog

GET    /v1/status-holdings
POST   /v1/status-holdings
PATCH  /v1/status-holdings/{id}
DELETE /v1/status-holdings/{id}

GET    /v1/personalized-matches
GET    /v1/briefs
GET    /v1/match-opportunities/{id}
```

`/v1/personalized-matches` 返回用户会籍根节点、所有可达节点和边、循环与交叉引用以及对应机会摘要。详细路线、价格和证据由机会详情接口返回。

`/v1/briefs` 统一读取当前官方和普通文章简报，不以 `OpportunityKind` 限制返回范围；接口可以按生命周期、项目搜索以及是否与用户会籍可达进行过滤。

Agent 复用这些能力，不另建平行会籍图或事实服务。Agent 交互、确认和等待目标所需的最小接口由 [会籍策略 Agent 产品方针](./personalized-status-match-agent-direction.md) 约束，并在实施变更中单独定义；它们不得改变上述确定性接口的事实含义。

## 10. 实施顺序

### 10.1 收敛机会范围

- 增加 `OpportunityKind`；
- 更新普通文章提取 Schema、提示词和验证；
- 将 StatusMatch 官方项目确定性标为 `STATUS_MATCH`；
- 为当前有效数据完成保守回填；
- 只从个性化匹配查询中排除 `OTHER`，保持现有简报生成、保存和展示范围不变；
- 让买分来源退出每日自动调度。

### 10.2 补齐路线价格

- 在申请路线中增加 `RoutePrice`；
- 支持一条路线多个目标等级；
- 支持不同地区和币种；
- 保留原始费用文本和证据；
- 使用 Flying Blue、Kenya Airways、GHA 等真实案例验证地区价格和不可用档位。

### 10.3 建立个性化读模型

- 增加 `StatusHolding`；
- 提供会籍项目和等级搜索；
- 从全部用户会籍根节点构造无固定深度的可达子图；
- 处理闭环与交叉引用；
- 通过 provenance 将图边与当前 FactSet、路线、价格、期限和证据组合；
- 合并没有映射边的其他 `STATUS_MATCH` 机会；
- 生成默认中国地区提示。

### 10.4 建立四个页面

- 我的会籍；
- 个性化匹配图；
- 机会简报；
- 机会详情。

### 10.5 接入单会籍策略 Agent

- 接入自然语言理解、关键歧义确认和用户取舍式推荐；
- 只让确定性程序返回正式候选和只偏离一个条件的近似候选；
- 只对最终少量候选调查 StatusMatcher 实际申请经验；正式自动使用前取得书面许可、授权接口或其他明确授权；
- 支持一次最小条件调整，以及用户明确同意后的一个等待目标；
- 保持申请、支付、对外联系、异常处理和数据库外活动发现不在 Agent 权限内。

```text
多 Agent
数据库外新活动发现
StatusMatcher 批量采集、镜像或正文复用
异常处理中心
同时管理多个等待目标
第三方会员账户登录
```

自然语言交互和取舍式推荐已由 [会籍策略 Agent 产品方针](./personalized-status-match-agent-direction.md) 明确纳入，不等于开放通用聊天助手。任何上述排除能力如需重新进入范围，必须先单独说明真实用户价值、不可替代性和新增复杂度，并更新当前产品方针。

## 12. 完成标准

本方案完成后，系统必须满足：

1. 用户可以录入多个已有会籍；
2. 系统从所有会籍根节点持续遍历到叶子、闭环或交叉引用，并在后端保留完整可达关系；
3. 闭环不会导致无限递归，也不会绘制到匹配页面；
4. 匹配页面对每个会籍只绘制一张卡片，并只保留跳数最少的一条到达边；
5. 所有 `STATUS_MATCH` 机会统一进入个性化匹配结果，`OTHER` 不进入匹配图，但仍照常生成和展示简报；
6. 付费匹配可以按申请路线和目标等级显示金额、币种与可用性；
7. 默认显示中国地区提醒，但不进行过滤、拦截或最低价替换；
8. 每项机会都能查看资格、挑战、期限、证据和申请入口；
9. 用户可以在简报页浏览全部现有简报；存在映射或可达关系时可以继续跳转到匹配图或机会详情；
10. 确定性目录查询、图遍历、结果组装和四个既有页面不新增 AI 调用；
11. 现有采集、事实、图谱、简报和审核能力得到复用，没有平行重建；
12. 用户可以用自然语言表达已有会籍、目标和取舍，Agent 能根据上下文决定直接查询或只追问一个关键问题；
13. Agent 只对程序返回的少量最终候选调查 StatusMatcher 经验，且不会把自报样本表述为真实审批成功率；
14. 无方案时 Agent 只提出一个有近似候选依据的最小调整，不连续降低用户要求；
15. 只有用户明确同意时才保存一个等待目标，没有新候选时不调用 Agent；
16. Agent 不执行申请、支付、对外联系，不创建新事实，也不进入多 Agent、权益优化或异常处理范围。

## 13. 最终新增范围

本总方针允许的核心新增范围只有：

```text
OpportunityKind
StatusHolding
RoutePrice
无固定业务深度的防闭环可达子图
默认中国地区提示
个性化匹配读接口
统一简报读接口
我的会籍、个性化匹配图、机会简报、机会详情四个页面
一个有严格行动、数据和复杂度边界的会籍策略 Agent
只面向最终候选的 StatusMatcher 实际申请经验调查
一次最小条件调整与一个用户明确确认的等待目标
```

JourneyPlus 的产品形态是“确定性会籍匹配底座 + 单会籍策略 Agent”：底座保证事实、路径和证据可靠，Agent 负责理解用户目标、根据取舍选择行动，并在没有合适方案时给出克制且可确认的下一步。它不是多 Agent 平台，也不是在固定查询外包装一层聊天文案。
