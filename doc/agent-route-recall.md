# Agent 早期路线回读与展示纠错

早期路线检查记录原先按 JSON 字段拆页，同一步的申请费、有效期和挑战条件容易分散到多次工具调用中。展示工具收到步骤引用时只报错，模型还需另行查找整条路线。

## 调整范围

- `services/route_archive.py` 在路线快照及正常工具结果的 `MATERIAL` 归档前生成业务概览。按原来的路线和步骤关系组合费用、适用条件、有效期、未知/冲突状态、资格检查、注意事项及版本与链接，不调用模型生成摘要。
- `artifact_views.py` 优先分页返回这些概览，随后仍可读取完整原始记录。概览标记为派生视图，不伪装成原文 JSON 路径。单条概览超过 6000 字节时明确退为路线索引，通过 `routes.evaluate inspect` 获取详情；不将一组业务事实切成脱离条件的片段。分页布局变化使旧游标失效，重新从第一页读取即可。
- `routes.evaluate` 的路线候选和步骤详情分别标注 `object_type`。模型继续使用候选的 `ref` 检查或展示路线。
- `display.present` 收到真实步骤或路线快照的引用时，返回同一个快照内可用的整条路线及路径。共享步骤对应多条路线时全部计数，最多返回前 10 条并说明是否完整；其余可从快照继续读取。模型自行选择，不自动展示任何候选。跨工作区、过期和无效引用仍由现有机制处理。
- 更新读取和展示工具说明，没有增加必填参数、工具数量、模型调用步骤或固定业务流程。

这些变化只涉及 Agent 工具及其读取视图。数据库表结构、AIWorkflow、业务数据模型、Harness 决策循环与上下文预算未调整。完整原文、操作档案和快照继续留存。

## 验证

`pytest tests/test_harness*.py tests/test_agent*.py -ra`：210 passed、10 skipped。跳过项需要显式配置隔离 PostgreSQL，不能视为通过；另有既有 Starlette/httpx 弃用提醒。新增 6 项测试覆盖费用/有效期/条件组合、完整原文续读、游标绑定、大概览回退、实际工具结果存档后回读、多路线候选、失败不生成展示及工作区隔离。

真实验收复用此前 11 轮长对话，走产品页面使用的 `/v3/agent` HTTP/SSE 接口、正式 PostgreSQL、`qwen3.8-flash` 和真实工具，显式开启缓存。只提交自然语言请求，没有预编排工具顺序或替换模型输出。本次核验生成的真实展示对象和回执，未另行验证浏览器图形渲染。

首次实测暴露概览识别归档类型的实现遗漏：实际工具结果存为 `MATERIAL`，初版误按 `TOOL_RESULT` 识别，仍返回旧式碎片。模型还错误声称展示工具拒绝了路线，实际上该轮没有调用展示工具。修正类型识别并新增经过真实存档入口的回归后，在同一对话自然语言重试。

修正后的模型自行调用三次工具：历史读取、原归档读取、展示。原归档第一页同时返回申请费 199 欧元（希腊）、批准后 12 个月、挑战 UNKNOWN，并保留资格限制与链接；模型正确说明 UNKNOWN 不能推出有或无挑战。展示回执为 OK，存档中的 `route_graph` 指向最早查询的原路线对象。没有重新搜索路线，也没有新增会籍或等待操作。历史关键词读取仍未找出早期消息，模型从已有上下文中的归档入口成功恢复；此次没有改动历史搜索语义。

两次实测加两次启动的 4 个探针合计 12 个模型请求，显式缓存全部开启，无传输协议错误。首次失败与修正后结果均保留，不计为一次全程成功。正式库 39 张表的名称与列名不变，28 张非 Agent 业务表及 `alembic_version` 的行数和内容指纹不变；仅产生正常 Agent 对话、工具结果、运行记录及展示归档。

原始请求、响应、日志和指纹只放在 Git 忽略的 `.local/agent-audits/route-recall-20260912/`。
