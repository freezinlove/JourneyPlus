# 最小多用户系统：实现与验收

2026-09-15。当前改动未提交 Git。

## 使用规则

- 每个账号独立保存个人会籍。公共活动、简报、映射表、价格表、原文归档仍共享同一份知识库。
- 每个账号只有一个当前工作区。刷新页面或重新登录继续当前会话。
- 会话在最近一次成功接收用户新消息后保留 24 小时；读取页面、工具执行和同一消息重试不续期。
- 开启新会话立即使旧会话失效，取消旧任务，清理聊天、笔记、图卡、工具结果和对应操作回执。已保存的个人会籍保留。
- 到期会话立即禁止读取和写入；后台维护约每分钟清理到期记录。服务停机期间不能执行物理清理，恢复后继续清理。
- 等待任务继续关闭。本次未增加注册、邮箱验证、组织、角色或后台管理页面。

## 登录与管理

服务入口：<http://127.0.0.1:8013/login>。

现有数据归属账号 `owner`。初始随机密码只保存在本机 `.local/multiuser/owner-login.txt`，文件权限为 0600；该目录被 Git 忽略。数据库仅存密码哈希和登录令牌哈希。

新增账号，在项目目录运行，密码通过交互输入，不放入命令参数：

```sh
.venv/bin/python -m journeyplus.accounts 用户名
```

重置账号密码并撤销该账号现有登录：

```sh
.venv/bin/python -m journeyplus.accounts 用户名 --reset-password
```

登录状态最长保留 30 天，与聊天的 24 小时保留时间独立。退出会撤销当前登录；浏览器多个页面会同步账号切换或退出。

## 改动边界

迁移 `0020_minimal_users` 增加账号表、登录会话表，给个人会籍和工作区增加所属用户，给工作区增加最后消息时间。会籍唯一性从全局计划名改为“用户＋计划名”。公共知识数据模型和 AIWorkflow 生产逻辑未变。

HTTP 登录边界确定身份；两套会籍 ORM 映射、会籍读写、匹配查询、工作区、原文以外的私人工具产物按用户隔离。模型无需传用户 ID。后台恢复执行从工作区还原用户身份。新会话与运行中的写入通过事务检查协调，旧任务不能在被替换后继续写入。

独立知识服务也接入登录边界，登录后进入知识页。旧版 Agent 入口及跨会话导入关闭，避免旁路访问。
