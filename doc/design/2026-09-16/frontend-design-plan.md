# JourneyPlus Web 与 Android 设计方案

配套：[交互概念稿](./preview.html) · [交付与检查记录](./README.md)

## 1. 结论

JourneyPlus 应成为一件精致、可信、适合每天打开的会籍工具。设计方向定为 **「安静的工作区，具有编辑品质的简报，清晰可操作的会籍路径」**。

视觉采用瓷白、墨色、少量深海蓝；圆润的控件和浮层；有节奏的字体与留白；连续、可中断的动效。品牌特色来自会籍连接线、路径端点和简报排版，而不是通用 AI 星光、渐变球、满屏卡片或豪华黑金包装。

技术选择：

- **Web：React + TypeScript + Vite，React Router，TanStack Query，Radix Primitives，CSS Modules 与语义化 CSS 变量，按需使用 Motion。**
- **Android：独立 Kotlin + Jetpack Compose App，自定义 JourneyPlusTheme，使用 Android 原生导航、输入、无障碍及返回行为。**
- 两端共用设计 token、API 契约、状态语义和验收数据，各自实现 UI；继续使用当前 FastAPI 与 AIWorkflow 数据。
- 本轮只交付方案和独立交互概念稿。现有页面、数据库、AIWorkflow、Harness 均不修改。原生 APK、生产前端迁移和联网部署属于后续实施。

这次值得升级前端工程结构，但框架本身不会带来审美。首先固定设计系统和关键场景，再按页面迁移，避免换完框架仍然是同一套卡片。

### 2.2 本次纳入

Web 和独立 Android 的登录、当前对话、活动与简报、版本详情、会籍管理、Agent 选定路径及申请经验展示；跨端视觉系统、交互状态、国际化、无障碍、性能和迁移方案。

### 2.3 不随设计扩张的业务

不增加机票酒店预订、行程管理、会员权益估值、自动申请支付、永久对话历史、推荐评分、成功概率、收藏或申请进度。等待能力仅按真实服务开关与现有实现呈现，不新承诺推送或后台唤醒。`OTHER` 保留简报展示，不能因界面筛选被永远隐藏。

用户此次明确提出独立 Android App，取代旧文档排除移动端的限制；这不自动改变其他业务边界。

**调研后的原创组合**：操作层从成熟工具提炼；阅读层从编辑设计提炼；路径图以会籍关系本身形成品牌。不是把三个产品的截图拼起来。

### 3.1 三个方向的比较

| 方向 | 气质 | 适配程度 | 决策 |
|---|---|---|---|
| A. 瓷白与墨蓝 | 清晰、圆润、细腻，带少量出版物气质 | 对话、简报和 Android 都稳定 | **主方向** |
| B. 暖纸与朱红 | 更强的杂志与手工编辑感 | 简报有特色，但长期操作界面容易偏复古 | 吸收标题节奏，不作为全局主题 |
| C. 深色金属与玻璃 | 很有展示感 | 密集文字、旧安卓设备、长时间使用成本较高 | 只发展克制的深色模式，不做重玻璃主页 |

### 3.2 把“不要 AI 感”变成具体规则

1. 不给每段文字加背景、圆角、边框和阴影。列表用行与间距；正文用标题与段落；只有明确可操作对象使用独立表面。
2. 不用星光图标、霓虹渐变、悬浮球、虚构百分比、数据看板装饰、随机彩色标签。
3. 同一视口只有一个主操作；品牌色用于行动、选中和路径，不涂满页面。
4. 首屏让用户看到当前问题或真实简报，而不是反复出现大标题加四张功能介绍卡。
5. 薄弱信息显示“未说明”，不能用空白的漂亮组件伪装完整。
6. 空数据、超长标题、密集映射和失败状态同样完成设计，不能只做理想三条样例。
7. 艺术细节集中在刊头、节点、曲线、字体与转场；避免每个组件分别炫技。

## 4. 信息架构

一级入口保持三个：**对话、简报、我的会籍**。账号与外观进入次级菜单。

### Web

- 宽屏左侧窄导航，中心是主要任务；读取对象时右侧出现详情区。
- 对话为空时显示一句自然引导和少量真实可执行的示例提问；开始对话后收起宣传性内容。
- 路径图由 Agent 的展示产物进入，可在对话内预览，也可展开；不恢复已隐藏的独立匹配图一级入口。
- 左侧可以显示“本次对话中的内容”作为当前产物定位，不伪装成永久会话列表。
- 小屏 Web 改用紧凑顶部导航与单栏阅读；不缩小三栏硬塞进去。

### Android

- 三项底部导航：对话 / 简报 / 我的会籍。统一 48dp 最小触摸范围。
- 轻量信息用底部弹层；长简报和完整图进入专用全屏页面。
- 打开图节点先显示这一步，再进入完整简报；返回恢复选中节点、缩放及原消息位置。
- 弹出键盘时让输入框随键盘移动，隐藏非必要底部导航；遵循系统返回、键盘关闭次序。
- 平板与折叠展开态可采用导航轨 + 列表详情双栏，不只把手机页面拉宽。

**跨端统一的是“在哪里找东西”和“状态是什么意思”，不是逐像素复刻 iOS。** Android 保留系统返回、触觉反馈、字体缩放、分享及链接行为。

## 5. 关键页面设计

### 5.1 对话工作区

**阅读秩序**：用户目标 → Agent 自然语言结论 → 模型选定的图或比较 → 对应版本简报 → 继续提问。

- Agent 正文直接落在页面上，没有包围整段答案的大卡片；用户消息使用一块轻微色差的柔和气泡。
- 消息正文宽度约 640–720px；中文正文 16–17px，行高约 1.7。工具进度占一行，避免大面积日志挤压正文。
- 输入框为圆润的浮动操作表面；只保留当前已有文本能力，不放无法使用的麦克风、附件、图片入口。
- 正在读取、计算或研究的描述来自实际事件；不编造“已分析 98%”等假进度，也不展示模型隐藏思考。
- 流式输出按帧合并 DOM 更新。用户停留底部时跟随；向上阅读后停止自动滚动，提供“回到最新”。
- 点击图、表或经验案例时保留消息上下文。选中对象的名称出现在后续提问的上下文提示中；引用由真实 `subject_refs` / `focus_ref` 传入。
- 渲染失败单独显示“路径图暂未显示，重试展示”，保留已经生成的正文。只有对应内容挂载并完成必要渲染后发送 `RENDERED`，异常发 `FAILED`。
- “新对话”按真实语义提示会替换当前短期工作区。不能悄悄按永久多会话产品来设计。

### 5.2 活动与简报列表

采用**编辑式目录**：精简刊头、紧凑日期信息、清晰的标题和短摘要、细分隔线。桌面可一列正文加窄元信息列，手机单列。默认不使用等宽等高卡片网格。

每条的优先顺序：

1. 标题：首先可读，标题过长自然换行。
2. 摘要：列表允许视觉截断，但进入详情能读完整文本。
3. 更新时间：使用数据实际时间，不伪装成今日发布。
4. 生命周期提示：过期和历史状态保持明显但不过度鲜艳。

首版保持现有分页顺序及 `has_more`；若改为全局更新时间排序、全局搜索、类型过滤，必须明确补 API 参数和稳定游标，不能只过滤已加载的 8 条然后声称“全部搜索”。概念稿列表仅演示版式，不代表已接入搜索。

简报不要求每条配图。首页可使用一幅原创抽象线路构图作为刊头背景，正文保持纯净。未来有正式图片资产时再使用，不能抓取官网照片作为默认配图。

### 5.3 简报阅读页

从弹窗式字段集合改为有完整 URL 的阅读视图；桌面可在侧边预览并展开，手机进入整页。原 `activity_id + version_ref + section` 链接继续可用。

版式顺序：

1. 轻量刊头：活动项目、更新时间、当前或历史版本。
2. 标题与原有摘要：允许有节奏的字体反差，但不重新改写已发布简报。
3. “和我的关系”：用一条清楚的关系描述或路径表示；无有效会籍、未找到路径、查询不完整分别显示。
4. 申请入口：明确外链标识。保留全部有效申请入口，不因设计偏好只留一个。
5. 会籍映射：桌面为有行列标题的表格；手机按来源项目展开目标等级，提供完整表格模式。
6. 费用表：按地区/申请方案分组，保留原币、目标等级、条件费用、未知及不可用。零费用与“没有费用信息，计算按免费处理”在文案上区分。
7. 资格、挑战、期限、注意事项：从已有同版本详情读取，按章节展示；缺失时不新生成。
8. 原始来源与版本：明确可访问的入口。历史资料默认保持历史版，“查看当前版本”是显式操作。

艺术表达落在刊头、标题、页边信息与分隔节奏，而不是把费用做成购物价格大字。正文不采用双栏杂志排版，避免手机阅读断流。

### 5.4 匹配关系图

建议作为 JourneyPlus 最具识别度的组件：**细线连接、清晰端点、稳定布局、真实会籍名称**。

- 图表达会籍取得关系，不绘制世界地图，不把项目缩成机场三字码。
- 默认节点是项目与等级，来源可分组显示；共同节点与共同连接只出现一次。
- 起点、目标、选中状态有明确外观；主选标识只跟随模型真实角色，不默认把数组第一条涂成“最佳”。
- 连线只展示免费/付费；金额、地区、资格在版本详情中读取。
- 桌面横向阅读，手机优先纵向步骤布局；保留全图缩放选项与等价文字列表，不要求用户靠捏合读 9px 字。
- 选中目标时突出相关路线，其余连接降强调但仍可见；这只是视觉焦点，不重新计算或删除结果。
- 展开分页时保留已有节点位置和选中对象，避免每次重新排布整图；当前页数、已加载范围及搜索不完整提示可见。
- 不提供新增节点、拖出连线或编辑事实操作。节点可以有焦点与浏览，不具有流程编排器含义。
- 不隐藏必要中间等级；不凭空认为高级会籍可以替代某个低级会籍申请。

首版保留轻量 SVG + DOM 思路，提取可测试的渲染模型。若真实结果规模证明需要成熟平移缩放与复杂布局，再引入 [React Flow](https://github.com/xyflow/xyflow)，关闭编辑行为并完全定制节点。它负责显示，不接管最短路径算法。

### 5.5 申请经验

- 使用紧凑的案例行：来源等级 → 目标等级、申请结果、报告日期、摘录、来源。
- 与官方简报使用不同的标题和信息说明，不靠颜色单独区分。
- 不能把若干自报案例画成预测成功率仪表盘；拒绝样本也要同等可读。
- 可以展开完整已获取正文；不通过展示阶段再次解析网页。
- “查看申请经验”必须触发真实 Agent 请求或展开真实产物；原型的演示不计作功能完成。

### 5.6 我的会籍

- 清晰的项目和等级列表，加一处克制的会员凭证视觉；无需全屏叠放仿钱包卡片。
- 项目、等级、有效期与是否参与计算在同一阅读区域；未设置有效期不显示“永久”。
- 过期记录折叠在次级区，但可找回、修改；不参与路径计算。
- 添加/编辑使用规范化目录与已有服务。先梳理 `/v1/status-holdings` 和 Agent holdings adapter 的身份、revision 与未解析记录差异，不在客户端另建一套规则。
- 写入后等实际成功回执才显示“已保存”；冲突时提供重新读取，不乐观伪造会籍修改成功。
- 移除会籍可使用明确确认；只有后端支持可靠恢复时才能提供“撤销”，不虚构恢复能力。

## 6. 视觉系统初稿

| `surface-subtle` | `#ECEFF3` | `#262D36` | 次级交互表面 |

| `line` | `#DAE0E7` | `#39434F` | 轻量结构线 |
| `warning-ink` | `#86501C` | `#E9BB86` | 过期、未知、条件提醒 |

以上是待真机验证的初始 token，不代表每个组合已经通过对比度认证。功能文本目标 WCAG AA；低对比只用于不承载信息的装饰。

### 6.2 字体

- 操作与正文：Web 优先系统 UI 字体，Android 使用系统字体；有需要时再捆绑授权清晰、子集化的拉丁/中文字体。
- 英文编辑标题可选择开源衬线字体，中文简报标题可小范围采用思源宋体/Noto Serif CJK 的授权版本。英文与中文分别验证，避免一边精美一边回退失衡。
- SF 字体与 SF Symbols 不作为 Android/Web 自行打包的默认资产；先使用系统可用字体和跨端授权清晰的图标。
- 正文 16–17px/sp；元信息 12–13px/sp；页面标题 Web 28–36px、Android 26–30sp；简报详情可适度放大，禁止正文低于易读尺寸。
- 金额、日期、计数用 tabular numerals；正文不强行等宽。中文不增加英文式大字距。

### 6.3 圆角、间距与材质

- 基础间距：4 / 8 / 12 / 16 / 24 / 32 / 48。
- 小型对象 10–12，操作按钮 14–16，输入区 24，弹层 28–32；不是所有元素统一 24px。
- 嵌套圆角按容器内边距保持视觉同心；表格保持清晰直线结构。
- 阴影仅用于真实浮起的输入、导航、弹层；列表不逐条投影。
- 玻璃只服务层级：导航与悬浮操作区可以轻微模糊；正文实底。低性能设备与减少透明度场景回退到实色。
- 以同一套几何、墨蓝路径和标题节奏建立品牌，不使用黑金、钻石、金属浮雕证明“高级”。

## 7. 动效：把“丝滑”落实到行为

参数为首轮原型调校目标，不是未经测量的性能承诺。两端共享动作意图，弹簧单位与参数分别调校。

| 动作 | 目标感受 | 初始时长/行为 | 必须保留 |
|---|---|---|---|
| 按下按钮 | 立即回应、轻微受力 | 80–120ms，约 0.98 缩放 | 不延迟真实操作 |
| 切换导航 | 位置连续 | 180–240ms，选中背景移动 | 键盘与屏幕阅读器状态同步 |
| 列表进入简报 | 看到对象从哪里来 | 240–320ms，共享标题或容器 | 返回恢复滚动位置 |
| 打开底部弹层 | 随手势、有阻尼 | 弹簧约 280–380ms | 中途反向操作可取消 |
| 图节点展开 | 关系清晰 | 180–260ms，稳定旧节点 | 不重新缩小整张图 |
| SSE 正文 | 内容自然出现 | 帧批量追加，不逐字装饰动画 | 不抢用户滚动位置 |
| 网络等待 | 状态诚实 | 短加载骨架，随后真实文字状态 | 不显示伪百分比 |

避免同时运行大面积 blur、持续背景动画、逐卡延迟登场和视差滚动。减少动态效果时以立即切换或短淡入替代。Android 使用系统 [Predictive Back](https://developer.android.com/develop/ui/compose/system/predictive-back)，不强做冲突的 iPhone 返回手势。

## 8. 技术选择与理由

### 8.1 为什么升级现有 Web

现有 HTML/CSS 完全有能力做漂亮的静态页面，问题是多页面状态、共享组件、流式事件、详情焦点与错误反馈集中在 DOM 操作中，样式还存在多个全局层叠版本。双端建设后，需要一个明确、可测试、可复用的前端边界。

| 方案 | 优点 | 成本 | 本项目决策 |
|---|---|---|---|
| 原生 JS + 模块整理 | 迁移最少、资源小 | 复杂状态与共享交互继续手工维护 | 可做过渡，非长期主方案 |
| React + TS + Vite | 组件与类型、生态、流式 UI 测试方便 | 新增构建及依赖，需要路由与缓存设计 | **采用** |
| Next.js | 适合需要 SSR、SEO 和服务端页面的平台 | 当前已有 FastAPI，增加另一个服务端体系收益有限 | 目前不采用；未来公开内容站单独评估 |
| Vue / Svelte | 同样能实现高质量 UI | 引入另一套并无明显业务优势 | 可行备选，不来回切换 |

React 官方同时说明了框架与从零搭建的取舍，Vite 并不自动提供路由和请求缓存。本方案明确采用 React Router + TanStack Query 填补这些职责，而不声称 React 官方只推荐 SPA。[React 构建指南](https://react.dev/learn/build-a-react-app-from-scratch)

### 8.2 Web 组件与状态

- Radix Primitives 管理弹层、菜单、焦点和键盘等行为，自定义视觉；不直接使用一套辨识度很高的默认 SaaS 模板。[Radix](https://www.radix-ui.com/primitives/docs/overview/introduction)
- CSS Modules 管理组件作用域；CSS 变量统一主题。首版不混用多套组件库。
- Motion 仅用于布局连续变化、弹簧和出入场；普通 hover 使用 CSS。[Motion](https://motion.dev/docs/react)
- TanStack Query 管理请求、缓存与失效；SSE 使用独立 reducer，按 run/seq 去重和有序回放。[TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview)
- 避免将每个 token 写入全局状态；按轮次与消息更新。虚拟化只在真实性能数据需要时引入。
- 历史简报缓存键包含用户范围、活动 ID、版本 ID 和视图类型。因“和我的关系”依赖用户，不能把整个详情当公共缓存。
- 公共事实和当前用户关系在缓存上区分。登出、账号变化、新工作区和过期后清理对应状态。
- 引用、未知 block 类型、未知事件类型做容错，不因一个展示块失败丢失整条回答。
- Web 构建产物仍可由 FastAPI 同源提供，减少跨域 cookie 和新服务部署负担；不移动 AIWorkflow 到 Node。

### 8.3 Android：为什么选原生 Compose

| 方案 | 与本项目的关系 | 决策 |
|---|---|---|
| Kotlin + Compose | Android 已明确需要；输入、系统返回、长列表、触觉与字体适配可直接使用平台能力 | **采用** |
| React Native / Expo | 未来同时做 iOS 且跨平台人力受限时有价值；Web DOM/SVG 并不能直接变成原生界面 | 当前不优先 |
| Flutter | 能自绘统一 UI，但增加 Dart 体系；需要单独处理平台细节 | 当前不优先 |
| WebView 包装 | 原型快，主要界面仍是网页，达不到此次原生体验目标 | 不作为独立 App 交付方案 |

Compose 可以扩展或替换 Material 的颜色、字体与形状，不等于必须长成默认 Material 模板。[Android 自定义设计系统](https://developer.android.com/develop/ui/compose/designsystems/custom)

实施建议：

- `ViewModel + StateFlow` 提供屏幕状态，Coroutine 管理请求与订阅，UI 只渲染。
- 导航使用稳定版本的 AndroidX 导航方案；正式建工程时锁定 Compose BOM、Kotlin、AGP 与 SDK 兼容组合，不在设计稿中猜“最新版本”。
- HTTP 客户端选择 OkHttp 与结构化序列化，SSE 支持续接 `after`、有序去重、取消、401 与 revision 冲突。
- 原生图使用 Compose 布局与 Canvas 连线，并给节点及等价步骤列表提供无障碍语义。
- 使用 Android Custom Tabs 打开官方申请站，浏览器负责用户登录与操作；不代填申请。
- App 进后台不承诺永久保活 SSE；回前台读取当前状态，再续接运行。网络重试不得重复提交用户写操作。
- 先复用现有 cookie 登录与账号范围，通过客户端 cookie 管理验证可用性；持久化凭据需用系统保护并在登出清除。不要为客户端开发顺手新建未经评估的 JWT 体系。
- 当前服务只监听 localhost，独立手机访问需要可达后端环境。模拟器联调用宿主机映射；真机可用明确配置的开发连接；正式国际化产品需要 HTTPS 域名、运维和发行配置。这是待实施依赖，本轮不对外开放现有服务。
- 第一版不增加离线写入队列、永久聊天缓存或推送；这些都影响现有业务和隐私边界。

## 9. API 与页面迁移对应

| UI 能力 | 当前接口 | 迁移要求 |
|---|---|---|
| 登录与账号 | `/auth/login`、`/auth/me`、`/auth/logout` | 保留 cookie、用户隔离、同源约束；两端登出清状态 |
| 当前工作区 | `GET /v3/agent/workspaces/current` | 注意它可能创建工作区，不能当作无副作用探测反复调用 |
| 运行与回复 | `POST .../runs`、`GET .../events?after=` | 保留 client_message_id、expected_revision、事件 seq、终态 |
| 取消 | `POST .../cancel` | 取消运行不撤销已经成功的用户变更 |
| 展示与翻页 | artifacts、presentations/browse、feedback | 真实产物引用，不从自然语言再猜结构 |
| 当前活动 | `GET /v2/activities?view=cards&limit=&offset=` | 不在局部数据上冒充全局检索；保留加载失败重试 |
| 简报与历史 | `/v2/activities/{id}`、`/brief`、`/history` | 明确版本、视图和旧链接语义 |
| 会籍管理 | `/v1/membership-catalog`、`/v1/status-holdings` 与 Agent 适配器 | 核对两入口数据形态，复用服务，不新增业务表 |
| 探索查询 | `POST /v2/explore/query` | 作为保留能力，不擅自恢复独立入口 |

目前 Python 动态 payload 并非全部由 OpenAPI 完整描述。生成 TS/Kotlin 客户端只能覆盖已声明契约；对展示 blocks 与 SSE 需补类型定义、契约样例和解析校验。不要承诺按一下生成器即可完整双端共享。

迁移按独立页面进行，保持外部 URL。一个页面同一时间只由一套渲染系统拥有，避免 React 与旧脚本同时操作 DOM。版本参数、登录路由及静态资源路径先做回归，再切流量。旧 UI 退出不意味着删除历史事实。

## 10. 国际化与无障碍

- 设计以简体中文和英文双语长度校验；首版不把“国际化”误解为给所有按钮加英文小字。
- 把界面文案放资源文件；活动名称保留官方写法，必要时补中文名。已有中文简报不因切换界面语言自动变成英文内容。
- 地区和金额不因语言切换改变筛选含义，不自动汇率换算。`USD 299` 等币种必须无歧义。
- 期限按后台实际日期精度展示。纯日期不做时区换算；时间点展示时区，避免本地化导致提前一天。
- 预计英文扩长 30%–50% 的控件压力测试；不依赖硬换行拼主标题；长项目名可换行。
- Web 键盘能完成导航、关闭详情和访问图节点；Android 用 TalkBack、200% 字体测试。
- 正文与关键操作满足 AA 对比；选中、付费、过期与错误不只靠颜色表达。
- Web 有 `prefers-reduced-motion` 与明确的降低透明度选项；Android 跟随系统动效与辅助设置。
- 生产资源本地打包和缓存；中国网络环境下不依赖 Google Fonts/CDN 才能显示正确布局。

## 11. 状态设计矩阵

| 状态 | 界面表现 | 不允许的表现 |
|---|---|---|
| 尚无会籍 | 给出添加或假设查询入口 | 把空图解释为没有机会 |
| 会籍已过期 | 保留记录并说明未参与 | 偷偷删除或继续计算 |
| 没有已发布知识 | 明确资料尚未就绪 | 说全世界没有匹配机会 |
| 搜索完整但无路径 | 说明本次条件下未找到 | 自动画出建议的虚构边 |
| 检索不完整 | 图旁保留范围说明 | 用“全部机会”作标题 |
| 费用缺失 | 保留“未说明”；说明计算政策 | 表述成官方明确免费 |
| 历史版本 | 固定标识，显式跳当前版本 | 后台刷新偷偷换事实 |
| SSE 断开 | 保留正文、重连状态 | 清空对话或重复发送 |
| 401 / 410 / revision 冲突 | 登录/会话过期/重新读取各自说明 | 统一显示“再试一次”并自动重写 |
| 部分渲染失败 | 保留其他结果，局部重试 | 发送虚假 RENDERED 回执 |
| 点击停止 | 停止状态与已完成回执 | 宣称之前的保存已经撤销 |

## 12. 实施顺序与交付门槛

以下为工作包估算，不是日历承诺；按一名前端加一名 Android 工程师投入估计，后端契约缺口另计。AI 辅助不能替代真机质量验收。

| 阶段 | 交付 | 估算 | 退出条件 |
|---|---|---|---|
| 0. 设计定向 | 本文、交互概念、参考依据 | 本轮完成 | 明确主视觉、平台与边界 |
| 1. 设计系统与关键稿 | Web/Android 的对话、简报、图、会籍，浅深色与状态稿 | 4–7 人日 | 中文英文与长内容评审通过 |
| 2. Web 基础与简报 | React 壳、登录、主题、列表、版本阅读页 | 6–10 人日 | 原链接、分页、登录和版本回归通过 |
| 3. Web 工作区 | SSE、产物、图、经验、会籍操作 | 8–12 人日 | 恢复、取消、焦点、回执和错误状态通过 |
| 4. Android 原生 | 登录、导航、对话、简报、图与会籍 | 12–20 人日 | 至少两档真机、键盘、返回、字体与弱网通过 |
| 5. 跨端一致与收尾 | 国际化、无障碍、性能、旧 UI 退出 | 4–7 人日 | 核心流程数据和交互一致 |

约 34–56 人日是规划级工作量，未含应用商店审核、公网后端运维、未预见的接口整改及新增业务。先完成 Web 简报和一个对话→图→详情闭环，再扩大，不同时翻新所有页面。

### 必须跑的实际场景

1. 从已有会籍请求路线，查看模型选择的图，再打开对应版本简报并返回原焦点。
2. 图含共享节点、多步路径与长名称，手机不挤压成不可读小字。
3. 当前事实更新后重开历史链接，内容仍属于历史版本。
4. 简报含大量映射、多地区价格、条件费用与缺失信息，排版和语义均保持完整。
5. 网络中断、刷新、切后台、取消和重连，无重复用户写入。
6. 新对话替换旧工作区，过期与跨账号访问行为正确。
7. 360px 手机、390px 手机、768px 平板、1280px 桌面和 200% 字体，无主要操作遮挡。

### 质量目标

- Web 交互与流式更新不出现明显长任务；上线环境测量目标 INP ≤ 200ms、CLS ≤ 0.1，加载速度以实际后端和设备条件为准。
- Android 在指定中档设备 Release 构建上测量帧耗时与 jank；60Hz 目标帧预算约 16.7ms，支持 120Hz 时约 8.3ms，不仅在模拟器凭感觉宣称“120fps”。
- 动效可中断，点击立即响应；减少动画设置生效。
- 使用视觉回归和关键交互测试。业务匹配正确性继续由现有确定性测试保障，不复制一份客户端匹配算法。

## 13. 本轮交互概念稿的边界

`preview.html` 用于看清方向，包含 Web 与 Android 布局预览、浅深色、对话与图、编辑式简报列表、简报阅读和会籍示例。所有项目、会籍、费用和关系均为虚构演示，页面有持续提示。

它不调用业务 API、不调用模型、不产生会籍写入；不是最终 React 实现，也不是可安装 Android App。原生手势、系统键盘、预测返回、触觉、实际 SSE 与性能，需要后续客户端开发和真机验收。

**最重要的设计判断：高级感来自一致、可信、可读与对操作的细致回应；艺术性来自 JourneyPlus 自己的路径语言与简报编辑，而不是把内容埋进更多装饰里。**
