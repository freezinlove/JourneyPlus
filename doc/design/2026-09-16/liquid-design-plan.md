## 1. 方向

**让界面像一层悬浮在远方光景之上的玻璃。**

沿用成熟 AI 工具的交互骨架，显著增强背景渐变、模糊、透光和边缘高光。国际化品质来自字体、间距、触控反馈、语言适配和信息一致性；英文装饰字仅用于概念稿气质展示，正式产品按语言设置统一文案。

用户提供的两张参考图是本版直接视觉依据，仅用于材质与布局分析。图中的人物、头像、个人资料及文字不成为 JourneyPlus 素材或产品需求。

### 从参考中提取

- 第一张：深炭灰底色、圆形工具按钮、悬浮胶囊导航；选中项像一块有厚度的磨砂玻璃。
- 第二张：大范围失焦背景；暖灰与冷暗色交织；边缘轻微反光；内容和控件之间有明显前后层次。
- JourneyPlus 的转译：把人物背景替换为抽象的地平线光场，用会籍路径和内容排版建立自身身份。

不复制参考图的集成设置、用户人格、头像或个人档案功能。

## 2. 与基础版的关系

| 维度 | 瓷白与墨蓝 | 流光 |
|---|---|---|
| 第一印象 | 安静、清晰、编辑式 | 沉浸、透光、柔和流动 |
| 背景 | 稳定纯色 | 暖灰、雾蓝、紫灰、深青交融 |
| 导航 | 平面选择层级 | 厚玻璃胶囊与内侧高光 |
| 简报 | 纸面感、衬线标题 | 透光封面、无衬线标题、稳定阅读层 |
| 适用重点 | 高密度日常阅读 | 品牌辨识与情绪体验 |

第二版是可替代的完整视觉方向，不只是给第一版增加一个深色主题。当前概念稿复用第一版的业务示例和交互脚本，以便同场景比较材质差异。

## 3. 材质系统

### L0：环境光场

夜航：暖灰 `#726856` → 蓝灰 `#303D52` → 深蓝 `#171E2C` → 深青 `#223E40`。

晨雾：暖白 `#D1C4B4` → 雾蓝 `#B6C9DD` → 淡紫灰 `#CED3E3` → 灰绿 `#A9C6C4`。

颜色以大面积扩散相互融合，不形成一颗显眼的通用 AI 渐变球。只允许极慢、小幅的环境位移；滚动与点击不引起大幅背景摆动。

### L1：内容层

对话正文直接落在稳定暗区，局部高亮的光场远离主要阅读位置。长文阅读页增加连续遮罩。多段文字共用一张阅读底，不逐段套玻璃卡片。

### L2：磨砂玻璃

路径容器、会籍凭证使用半透明填充、细描边和柔和内高光。填充承担可读性，模糊负责深度感。夜航主要文字接近白色，次要文字为灰蓝；晨雾采用深色文字。

### L3：交互玻璃

导航、输入框、详情面板具有更强的边缘高光、更厚的背景模糊和更明确的按下反馈。用户应能一眼识别哪些区域可以操作。

本原型使用 CSS 渐变、内阴影和 backdrop-filter 模拟液态材质，未实现物理折射。真正的折射着色器属于后续可选实验，需要双端性能实测后决定。

## 4. 页面设计

### 对话工作区

- 保留“对话 / 简报 / 我的会籍”三个入口。
- 自然语言回答保持连续排版，重点结论用字重和字号强调。
- 输入框呈浮动玻璃舱，发送按钮独立为圆形；移动端与底部导航保持间隔。
- 路径图中的连线为细光线，节点采用透明度更高的实体触控面，不能只靠发光区分关系。
- 产品当前只有短期工作区，依然不伪造永久会话历史。

### 简报目录

- 大标题与轻量光学环作为封面语言。
- 条目使用编号、标题、摘要、日期与细分隔线；保留明确的阅读顺序。
- 光学环不旋转、不闪烁，不干扰内容浏览。
- 正式内容有图片时也不自动整页模糊；避免不受控的图片颜色破坏文字对比度。

### 简报阅读

- 封面保留光场，正文落入有足够遮盖能力的阅读底。
- 来源、时间、费用和版本信息保持可见，标题不替代事实。
- 费用表、会籍映射与申请条件沿用当前数据结构，不因视觉需求删减。
- 默认当前版本，历史链接保持其版本；明确操作才切换当前资料。

### 我的会籍

- 会籍凭证采用较大圆角、透光层与光学环压纹。
- 项目、等级、有效期承担主要信息层级，不增加虚构编号或权益。
- 编辑使用玻璃面板，表单区保持稳定底色。

### Android

- 底部导航变成悬浮胶囊，选中项有凸起磨砂质感。
- 路径按纵向阅读，详情从底部进入；不把桌面图直接缩小。
- 原生实施时适配安全区、系统手势、键盘抬升和字体缩放。
- 保留 Android 原生返回与无障碍行为；视觉接近 iOS 的圆润连贯感，平台操作遵循 Android。

## 5. 动效

| 场景 | 设计目标 | 原型覆盖 |
|---|---|---|
| 按压 | 小幅压缩，松开柔和恢复，约 120–220ms | 已有 CSS 反馈 |
| 切页 | 短距离淡入，约 220ms | 已有 |
| 详情面板 | 连续上移与背景失焦，约 280–360ms | 已有概念过渡，原生弹簧待实施 |
| 胶囊选择 | 同一玻璃选中层平移，保留速度连续性 | 当前为选中材质切换，连续滑块待实施 |
| 环境光 | 24–30 秒轻微位移 | 已有 |
| 减少动态效果 | 停止环境动画与过渡 | 已有媒体查询 |

“丝滑”最终由帧时间、手势中断与键盘协同决定，不能只凭截图验收。原型未声称达到原生流畅度。

## 6. 工程与可读性约束

沿用基础方案：Web 使用 React / TypeScript，Android 使用 Kotlin / Compose，共享语义化设计变量和业务契约。第二版不要求更换后端或 Agent。

- Web 的模糊效果必须有实色回退；原型已加入不支持 backdrop-filter 时的样式。
- 减少透明度偏好使用更实的底色；正式 App 还需提供应用内选项，避免完全依赖系统媒体查询。
- Android 的实时背景采样能力与成本需要按最低支持版本实测。优先预先模糊的环境底图加半透明表面；不要对每个滚动条目重复进行实时背景模糊。
- 不持续动画化 blur 半径；环境光仅缓慢平移。
- 正式阶段逐个检查最亮/最暗背景下的文字对比度、200% 字体、TalkBack 和键盘遮挡。正文目标至少 4.5:1，不能把这份目标当作已完成的测试结果。
- 不在玻璃面板上放另一层密集玻璃表格；复杂数据增加实色支撑。
