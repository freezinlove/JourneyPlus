# Agent 正常生产链路验收（2026-09-13）

## 结论

**本轮综合验收不通过。** 正常网页、真实第三方模型、正式数据库已经实际连通，活动读取、图卡、用户数据操作、后台等待检查等多条链路可工作；但最主要的“根据会籍查匹配路径”在当前正式数据上反复失败。不能把运行记录的 `COMPLETED` 当作用户要求已经完成。

本次只做生产验收和事后审计，未修改应用代码、数据库模型、AIWorkflow 或模型配置，未创建 Git 提交。缺陷保持原状，供后续针对性修复。

## 实际执行方式

- 从 Chrome 的正常 `/workspace` 页面创建三个会话，填写自然语言并点击发送，由正式 Qwen 自主选择工具、参数和后续行动。测试包含普通提问、自然纠正和明确标记的临时会籍/等待任务。
- 使用正常 `python -m journeyplus.agent.server` 服务、现有正式 PostgreSQL 配置。未替换 ModelPort，未使用隔离库、模拟模型或直接调用工具的测试脚本代替用户操作。
- 开始时没有 Agent 服务监听，因此启动了正式入口；等待检查、过期会话清理和恢复生命周期保持启用。中途在全部请求结束后正常终止并重新启动同一入口。
- 数据库查询和代码阅读只用于旁路审计。会籍、任务和笔记的创建、修改、取消、删除全部通过网页聊天交给模型执行；没有用 SQL 修正测试结果。
- 真实聊天发生于北京时间 **18:55:51—19:24:45**。共 **37 轮、106 次工具调用**，分别为主会话 16 轮、用户操作会话 16 轮、知识会话 5 轮。
- 持久化运行终态为 35 次 `COMPLETED`、1 次主动 `CANCELED`、1 次 `PARTIAL`。其中多次 `COMPLETED` 实际只是解释失败或建议继续，并未完成要求的路径图。

运行代码基线：`e2a73ecc50e5fd5b5095202b196a60d5e11695c6`，开始时工作区干净。

模型配置：`qwen3.8-flash`，native tool calling，显式缓存已开启。配置的上下文窗口为 32,768 token，历史目标预算 100,000 token；单轮累计输入软/硬预算为 90,000/120,000 token。未在此次验收中提高预算或更换模型。

最终检查点累计记录 137 次模型请求、2,359,572 个输入 token。这个数是 Harness 检查点统计，不是独立核对的供应商账单；缓存命中 token、每次完整网络请求体没有持久化，不能据此声称本轮全部请求均命中缓存或完成了逐请求上下文抓包审计。

## 优先缺陷与归因

### 1. 主查询先存全量搜索中间结果，再分页，导致正常查询失败

本轮 **17 次**工具观察包含 `Artifact exceeds one megabyte; split into referenced sections`。例：知识会话第 5 轮，仅查英航 Silver → Flying Blue Gold、希腊、1000 欧元上限，仍失败；相同业务条件由正常等待检查获得 EUR 199 的真实结果。

`src/journeyplus/agent/tools/routes.py:205` 把 `server_routes`、`server_steps` 与 snapshot 一起组装，调用 ArtifactStore 保存后才 `result_page`。`src/journeyplus/agent/adapters/artifacts.py:40` 限制单对象 1,000,000 字节。底层搜索积累的步骤包含遍历过程中产生的步骤，因此查询目标小不代表存储对象小，减小输出页 limit 也解决不了。

对照 `src/journeyplus/agent/services/waiting.py:199`，等待结果只保存命中路径所引用的步骤；本次单条结果约 8.5 KB，可以正常继续读取和展示。

**这是结果组织/保存的问题，不是本次模型没理解价格，也不是数据库没有对应匹配。** 错误却被归到 `INVALID_ARGUMENT`，诱使模型不断调整参数重试。优先应整理/分段存储结果、让分页真正限制交付规模，并正确区分容量故障和参数错误；不能只调大上限或指望模型反复缩小 limit。

### 2. 正常业务任务被上下文与累计预算消耗拖垮

主会话第 3 轮为确定英航身份用了大量查名称操作；知识会话第 1 轮累计 10 次模型请求、110,408 输入 token，最终 `PARTIAL`，既没有要求的卡片，也没有最终自然语言答复。其他多轮进入预算收尾后，请求展示仍被 `BUDGET_LIMIT` 拒绝。

当前并非实际给予模型 10 万 token 上下文：`harness/context.py:17` 先受 32,768 的配置窗口限制，再扣除输出与保留空间。单轮输入预算又按多次请求累计计算，重复发送历史会持续消耗。

优先修工具结果尺寸、名称/引用读取和历史搜索；再分别核定模型真实窗口、单请求上下文目标、单轮累计成本。应保留足够的正常回答收尾能力。不能只把这些失败归结为模型“不听话”。

### 3. 工具事实正确，但最终叙述仍会错误；压缩后的完整因果尚缺可观测记录

| 实际工具/数据库内容 | 模型实际说法或行为 | 归因边界 |
| --- | --- | --- |
| Flying Blue caveats 明确写中国大陆不可申请 Platinum | 早期回答称中国限制未提供，并把这个判断写入临时笔记 | 读取结果有该事实，解释/后续上下文使用出了问题；后来单独提问正确回答 |
| 正式日期为 9 月 13 日，会籍截止 9 月 12 日，工具判断过期 | 模型说“今天 2026-08-04”，质疑过期结果 | 模型没有可靠使用当前日期；目前上下文未见显式当天日期注入 |
| 等待 list 返回 `RESULT_PENDING`、新 revision、真实 result_ref | 展示正确路线后又说任务仍 ACTIVE，或把旧修改回执说成最新状态 | 当前工具输出正确；后续预算压缩可能移出该行，不能未经逐请求捕获就断言全由模型理解造成 |
| 文章来源链接含 `/2026/09/11/` | 最终自然语言改写成 `/2026-09-11/` | 模型改写链接错误；卡片保留正确链接 |
| 用户要求按已存有效会籍查，实际全过期 | 模型读取过期项后改用显式 tier 查询 | 工具允许假设查询本身合理，但此次是模型越过用户的有效会籍条件 |

上下文代码还有值得优先核对的具体机制：等待列表按创建时间从旧到新返回，通用 `trim_for` 从尾部移除行。因此预算压力下可能先去掉最新有效任务、留下较早已取消任务。该机制是代码审计发现，不能冒充本次某个请求的线缆级上下文证据。建议保留当前操作相关任务的简短最新状态，历史大结果再按需展开。

模型偶尔把 `display.present` 写成不存在的 `items` 结构，或提供缺版本的展示引用；工具正确拒绝，但要多次纠正才能展示。需要改善实际提供给模型的接口说明与错误恢复体验，不需要恢复逐字段原文引用协议。

### 4. 历史和资料搜索的真实行为不容易被模型正确使用

`adapters/persistence.py:181` 对历史序列化内容做整个 query 的连续子串匹配。模型组合多个词搜不到，工具调用参数又可能包含同样的检索词，从而命中近期工具记录。前两次找“最早的问题”失败，用户明确要求只搜“会籍挑战”后才成功。

资料检索与原文引用也存在类似负担：原文章节读取仍有二次 artifact 入口，模型一度把 document 引用传给要求 artifact 的入口，或续页时漏带原 query。工具错误保护有效，但用户需要反复说“继续”。优先让搜索语义、继续读取参数和原文入口更直接；不应要求每条事实配原文证据。

### 5. 展示中仍有内部字段和来源角色错误

- 两路径比较的有效期列实际显示：`value：批准后12个月；conflict：false；evidence：暂无；alternatives：暂无`。这是程序将整个状态有效期对象交给通用展示，见 `services/presentations.py:21` 与 `product/static/workspace_v3.js`。用户需要的就是“批准后12个月”，不需要这些内部字段。
- LoyaltyLobby 文章卡片实际标成“官方来源 · loyaltylobby.com”。`product/static/knowledge_ui.js:106` 只有 `THIRD_PARTY` 分支显示“文章来源”，其余均默认“官方来源”。链接没有丢，但来源身份显示错误。

### 6. 后台命中与主动提醒需要单独补验收

正式 maintenance 已实际查出单条、多条结果；任务记录转为 `RESULT_PENDING`。本次观察到用户主动询问才读取和展示，未观察到后台主动把结果提示到当前页面。对应样本的 `notified_at`、`pending_seen_at` 仍为空。

后台查询成功不等于“有结果再提示我”的用户闭环已经通过。需要核对既有提醒入口和结果消费状态，再决定补哪一小段连接；不必让后台启动另一套 Agent 或 AIWorkflow。

## 覆盖边界

- 正式库当前没有已结束/已软归档的活动样本。未擅自把真实活动归档以造场景，因此归档旧引用、旧图卡和旧上下文失效，本轮不能判通过。
- 多页主路径、完整跨项目多跳以及其费用比较被 1 MB 故障阻断。等待得到的两条单步路径图与比较通过，不替代这些场景。
- 本轮 Flying Blue 金额/映射核对基准是当前正式事实版本；没有重新运行 AIWorkflow，也没有宣称重新逐字段验证了官网全部内容。普通文章的 FREE 是既定数据口径，不等于证明相关信用卡无年费。
- 本次使用真实 Qwen，不是 Codex 接替 ModelPort。第一视角是普通用户页面实际体验，第三视角是实际请求、持久化调用/结果、检查点、数据库与页面对照。没有捕获每次预算投影后的完整供应商请求体，压缩如何影响个别错误的归因仍需补观测。
- 已做空闲正常重启；未人为制造模型限流、数据库故障、进程处理中崩溃或过期时间篡改。正常维护自然清理了旧会话，但未完整验收当前会话跨 24 小时的 UI 行为。
- 显式缓存配置开启；没有本轮逐请求缓存命中统计，不作命中率声明。
