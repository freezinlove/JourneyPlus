# 贯通实例、交付边界与验收设计

## 1. 原文依据与技术补全的边界

[discussion-source.md](discussion-source.md) 保存当前分支 13 个讨论回合中的 12 份最终答复和全部对应用户消息。候选研究回合 interrupted，原本无最终答复；不将该回合中间研究过程当用户已认可结论。后续数据库整体重构优先于早期“只修读取层”；后续整体卡片点击优先于连线／标签可点；最终经验融入原详情优先于独立经验卡设计。

本轮确定的字段、枚举、版本并发、工具 envelope、状态机和初始预算属于详细设计补全，不谎称全部在早先聊天中逐字出现。所有硬业务原则来自讨论；以下演示用合成事实，不冒充真实活动价格。

## 2. 用真实调查问题检验新模型

讨论时 Kenya Airways 的数据快照有 207 条映射、4 种申请方式、12 项价格，关键缺口是映射与方式并排保存。迁移必须对这个真实样本逐项输出：旧字段路径、原文证据、归属 option、价格作用目标与 mapping 范围、关联是否已证实。

不能直接生成 207×4×12 组合，也不能用某个最低价补齐未知。在只知道这三个数量而没有重新核验原文时，本设计不指定哪个真实价格属于哪条映射。实施验收需使用备份中的源资料证明这些关系；无法证明的落 UNRESOLVED，保留旧值和材料。这个未知是数据质量边界，不是把模型设计留给实施者。

## 3. 完整合成夹具

设有活动 `B-2026-01`（仅示例），来源资料如下：

- HOME H1：航空会籍与酒店会籍有两种申请方式；可申请 Silver 和 Gold。
- Terms T1 第2节：航空 A Gold 可申请 B Silver 或 B Gold，来源须正常取得；Silver 申请费 EUR100，Gold EUR200，无挑战。
- Terms T1 第3节：酒店 H Platinum 可申请 B Gold，申请费 EUR50，但获挑战，90天内完成4次住宿；住宿成本未说明。
- FAQ F1 Q4：通过其他匹配取得的来源会籍不接受。

预期入库如下（下列短 ID 仅用于说明，数据库实际为 UUID）：

| 对象 | 记录 |
|---|---|
| Activity / KnowledgeVersion | B-2026-01 / K1，current=K1，关联 H1/T1/F1 |
| Option 身份与版本 | O-air/V-air-K1、O-hotel/V-hotel-K1 |
| Mapping | M1 A Gold→B Silver 属 V-air；M2 A Gold→B Gold 属 V-air；M3 H Platinum→B Gold 属 V-hotel |
| Price | P1 EUR100 target=Silver mapping=M1；P2 EUR200 target=Gold mapping=M2；P3 EUR50 target=Gold mapping=M3；均 APPLICATION/REQUIRED，各自 charge_key |
| 条件 | 航空方案 SOURCE_ACQUISITION=EARNED_ONLY，证据 T1 §2、F1 Q4；不能把另一方案的附加条件隐式复制给它 |
| 挑战 | 航空 KNOWN/NONE；酒店 KNOWN/REQUIRED，metric STAYS=4、window=90天，住宿支出 UNKNOWN |
| 证据 | E-price1 指 T1 §2 对应行并带表头；E-elig 指 F1 Q4；E-challenge 指 T1 §3 |

同一资料写入两次只复用相同版本／提取键；正文改变才产生新文档版本。所有事实与证据归属 K1，价格不在简报里再存真值。

## 4. 用户问“申请 B Gold 要多少钱？”

这是活动价格问答，无需持有会籍或目标推荐流程。query_activity_materials 定位 B-2026-01，取 Gold 的两个方案：航空 EUR200；酒店 EUR50+住宿挑战支出未知。返回两项价格、方案适用性和挑战，不把 Silver EUR100 混入，不回答“最低50欧即可拿Gold”。

模型决定先解释两个办法；服务端显示有方案范围的费用和资料版本。活动卡整体点击到同一详情的两个方案。进一步问“酒店那种要住几次”只展开 V-hotel 的挑战证据，不注入全部映射。

## 5. 用户问“我有 A Gold，100欧以内，不接受挑战”

用户新会籍可先作为假设查询，不强制保存；正式持有会籍写入另出确认。目标未明确允许探索。程序得到 R1=A Gold→B Silver（EUR100，无挑战），R2=A Gold→B Gold（EUR200，无挑战）。R2 明确预算 FAIL；酒店办法不能利用用户并未持有的 H Platinum。

R1 已声明预算与挑战条件 PASS，但来源取得方式未知，卡片显著提示资格待确认。若用户要求“确定符合资格的方案”，R1 进入 UNKNOWN；不能把正式查询条件与获批保证混为一谈。模型比较包只带 R1、R2的排除／近似原因和相关限制，不带全篇 FAQ。

用户继续“我的 A Gold 也是匹配来的”：工作区增加临时 SOURCE_ACQUISITION=MATCHED，不长期保存为画像；程序重新评估 R1/R2 来源限制 FAIL，模型引用 FAQ 解释。不得提出“放宽来源资格”来绕过官方禁止规则。

若用户有正常取得 A Gold 且目标明确 B Gold，只有 R2 超预算一个可调条件，可以提出 cap100→200 的单项调整；确认前不进入当前正式推荐，拒绝后不再递归提更宽松方案。

## 6. 用户问“B 到 C，再到 D，这两条哪个更稳？”

假设已有两条可定位路线共享 B→C，程序创建 S-common、S-CD1、S-CD2 三个步骤研究对象。模型调用 research_statusmatcher，用户无需重新描述每步。共用步骤只调查一次；详情报告结构化进入工作区，报告层与步骤层独立。

若 S-common 有直接可比报告，S-CD1 只有部分可比，S-CD2 请求失败：明确每一步情况，保留已查数据；不能把 S-common 的正面计数扩散成整条路线高成功率，也不能说 CD2 没人成功。卡片一条简短经验状态，原详情按步骤展开。用户问“第二步被拒原因”优先复用相关报告，再必要定向补查。

服务器许可关闭则零网络，状态 DISABLED；正常官方资料仍能显示。经验暗示资格限制则回查官方活动资料，不将报告保存为官方规则。来源条件改变时缓存重判可比性。

## 7. 更新、旧卡和三入口一致性

T2 将航空 Gold 费用由200改为180：新 K2 引用 T2 价格行，V-air-K2/P2-new；K1/P2 仍存在。原子 current 切到 K2，CURRENT 卡先显示180；UPDATE 说明200→180，生成未完成则显示待更新而非无标识旧简报。

新图查询和新 Agent 回合使用 K2，金额180。旧回答仍绑定 K1，点击看到当时200并提示有更新；刷新后重新查询 K2，生成新内容，不修改旧话语。同一新查询快照下三个入口必须都使用180及同一证据。

## 8. 简洁交互验收实例

1. 简单活动问答只显示答案与必要事实，不强制整图。
2. 点击卡／节点 → shared detail，messages 数量、model_calls 和 research_requests 均不增加。
3. 节点有多个取得方案 → 同面板列方案，不能随机跳一篇文章；图连线和费用标签没有独立导航。
4. 点回答末尾“比较这两条” → 用户消息可见，带当前对象 refs，进入正常 Agent 回合。
5. 来源／申请链接集中详情；经验只在已有详情展开，无多报告卡瀑布。
6. 窄屏路线为纵向步骤，返回保持滚动和焦点；键盘可打开整体卡片。

## 9. 验收矩阵与责任落点

| 板块 | 必须遵循的详细设计 | 最低实现证据 |
|---|---|---|
| 数据身份和存储 | database-design §1–5 | PostgreSQL FK／唯一性／JSON校验；跨版本价格引用被拒 |
| 来源与 Workflow | database-design §6–8 | 重复处理、并发旧基线、半失败、三页完整性、幂等回填 |
| 渐进披露与数据包 | data-access-design §1–3/6 | 闲聊零注入；按问题只取相关片段；展开保留脚注 |
| 路径与候选处理 | data-access-design §4–5 | 合成夹具正确；未知、币种、费用范围、重复到达、partial |
| 对话与恢复 | agent-runtime-design §1–3 | 真实中文模型、任意输入、续接、故障后可恢复、并发和三次上限 |
| 用户写入与等待 | agent-runtime-design §4–6 | 过期／重复确认、无命中零模型、首次结果停止、GET不消费 |
| 简报与图 | presentation-research-design §1–4 | 同版本价格一致、更新差异、多路线保留、公开挑战 |
| 展示与点击 | presentation-research-design §2/8 | 桌面／窄屏真实浏览器，浏览与消息边界可观测 |
| StatusMatcher | presentation-research-design §5–8 | 列表与详情夹具、时间和可比性、总预算、许可状态；许可具备再真实链路 |

评测集初值40题：闲聊/澄清/恢复8，活动资料8，路线费用和资格12，多轮指代与交互6，经验与等待6；其中10题保留不用于 Prompt 调参，关键题至少3次独立真实模型回合。固定同源数据比较全量旧包、全候选精简包、分组短名单+展开以及同字段 Markdown。记录召回、关键事实/引用错误、完成率、真实usage、调用数、P50/P95时延；不得仅因 token 更少判断优化有效。

上线门槛：确定性金标的错价／未知误判／越权写入为零；原先自由输入失败案例能推进；三入口版本一致；真实 Provider 和浏览器通过；迁移恢复包含切换后的会籍／等待写入。StatusMatcher 未许可时明确不声称生产链路已验收。没有统一假设的绝对 token 节省率或真实审批成功率指标。

## 10. 实施者可以决定和不能决定的内容

可决定：文件拆分、最终类／表名字、ORM具体写法、CSS尺寸、额外性能索引、经评测调整的预算。需要遵循上述合约完成代码、迁移和验证。

不可自行重新决定：是否整体统一数据库、方案与路线区别、价格映射关联、版本发布、条件继承与未知、工具数据形态、浏览与发消息边界、长期用户记忆范围、经验临时性和按步骤联动。若真实资料暴露未覆盖业务情形，应形成具体设计修订并附反例，不得静默建立第二套事实存储。
