## Why

JourneyPlus 的现有存储围绕不同采集链路和简报产出逐步叠加，映射、申请方式、价格和来源缺乏明确关联；Agent 又把完整查询目标设为所有输入的前提，并直接接收重复的大型候选对象，导致自然对话失败、事实判断失真和不可解释的展示。用户已确认整体重构：建立干净、有逻辑、可追溯且适合渐进披露的统一活动知识库，让单 Agent、AI Workflow、简报和匹配图共同使用，而非迁就现有页面与存储的缺陷。

## What Changes

- **BREAKING**：重建来源中立的活动／知识版本／申请方案模型，明确来源会籍、目标等级、价格适用范围、条件和证据的关联；回填邮件发现的官方活动并接入日期边界内的普通文章来源数据，不继续维护平行事实含义。
- 将活动页、FAQ、Terms、第三方文章组织为有版本和章节定位的来源资料；保留来源权威性、冲突和未知，渐进披露不等于重复保存多份事实。
- **BREAKING**：Workflow 改为采集、提取、关联、验证、发布统一知识版本，再生成简报；所有消费者读取明确版本，资料陈旧与活动结束分离。
- **BREAKING**：Agent 接受任意自然语言，包括闲聊、具体活动问答、路径探索、比较、经验调查和跟进；按当前问题组合受限工具，不要求所有输入先有完整会籍目标。
- 合并“查询活动事实”和“查询来源内容”为同一个活动资料能力；与路径查询、授权的外部经验调查共同提供概览、比较、详情和依据。
- 分离完整服务端知识、模型决策包与页面展示包；确定性过滤、去重、覆盖保留和按需批量展开控制上下文，模型主要选择引用和解释，不生成正式图边、金额或 URL。
- 引入可恢复且到期清理的临时对话工作区；长期用户记忆仅保留确认后的持有会籍，明确等待目标作为独立业务任务。
- **BREAKING**：重做简报为当前活动卡与实质变化简报，匹配图为关系探索与路线比较；一首选两备选只约束最终推荐，不限制探索。
- 返回可组合的文本、活动卡、路线图、对比、证据、经验和确认内容；节点／卡片整体点击只打开统一详情，连线与费用等标签不各自跳转；下一步建议独立发送可见自然语言请求。
- StatusMatcher 按实际申请步骤定位列表和报告详情，结构化为工作区临时观察；支持等级、时间与情境可比性，关联路线与官方条款，结果融入原有详情，不新增一排点击入口或长期经验事实库。
- 保留单 Agent、服务端确认门、无模型的确定性浏览、一个确认后的等待任务和有上限的执行；补齐迁移、语义回归、真实模型、可观测性和端到端体验验收。

## Capabilities

### New Capabilities

- `unified-activity-knowledge`: 会籍目录、活动、知识版本、申请方案及价格／映射／条件的统一身份和关系。
- `versioned-source-evidence`: 文档版本、结构化章节与证据定位、来源权威性和内容边界。
- `knowledge-publication-workflow`: 来源中立提取、关联校验、原子发布、生命周期和派生产物一致性。
- `progressive-agent-data-access`: 活动资料统一工具、分层上下文、受控批量展开、覆盖和大小预算。
- `conversational-membership-agent`: 任意自然语言、组合动作、动作合约、错误恢复和确认门。
- `temporary-agent-workspace`: 短期对话、焦点与引用、恢复与过期、长期记忆边界。
- `membership-route-evaluation`: 路径生成、费用／挑战／资格语义、候选分类、覆盖和个性化选择。
- `activity-briefs-and-exploration`: 当前活动卡、变化简报、关系探索和多路线比较。
- `agent-result-presentation`: 内容块、统一详情、简洁整体点击、独立下一步消息与无模型浏览。
- `scoped-statusmatcher-research`: 授权按步骤调研、报告可比性、临时结构化观察和对话／呈现联动。
- `confirmed-membership-waiting`: 单条件调整、明确等待确认、确定性检查、首次命中和任务结束。
- `knowledge-migration-and-evaluation`: 可回滚迁移、全链路一致性、金标、上下文评测与运行诊断。

### Modified Capabilities

无已同步主规格可作 MODIFIED delta；`openspec list --specs` 当前为空，因此上述能力使用 ADDED Requirements 完整定义目标行为。这不表示旧行为保持不变：历史 change 与文档的替代关系见 [设计](design.md) 和 [决策追踪](decision-traceability.md)。不修改或归档历史 change 来伪造实施完成。

## Impact

- 影响 SQLAlchemy 模型和 Alembic 迁移、采集与正文处理、官方／普通文章事实链路、价格与图查询、简报、Agent Controller／契约／工作区、StatusMatcher、每日等待检查、FastAPI 与前端呈现、配置和测试。
- 继续采用 Python 模块化单体、FastAPI、PostgreSQL、Pydantic 与现有 AIProvider。关系表保存身份和关联，类型化 JSON 保存复杂事实，文档保存正文；不以图数据库、向量数据库、多 Agent、消息平台或新前端框架为前提。
- 当前本地单用户、不执行申请／支付／对外联系、不建设完整权益目录或数据库外活动发现的范围继续有效。任意自然语言不等于所有领域都具备数据能力。
- 当前用户已授权按本 change 实施代码、隔离回填和真实验收；文档完整不表示代码实施完成。正式数据库迁移与默认入口切换按验收流程处理，不自动启用外部调查或创建 Git 提交。
