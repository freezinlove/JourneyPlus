## ADDED Requirements

实施合约见 [核心详细设计](../../data-access-design.md)；它与本规格共同约束实现，不将核心机制留待代码阶段重新选择。

### Requirement: 单一活动资料能力
Agent SHALL 通过同一活动资料能力定位活动并读取相关结构事实、FAQ／Terms、来源或变化；系统 MUST 不要求模型先选择“事实库工具”还是“正文工具”。

#### Scenario: 复合活动问题
- **WHEN** 用户询问一个活动的费用和Terms对来源会籍取得方式的规定
- **THEN** 同一能力返回相关费用事实和条款依据，不传整份活动全部资料

#### Scenario: 活动名称歧义
- **WHEN** 用户的简称可能指向多个活动期次
- **THEN** 工具返回少量带区分信息的定位候选，Agent澄清后再读取具体事实

### Requirement: 分层披露与三类数据对象
系统 MUST 分离完整服务端知识、模型决策包和UI展示包；模型读取 SHALL 支持概览、比较、详情、依据，按问题选择而非固定全发。

#### Scenario: 查询路径概览
- **WHEN** 用户只想知道能到达哪些目标
- **THEN** 模型得到分组目标、路径和重要费用／条件状态，不收到全部FAQ、Terms和历史简报

### Requirement: 高信号结构化模型输入
模型决策包 SHALL 使用有类型、可读的结构和必要短文本，包含稳定短引用、单位、未知和冲突；系统 MUST 去除重复步骤、无关原文及内部技术冗余。

#### Scenario: 同一步出现在两条路线
- **WHEN** 两条候选包含完全相同申请步骤与版本
- **THEN** 模型包共享步骤信息且引用可还原，不重复发送完整费用和证据正文

### Requirement: 压缩不得隐藏决策条件
候选摘要 MUST 显示影响选择的资格、费用适用范围、挑战、未知、冲突与时间限制；无法完整披露关键条件时 SHALL 标记必须展开并阻止确定推荐。

#### Scenario: 关键条款超过摘要预算
- **WHEN** 一条候选的适用限制无法在比较卡内完整表达
- **THEN** 卡片标识未展开关键条件，工具允许批量核对，Agent不得把它当无条件可行

### Requirement: 分开搜索覆盖与呈现覆盖
接口 SHALL 返回实际搜索范围、partial状态、已观察数量和呈现子集信息；系统 MUST 不将预算内未找到或短名单遗漏称为全库无解。

#### Scenario: 搜索预算耗尽
- **WHEN** 路径搜索未完成便达到技术预算
- **THEN** 响应说明partial和继续方式，数量仅描述已观察结果

### Requirement: 受控批量展开与上下文重建
Agent SHALL 能批量展开少量所选路线或活动资料；程序 MUST 在后续模型调用中重新构建聚焦上下文，而非累计全量历史工具响应。

#### Scenario: 比较两条路线的资格
- **WHEN** Agent选择两条路线核对资格
- **THEN** 程序在一次受控读取中返回两者相关事实与必要证据，保留其他候选的覆盖提示而不重发所有详情

### Requirement: 输入预算可测量与可校准
系统 SHALL 配置候选数量、内容大小和回合预算并记录实际使用量；格式和短名单参数 MUST 经过保留集评测，不将字符数等同token。

#### Scenario: 更换JSON为表格实验
- **WHEN** 比较不同序列化格式
- **THEN** 实验使用相同字段和任务，记录正确率、召回、真实usage与耗时，不因更短就认定更优
