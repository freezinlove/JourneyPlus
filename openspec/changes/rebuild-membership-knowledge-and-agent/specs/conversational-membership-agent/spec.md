## ADDED Requirements

实施合约见 [核心详细设计](../../agent-runtime-design.md)；它与本规格共同约束实现，不将核心机制留待代码阶段重新选择。

### Requirement: 任意自然语言入口
Agent SHALL 接受闲聊、意图表达、活动问题、路径探索、比较、经验调查和后续指代；所有输入 MUST 不以完整会籍或目标字段作为统一前置条件。

#### Scenario: 用户打招呼
- **WHEN** 用户发送“你好”
- **THEN** Agent自然回应，不读取活动或路线资料，不报目标缺失错误

#### Scenario: 用户没有明确目标
- **WHEN** 用户问“我有什么能匹配的？”或只说“我有汉莎金卡”
- **THEN** Agent根据现有信息探索或问一个关键问题，不因target为空而结构化失败

#### Scenario: 超出当前知识范围
- **WHEN** 用户提出数据库不支持的权益优化或其他领域问题
- **THEN** Agent正常说明能力边界，不编造事实、不执行越界动作也不抛合约错误

### Requirement: 动作特定合约与组合工具
系统 SHALL 将可不完整的理解草稿与可执行动作分开校验；Agent SHALL 按当前问题和观察选择允许动作，并组合活动资料、路径与经验能力。

#### Scenario: 只问活动条款
- **WHEN** 用户明确询问已定位活动的申请资格
- **THEN** Agent读取该活动资料，不强制保存持有会籍或先生成推荐

#### Scenario: 复合比较问题
- **WHEN** 用户同时要求比较价格并核对某个资格条款
- **THEN** Agent组合相关读取并形成聚焦回答，不把所有问题固定走同一调用链

### Requirement: 每回合关键追问与正式确认
Agent SHALL 每回合最多追问一个影响当前结果的关键问题，后续回合允许继续补齐；正式会籍写入 MUST 经唯一规范化和用户明确确认。

#### Scenario: 上轮澄清仍有下一项歧义
- **WHEN** 用户回答了项目歧义但等级仍不明确
- **THEN** 下一回合继续问等级，不因曾问过一次而强制重开工作区

#### Scenario: 临时假设与已有会籍
- **WHEN** 用户说“假设我有某张卡”或复述已确认的相同会籍
- **THEN** 前者只保存在临时假设中，后者直接复用；任何新的正式写入均有具体确认内容

### Requirement: 有限调用与分类恢复
Controller MUST 对每HTTP回合强制最多三次模型调用并计入修复，允许至多一次可恢复输出格式修复；网络、Provider、JSON、Schema、非法动作和工具失败 SHALL 分开诊断。

#### Scenario: 模型输出字段错误
- **WHEN** 输出Schema失败且回合仍有修复预算
- **THEN** 系统以脱敏错误路径进行一次受限修复，不放宽业务权限或伪造缺失事实

#### Scenario: 已有事实但模型最终回答失败
- **WHEN** 候选或资料查询成功而模型失败或预算耗尽
- **THEN** 保留工作区和可浏览事实，说明未完成的部分并允许重试，不只显示候选数量

### Requirement: 服务端动作权限和幂等
Controller MUST 校验动作白名单、对象版本、确认令牌和写入条件；浏览上下文或客户端伪造历史不得替代确认。

#### Scenario: 重复确认或旧版本确认
- **WHEN** 同一个确认请求被重复提交或绑定的工作区版本已变化
- **THEN** 系统幂等返回已有结果或要求重新核对，不重复保存、不应用过期调整

### Requirement: Provider可用性真实表达
系统 SHALL 区分未配置、最近健康状态与本次调用结果；其他确定性页面 MUST 在Provider不可用时继续工作。

#### Scenario: Provider对象存在但调用超时
- **WHEN** 已配置模型本次无法响应
- **THEN** 页面显示本次模型失败而非假称可用，详情和图的确定性读取仍可使用
