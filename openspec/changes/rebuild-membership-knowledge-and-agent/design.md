## Context

本 change 持久化当前对话已认可的完整设计，用户后续纠正优先于早期方案。尤其固定四项：活动事实与来源内容是同一查询能力；长期用户记忆仅为会籍；节点／卡片点击浏览与下一步消息是不同交互；StatusMatcher 经验融入路线现有详情，不增加杂乱入口。

当前 `FactSet` 将 status_mappings 与 application_routes 并排保存，价格虽有金额／币种／等级，但方案适用关联不足。数据库真实样例 Kenya Airways 有 207 条映射、4 种申请方式、12 项价格，不能让模型或查询器自行猜关联。现有状态、简报和关系图可以整体替换，原始资料、证据与版本应保留。

调查实测仅作为问题依据：12 条天合候选的紧凑 JSON 为 25,393 字符；完全相同步骤提取为共享表后为 18,305 字符，可无损还原，下降 27.9%。字符不是 token，也不代表新模型效果已验证。自然语言“我有什么能匹配的？”曾因 interpretation.target 必填失败；相关 31 项旧测试通过并不构成新能力验收。

文档入口：需求见 `specs/`，完整用户决策映射见 [decision-traceability.md](decision-traceability.md)，分阶段执行见 [tasks.md](tasks.md)。当前仓库无主规格，采用完整 ADDED specs；历史 change 不修改、不自动归档。

## Goals / Non-Goals

**Goals:**

1. 一套统一活动知识服务 Workflow、Agent、简报和关系图；用领域关系组织事实，而非按来源或页面堆 JSON。
2. 任意自然语言进入同一单 Agent 对话，依任务组合工具，逐步提供足够且可追溯的信息。
3. 费用、挑战、资格、生命周期及查询覆盖诚实且一致；模型不发明事实或隐去关键未知。
4. 结果简洁可浏览，卡片／节点一个主要点击入口，证据和经验在统一详情内展开。
5. 可迁移、可回滚、可恢复、可评测，保留旧资料与确定性浏览能力。

**Non-Goals:**

- 多 Agent、任意 SQL／URL 工具、全网发现数据库外新活动、自动申请／支付／联系项目方。
- 完整会籍权益目录、泛旅行规划、会员账号同步、材料收集、客服／退款／申诉、长期聊天画像。
- StatusMatcher 批量镜像或长期案例事实库；将社区比例表述为真实审批概率。
- 为重构预先引入图／向量数据库、消息队列、独立 Worker、通用条件 DSL 或新前端框架。

## Decisions

### D1. 一个知识底座，三类消费视图

关系表保存稳定身份和关联，类型化 JSON 保存复杂事实与未完全结构化说明，正文保留版本和段落结构。继续 PostgreSQL、SQLAlchemy、Alembic、Pydantic、FastAPI 和现有 AIProvider 的模块化单体。

完整知识对象只在服务端使用；模型决策包和 UI 展示包分别构造。图、路径、简报均是派生视图，不能反向成为第二份权威事实。数据库可以有必要的后台表，但 Agent 不认识采集表、日志表或多个来源内部模型。

备选考虑：只在旧 DTO 外做摘要无法修复关联错误；所有内容放一个 JSON 无法清楚维护身份和适用范围；每个文字条件都拆表／转规则引擎成本过高；单独图数据库不能解决证据和价格归属。采用有边界的混合存储。

### D2. 领域关系与建议物理模型

以下为实施基准，表名可以按现有迁移命名调整，但身份与约束不能省略。

| 领域 | 建议记录 | 关键字段和关联 |
|---|---|---|
| 目录 | MembershipProgram、MembershipTier、MembershipAlias | 稳定 ID、名称／规范键、项目分类、可证实的联盟归属；等级属于项目，别名可歧义，不能静默任选 |
| 活动 | Activity | 项目／目标范围、机会种类、活动期次身份、当前知识版本；同一项目不等于同一次活动 |
| 知识版本 | ActivityKnowledgeVersion | activity_id、版本号、发布状态、来源集合、共同事实、内容签名、发布时间 |
| 申请方案 | ApplicationOption | 稳定逻辑 ID＋版本引用、申请方式、来源资格范围、共同条件、目标范围、入口、时间／有效期事实 |
| 对应关系 | OptionMapping | 方案版本、来源项目／等级或明确范围规则、目标等级、availability、条件、证据 |
| 费用 | OptionPrice | 方案版本、目标档位／明确通用范围、金额、币种、费用角色、适用条件、可用性、原文及证据 |
| 来源 | SourceDocument、DocumentVersion、DocumentSection | 复用 SourceItem/DocumentVersion 时明确别名；网址、来源类型、抓取版本、允许保存的正文、章节／问答／表格与脚注 |
| 活动来源关联 | ActivityDocument | 一个活动对应多文档，一个文章可对应多活动，记录相关片段与来源角色 |
| 证据 | EvidenceReference | 文档版本、章节／表格行定位；由具体事实／映射／价格引用，不接受只有首页 URL 的伪精确证据 |
| 派生简报 | ActivityBrief、ActivityUpdateBrief | 知识版本或前后版本、正文、事实引用、生成版本，不存独立价格真值 |
| 用户 | StatusHolding | 规范项目／等级、可选有效期，确认后写入 |
| 临时状态 | AgentWorkspace | 有类型状态、焦点、近期展示／顺序、引用映射、预算、TTL、临时经验 |
| 等待任务 | WaitGoal | 确认的条件、持有会籍引用、任务状态、首次命中与展示确认，不属于用户画像 |

Activity → KnowledgeVersion → ApplicationOption → Mapping/Price 是主要归属链。身份以稳定 ID 关联，禁止用数组位置跨版本关联；外键、唯一约束、发布版本不可变、单一 current 指针维护一致性。复杂事实使用 `value/known_state/evidence_refs/conflict/alternatives` 类型结构，不做无类型键值仓库。

映射和价格不能因都在同一活动就交叉适用。共用条件在方案层保存，例外归属到具体映射／价格，继承必须明确且保留证据；方案是一步申请，路线是多个方案组成的计算结果。来源范围可为明确会籍、明确项目／类别规则、公开资格或未知，空来源不能同时代表公开与未知。信用卡等来源类别只有既有 STATUS_MATCH 资格允许时才参与，不恢复 OTHER 信用卡赠会籍机会入图。

来源不明确时不做映射×地区×价格笛卡尔积猜测。保留待关联材料／草稿和 UNKNOWN，进入待确认视图；不能错误发布成已证实的方案。没有证据的跨项目等级大小／联盟高卡等价保持未知。

### D3. 正文、结构化知识与证据同源

保留允许存储的来源 HTML 和清洗文本，按文档真实结构生成 FAQ 问答、Terms 章节、段落、表格、行及关联脚注。section_id 在文档版本内稳定，证据必须落到对应版本；不把文档全切成互相失去上下文的固定字数块。

先使用活动限定的章节索引和文本检索；暂不引入 embedding。活动资料工具优先给已提取事实，需要细节／原文／冲突时补充相关片段。事实与片段属于同一个工具，不让模型先判断数据库内部位置。

官方与第三方资料可共同支持活动但来源身份不合并。无说明、未检索到、内容缺失、冲突分别表达；搜索不到不等于允许，也不等于不存在。原文属于数据而非工具指令，不能改变动作权限或产生任意网络请求。

保留现有来源许可／清洗限制，特别是项目 TERMS 中平台公共后半段的排除，历史费用表不能进入当前报价；这里的原始正文不是无限制网站镜像。

### D4. Workflow 生产知识，简报成为消费者

流程固定为采集／版本化 → 内容定位 → 来源限定的提取与方案关联 → 确定性校验 → 发布知识版本 → 派生简报／查询投影。官方和普通文章提取方式可不同，发布结果使用同一模型。一文多活动不能混淆资格／日期，无法确认同一活动期次的资料不自动合并。

表格价格继续优先确定性提取；模型补充非表格文字，不另建在线摘要 Agent。校验来源、作用范围、日期、金额、映射方向、冲突以及别名唯一性。仅增加相同证据不生成虚假的实质变化简报。

发布以短数据库事务原子切换 current version；模型／网络调用在事务外，避免长事务。失败保留上次有效版本及当前错误。简报生成可在发布后受控重试，未生成的当前简报显示待更新；禁止旧版简报无标记冒充新版。缓存键包含活动知识版本、查询条件和持有会籍版本。

活动结束、生效／截止时间、资料新鲜度、最后检查、来源变化、知识发布分别建模。现有三页完整性及 HOME 结束判定继续保留；辅助页失败不说明活动结束。普通文章证据过旧可不再用于“当前可行”结论，但不能伪造活动关闭事件。OTHER 仍可出活动卡／简报，不能入匹配图。

### D5. 渐进式模型数据契约

对模型暴露三个主要读取能力：

1. `query_activity_materials`：项目／活动线索＋当前问题＋关注方面，内部定位活动，返回概览、事实、相关正文或变化；歧义时返回少量明确对象供选择。
2. `query_membership_routes`：确认的会籍／目标／取舍或探索范围，返回分组概览或候选比较；受控 `inspect_routes` 批量展开属于此能力内部操作，不建设全表访问工具。
3. `research_statusmatcher`：上下文中活动／方案／步骤及问题，按授权调查，不要求用户先跑完推荐流程。

持有会籍／等待任务是独立写操作，有服务端确认门。快照、用户身份、已知对象映射由程序注入，不要求模型填写已知 UUID 或数据库连接信息。

四种披露视图：概览（身份／目标／状态／关键限制）、比较（步骤／适用金额／挑战／期限／不确定性）、详情（少量方案的完整相关事实）、依据（相关章节／表格／例外／变化）。不是每次必须四步，也不把四份数据同时发送。

模型输入用浅层 JSON、可读字段名和必要中文短说明。路线／步骤／事实使用工作区稳定短 ID 加名称；金额十进制字符串＋币种，时间包含精度和时区。明确 UNKNOWN/CONFLICT/NOT_APPLICABLE，不用空字符串或零冒充已知。本文附带的概念字段不是要求新表完全一比一照搬。

比较包包含 query、snapshot_ref、coverage、cards、reason_counts、available_expansions。card 包含 from/to、step_count、cost_state/scope、challenge、deadline/validity、constraint_checks、material_caveats、fact_refs、needs_inspection。完整 UUID、重复 URL、HTML、无关简报和大列表留在服务端。关键否定、资格、未知／冲突不可为了节省 token 隐藏；装不下时标 needs_inspection，禁止无条件最终推荐。

精简步骤：正确检索 → 硬条件评估 → 完全重复去重 → 保守的可比较支配／分组 → 保留不同取舍的代表 → 字段投影 → 受控展开。已知事实由程序计算；不新增 LLM 先压缩全库再喂另一个模型。

默认实验短名单 8 条、上限 12 条；少量候选全部返回，公开探索支持分组继续，不以三条限制探索。不是已证明最优参数。比较包约 5,000、聚焦包约 7,000 输入 token 作为调参起点；系统提示／Schema／工作区也计入总上下文。先使用实测字符／字节代理，真实评测记录 Provider usage；不能固定字符÷4充当准确 token。

查询覆盖与呈现覆盖分别返回；资源受限用 partial 和 observed counts，不能报告全库总数或保证全局最佳。按完整语义单元降载，禁止截断 JSON／否定句。

### D6. 路线评估只计算有依据的条件

从持有会籍和明确目标定位相关图，及时过滤生命周期／目标，按需读方案；没有持有会籍时也能浏览公开挑战，不伪造来源节点。所有映射按目标档位、方案和已知适用条件绑定费用，不取整个活动的最低金额。

费用：明确累计且同币种才加总，互斥价格并列，条件费用单列；不同币种不自动换算；申请费与完成挑战支出分开。任一步已知收费不能标全程免费；未知不能视为零。预算已有同币种必要支出超过上限可 FAIL；未超但剩余未知仍 UNKNOWN。

挑战：任一步 REQUIRED 则“不接受挑战”FAIL；其余全已知 NONE 才 PASS；有未知则 UNKNOWN。资格、截止、有效期和来源会籍取得方式按证据显示，部分不可计算条件由用户确认，不以“符合已声明条件”承诺全部申请资格已验证。地区默认提示，不隐含用户国籍／居住地或新增地区硬过滤；实际价格适用性不确定必须标未知。

候选四种观察：符合已证实条件、恰好偏离一个条件、关键未知、排除及原因。目标未明确时可探索；相邻较低等级仅在同项目顺序有依据时可作为调整，不能按等级名称跨项目排序。HIGH 不能让模型凭名称认定联盟高卡。

搜索有节点／边／展开状态／耗时技术预算，不设隐藏业务六步上限；路径组合爆炸必须报告未完全覆盖。先截前100条再过滤不可作为“无解”证明。到同一节点的不同来源取得方式、限制和已访问集合可能影响后续，不可只凭低价删除路径状态。

严格支配只在同目标、作用范围、重要风险可比时使用；经验未调查的独立方案不能永久删除。短名单保留差异化费用／挑战／步骤／目标／不确定性；被折叠项可恢复，未覆盖时说明而非万能分数。最终选择由 Agent 输出首选与至多两个备选及理由／引用。

### D7. 自由对话与有限单 Agent

InterpretationDraft 允许不完整目标；按动作区分合约，只有执行对应查询／写入时验证必要参数。闲聊直接响应零业务读取；事实问题读取资料；探索读取关系；复合问题组合工具。无能力的问题正常说明边界而非抛 Schema 错误。当前回合最多问一个最关键问题，后续回合允许继续补齐，不再一次追问后强制重开。

中文别名通过可检索目录规范化，不截取前300节点。新会籍保存及已存会籍修改必须唯一识别并确认；临时假设不覆盖正式会籍。“确认”绑定具体 pending_action_id／工作区版本，过期或重复点击不产生重复写入。

初始保留每 HTTP 回合至多三次模型调用（修复也计入）：理解 → 程序查询 → 比较／选取需展开对象 → 程序批量资料／许可经验 → 最终答复。第二次信息充分可结束；第三次仍不足则保留工作区、给可用事实与续接，不硬凑推荐。不是固定必经链，闲聊、资料直问、澄清可更短。

HTTP/timeout/invalid_json/schema_error/invalid_action/tool_error 分别记录；可恢复格式错误最多修复一次，工具权限和事实错误不能通过宽松校验修掉。预算／网络失败保留输入和已有资料，提供真实降级；available 不等于 Provider 对象存在，区分配置、最近可用性和本次状态。

### D8. 临时工作区与业务任务分离

工作区默认24小时固定到期、可配置；UI 显示过期与重开。保存短期消息／回答呈现记录所需内容、结构化目标、未确认假设、焦点、最近路线顺序、证据／版本引用、pending actions 和预算。它可落 PostgreSQL 以支持刷新／重启；不成为无限延长的长期聊天记忆，也不保存思维过程。

长期用户记忆仅 StatusHolding。WaitGoal 是明确确认的一个可结束任务，字段不是日后默认偏好。工作区只存必要快照和引用，避免完整图／候选／HTML多次嵌套；授权范围内临时经验同TTL清理。

推荐完成不等于工作区不可继续。“第二条”“它”“改为免费”可绑定前一展示对象；换话题更新焦点并移除无关上下文。图／卡片点击可更新浏览焦点，不伪造用户消息或产生模型调用。上下文歧义时问清楚，不将最后浏览对象无条件替代明确文字。

旧回答不被新事实静默重写；新回合产生新展示并说明条件变化。事实版本改变时重新校验所选项，提示刷新；短 ID 不跨快照重新指向不同路线。

### D9. 简报与关系图作为共同知识的视图

简报重做为当前活动卡和实质变化简报。当前卡说明机会／目标／费用／主要限制；更新简报说明发生了什么和影响，重复文章合并来源而不是重复活动。事实数字／状态由服务端填充，AI 组织重点；OTHER 继续可浏览但不入图。与用户会籍的关联由程序计算，不为每用户生成独立简报真值。

匹配图初始显示已有会籍、相关直接机会和分组展开；既可树状布局，也可纵向步骤呈现。每个会籍可只画一次，但多种到达路线可展开比较；不能用最短路径投影删除有价值选项。防环和共享子图仍确定性，搜索截断明确。无来源资格的公开挑战独立机会呈现，不创造虚拟会籍根。

推荐图只呈现首选／差异化备选及必要中间节点，共同步骤可合并，费用／挑战／未知标记来自同一方案版本。图说明怎么走，对比说明为什么选，窄屏转换为步骤卡。

### D10. 结果呈现与点击边界

同一对话响应支持 text、activity_card、route_graph、route_comparison、evidence_answer、experience_summary、confirmation 等受控内容块，可组合不必全出现。模型返回对象ID／理由／事实引用；服务端验证后生成图边、价格、入口和布局数据。简单问题先直接答案；长文不塞 h2，不把所有返回都变成纯文本。

每张活动卡／路线卡、每个会籍节点只有一个主要浏览入口：整体点击 → 当前页面统一详情面板（窄屏抽屉／详情页保持返回位置）。活动卡定位活动；路线卡定位步骤；节点有多个方案时在该面板列相关方案，不随意跳某一个。费用／状态／限制标签与连线默认不独立可点，不堆链接栏。

详情先组织概述、适用价格、条件、期限；简报融入概述，FAQ/Terms 证据和历史按需展开，活动深链接／原始来源／申请入口集中放在详情。浏览、展开、返回均零模型调用；没有隐式启用联网调研。

下一步建议放在整条回答末尾，默认至多3个最相关可选短句。点击“比较两条”“看看申请经验”发送可见自然语言消息和对象上下文，走正常 Agent 回合；自由输入始终可用。确认卡明确显示将保存的内容或条件前后差异；确认本身是受保护业务操作，不伪装成普通浏览或无上下文按钮。

“本次依据”折叠显示读取对象／数据时间／筛选原因／覆盖／调查状态和错误，展示实际操作摘要，不展示思维链、不伪造实时进度。不新增 SSE/异步 Run 平台作为必需项；受限同步回合先交付，若实测延迟不满足再单独评估。

### D11. StatusMatcher 是临时经验观察

触发：上下文已定位活动／方案／申请步骤，用户请求／接受经验调查且服务端内容使用授权可用。用户“哪个更稳”“查第二条”可表达调查意图；不要求先完成推荐或保存会籍。无可定位对象先定位，不全网发现新活动。

读取：规范项目定位公司列表 → 筛少量相关报告引用 → 读取详情 → 解析来源／目标项目与等级、提交日期与实际申请日期、页面标签、叙述支持的结果和情境 → 去重／可比性判断 → 步骤聚合。搜索仅可在许可范围内定位 StatusMatcher 报告，搜索摘要不能作为样本证据或绕开授权；一期不要求通用搜索引擎。

直接可比／部分可比／不可比分开，最近12个月优先，不足可扩至24个月并标明，更早为历史背景；日期缺失不能混入近期样本。同一期次、方向、等级、申请方式、地区／会籍取得方式等关键情境已知不符时排除或降级，不因名称相似认定同活动。页面 Match 与文字挑战矛盾时保留原标签与核对结果，不强算直接成功。OTHER／无法判断不进有效结果分母。

报告观察包含 report_ref/url、submitted_at/application_at、from/to、reported_label、normalized_outcome、comparability/reasons、与当前问题相关的最小要点。聚合包含 step_ref、activity_version、研究条件、查询时间、窗口／覆盖、分类计数、限制。模式必须版本化；短引用映射由服务端维护。

原HTML默认仅处理期内，结构化报告最小信息／聚合／引用按授权在工作区临时保留，随TTL清除；不新增长期经验表到官方知识层。临时保存并不豁免内容使用授权；关闭时返回DISABLED，失败UNAVAILABLE，已查但不足INSUFFICIENT，未请求NOT_REQUESTED。

共用步骤本工作区只调研一次，缓存键包含实际方向／等级／方案与相关条件。用户补充“会籍也是匹配来的”时重新判断样本可比性；事实版本变化或明确刷新时重新核对。部分成功部分失败分别保留，不丢整个调研。访问采用域名白名单、每跳校验、响应／报告数量／请求总数／总截止时间预算；分页有上限、可披露partial，不再只有每请求12秒超时。

初始每次最多3条聚焦路线；建议请求总数12、每公司列表最多2页、详情最多8份、单响应1MB、全轮4MB、网络总截止20秒作为可配置实验起点，超限停止并保留不足。多步覆盖不够时不提高总信号；不按整条路线池化、不相乘观察比例。

经验只影响原本满足已确认条件的路线比较。案例与官方不同可触发同一活动资料工具核对，不能直接修改规则／关闭活动。拒绝原因等追问复用已查结果，必要时定向补查；当前未查的新候选不能被悄悄丢弃或视为更差。

呈现固定采用用户认可版本：路线卡仅一句经验状态；整体点击进入原有详情中的“申请经验”，展示样本范围、分布、主要观察和少量引用。不新增报告卡片瀑布、单独点击标签或一排经验入口。继续查／比较是独立下一步消息。

### D12. 无解、调整和等待

有单条件近似候选时只主动提一次有依据调整，显示前后与新增候选；未确认不应用，拒绝后不继续降低要求。没有任何近似候选也允许在完成真实无解检查后明确提供等待，不再要求先产生不存在的调整。

只有确认的条件和显式等待意图才能创建一个任务。资料未知／搜索partial不能声称全库无解；如用户在已告知范围后选择等待，只保存可执行、已确认条件，并区分“当前未找到”与“证明无方案”。

每日发布后确定性检查，无新匹配不调用模型、不通知。首次命中生成一次结果后默认停止搜索更优路线，除非用户明确保留等待；失败不推进成功去重。读取状态不自动消费结果，前端实际展示后确认seen，重复确认幂等。去重按任务／命中版本或候选语义引用，不因列表顺序或整组签名变化重复通知旧命中。

### D13. API、模块和测试边界

保留同仓部署和现有启动入口；新增／调整契约时使用显式 schema_version，旧 `/v1` 消费者通过兼容适配或有说明的新版本迁移，不静默改字段含义。对话提交、工作区读取、确定性详情展开、待展示确认分别有清晰契约；工具内部方法不要求全暴露 HTTP。

建议模块知识模型／发布、来源片段／证据、活动读取、关系计算／评估、Agent状态／上下文、结果组装／页面、经验适配、等待。边界体现职责而不是强制拆成许多包；先复用原有解析器和 Provider。当前未跟踪 frontend 不视为已完成实现，也不删除或自动纳入新技术路线。

评测按 [决策追踪](decision-traceability.md) 与12份spec进行：迁移审计、确定性合约、状态机、Mock工具、真实PostgreSQL、固定中文真实模型、浏览器交互、授权网络分层。上下文方案比较完整旧输入、全候选精简卡、覆盖短名单＋展开、同字段Markdown；正确答案由人工核对事实，不把旧程序输出当金标。初始30–50任务、关键样例多次复跑、调参与保留集分离，记录召回／硬条件错误／证据／未知／token／调用次数／P50/P95。数值错误在验收样例中零容忍，不先承诺压缩率。

## Risks / Trade-offs

- [映射与方案历史关联缺失] → 回填保留来源与UNKNOWN，按真实资料校对，不通过最低价或字符串相似强行关联。
- [规范化或活动去重误合并] → 保留旧ID映射、活动期次与来源片段，不确定项进入审核，不破坏原始记录。
- [资料抽取丢脚注／否定] → 章节表格结构、证据定位和反例验收，正文仍可回查。
- [渐进披露漏最佳选项] → 分开搜索召回和呈现覆盖，保留差异候选及展开入口，不宣称全局最优。
- [详情多次调用延迟] → 批量读取、请求内缓存、最多三次模型调用、完整回合预算和可续接降级。
- [文案与结构事实不一致] → 关键数值由服务端呈现、引用校验加真实模型评测；引用存在不代表自然语言语义已获证明。
- [授权或外部网站变化] → 调查默认关闭、版本化解析器、详情页契约测试、失败单独标注；不以搜索摘要代替授权。
- [三种产品版本不同步] → 明确知识版本、旧简报标旧／待更新、切换前重新验证、短事务发布。
- [新模型过度复杂] → 固定领域实体、有限条件类型、同一PostgreSQL，不引入通用规则平台；按阶段交付垂直链路。

## Migration Plan

1. 记录旧表／文档／事实／价格／映射／持有会籍／等待状态数量与签名，备份并演练恢复。现有原文、历史与未跟踪工作区文件不删除。
2. 增量增加模型和来源章节，建立可幂等 old_id→new_id 映射，先迁移目录／活动身份，再方案／价格／映射／证据；不确定的关联留待处理。
3. 回填 current 及所需历史版本，按事实证据复核；尤其撤销“没写费用所以免费”的旧推断，保留迁移原因。
4. Workflow写新模型并发布影子版本，旧消费者继续读旧数据；同一文档重复处理保持幂等。对照新旧差异，以事实而非旧输出验收。
5. 先交付同一活动的资料详情→路径→简报→Agent的垂直链路，再扩大到全部当前范围。完成数据正确性与展示回归后分阶段切换读取。
6. 切换使用明确配置及schema版本；旧工作区可提示重新开始，新holding和wait写入必须保留可回滚映射／重放记录，不能回滚时丢用户操作。
7. 回滚先切回已验证旧读路径，必要时暂停发布／写入并按备份与增量记录恢复；不得仅降级schema删除新用户数据。恢复演练通过后才退役旧重复事实模型。
8. 更新产品总方针、Agent方针、技术基线、运维与验收；规范归档／sync安排在代码验收完成后，不在本轮文档创建时标完成。

## Open Questions

核心设计已在上述详细设计确定，不留“实施者再设计一套”任务。实施期仅保留受证据约束的预算／布局调优、实际资料中无法证明的迁移关联和具体代码命名；有限条件类型已定义，未支持复杂规则保持 UNKNOWN/TEXT，不能任意扩建规则平台。StatusMatcher授权属于外部启用条件；未取得时完整交付关闭／降级行为和受控契约测试，不声称真实生产调查已验收。
