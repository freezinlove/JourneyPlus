## Context

基线为 rebuild-membership-knowledge-and-agent。2026-09-07 两工作区十轮真实测试中：费用查询 21.92 秒（模型 21.60 秒，工具 0.20 秒，两次引用错误）；路径 47.02 秒（模型 46.03 秒，工具 0.85 秒）；追问复述模板；公开入口连续三次询问偏好。相同约 4895 输入 tokens 的参数对照：默认 7.45/13.07 秒，关闭思考 1.77/1.94 秒，默认产生 457/875 思考 tokens。此为小样本，不推定全部历史耗时来自思考。

StatusMatcher Air Canada 公开页真实读取 1.85 秒并解析 16 候选，Royal Jordanian 所试地址 HTTP 500；并非全站不可达，也未证明详情链路已通。预览未注入 researcher，生产装配没有 verified company mappings。

## Goals / Non-Goals

Goals: 正文自然交流且有依据，连续任务不重复问可选项，展示指代可靠，渐进披露低负担，真实流式与可测性能，隔离预览真实研究可用。

Non-Goals: 重做官方知识模型、历史 LoyaltyLobby 回填、多活动拆分、正式发布、自动 Git 提交。不会通过取消事实校验、隐藏关键限制、伪造成功率或绕过网站访问限制实现体验。

## Decisions

### D1 对话表达与事实权限

保留后端金额、资格、费用合计、覆盖与版本的权威计算。模型选择当前问题相关事实和展示对象，并生成面向用户的简短自然语言。移除 selected_routes 一律替换正文及费用模板覆盖。优先复用 answer_grounding 的校验能力，校验对象来自本轮或明确复用的版本，不能让模型自造金额、由 UNKNOWN 推导 PASS、把费用部分合计说成总价。正式数值/结论用后端事实绑定；未通过校验的片段不发送，预算内允许一次定向修正，否则用面向当前问题的局部安全说明并标记原因，不撤回已展示有效内容。不要每轮额外调用一个审稿模型。

正文必须回答本轮问题；“资格缺口”按 constraint_checks 提炼哪些缺用户证件/地区等信息，哪些缺来源事实，不重复路径概述。解释未知时区分知识未核实与官方未发布。保存提议正文与内部 reason 分离，明确待确认操作。原文、版本、完整字段放详情；关键决策限制留正文。聊天不强制卡片；卡片与图由服务器从选择的引用生成。

### D2 临时任务与澄清

在现有 workspace JSON 增加小型 task_context（兼容缺省）：intent、target_scope、category_scope、hypothetical_empty。起点和硬条件只保留在已有 query，待确认内容复用 pending_action，结果引用复用 presentations/route_searches，不重复存一套状态。scope 对目标/类别显式区分 UNSPECIFIED / ANY / SELECTED；通过模型当轮解释更新，后端验证合法结构与已披露身份，不增加一次专门状态模型请求。短答结合历史和 unresolved_question 理解；仅对明确不限表达提供窄范围兜底，不扩成长正则意图引擎。

路由 query 为执行真相，task_context 为对话语义；不限目标清空旧 target/alliance/category 对应筛选，不清除无关预算与起点。所有变更按当前回合 revision 原子提交。假设为空起点必须 use_saved_holdings=false，不能回退用户存量。ASK 必须说明缺什么、是否阻塞，后端拒绝对 ANY 范围继续追问以及已查无命中后问可选偏好；查询无命中直接结合覆盖回复。当前请求缺关键词不取消既有任务。切换话题允许替换任务，无关闲聊不强制执行旧任务。真实会籍写入仍走原确认机制。

### D3 展示记录与引用

复用 presentations/focus/ReferenceMap，展示清单包含 presentation_id、顺序、对象类型、稳定引用、版本及短名称/关键指标。默认最多提供最近两次相关展示、每次首批对象摘要，相关当前对象优先；完整图、条款及历史展示仅服务端保存。点击卡/节点只浏览并更新 focus；下一步按钮发可见 message。指代优先顺序：明确 subject_refs > 明确序号/展示 > 当前 focus > 最近唯一对象；歧义时询问。用户说“第二条”按实际 presentation_index，不按数据库排序。

引用校验区分 activity/version/fact/route/step，不让模型组装版本路径；调查两次 selection_error 的真正来源，保持公开引用与完整资料索引一致。目录引用不能当事实证据，活动引用不能当路线。允许服务器解析已披露事实所属版本，不接受猜测引用。模型输入裁剪不得让合法引用变成不可解析。来源内容始终不可信。

### D4 查询预算与复用

按问题提供费用/有效期、路线摘要、所选比较或资格条件。无关全文不预注入；候选分页与模型预算独立，“全部”保持全范围检索但首批有序展示，显式 has_more/cursor/coverage。缓存键包括规范参数、起点、知识版本、有效时间，工作区临时复用，范围/版本变化失效；同轮相同读取去重，独立请求批量处理。依赖查询保持顺序。

近期对话取必要窗口，task_context 摘要替代无限历史增长；材料按需展开。报告每轮全部请求总 tokens，不能只看某次缩小。基础 prompt/schema 精简需要契约回归，不先引入多层路由模型。默认三次模型预算不扩大，常见事实目标两次以内。

### D5 参数与观测

Provider 提供可选 thinking 策略，Agent 常规调用显式 false，避免改变 AIWorkflow 的默认推理行为；配置/metadata 标明实际参数。记录 prompt/completion/total、reasoning_tokens、cached_tokens、响应模型、HTTP 耗时及流式首事件/首正文时间。禁记 API key/思考原文。超时使用剩余预算与 IO 上限较小者，记录实际值而非把剩余回合时间误标为 IO 超时。不以提高超时当优化。复杂请求思考策略须后续实测，不默认新增分类调用。

### D6 流式协议与恢复

保留同步 messages 接口兼容；新增本轮创建/订阅事件链路，复用 client_message_id、revision、active_turn/lease 做幂等。采用可恢复 SSE：事件通过 delivery run URL 确定流身份，含单调 seq、type、payload；accepted.payload 关联实际 turn_id。类型 accepted、phase、text_delta、block、completed、failed；phase 仅真实阶段，等待模型时明确整理中。completed 引用已持久化最终工作区；failed 标记不完整且保留已发送内容。客户端通过最后 seq 恢复，不创建新 turn；刷新恢复 active turn。工作者/订阅解耦，断线不重复写入。

事件保留范围与 workspace TTL 一致；使用 agent_delivery_runs（workspace FK、唯一 workspace+client_message_id）和 agent_delivery_events（run FK、唯一 run+seq）；run 在模型工作开始前创建，因此 accepted 再绑定 turn，只在隔离库迁移。清理 workspace 时级联清理事件。进程重启通过租约判定中断，不承诺未完成生成自动续算，允许明确重试。读消息不能等工作者持有事务；模型及网络始终在事务外。

Provider SSE 增量读取；结构化动作仅在完整合法后执行，不展示 JSON。回答阶段按句/短段暂存并校验后发送 text_delta，不把整轮最终正文一次性伪装成流式。卡片图完整校验后发送 block。流式生成/验证共享 D1 事实集合，不能在 JSON 还不确定属于 ANSWER 时泄漏内容。必要时分离工具决策与答案输出协议，但不使常见三次预算变成固定四次；完整实现后才勾选流式。

前端消费事件递增追加文本，按事件 seq 去重，同一展示块只保留一份；不在每个 token 重画全页。发送反馈 <1 秒，显示真实阶段/耗时，无思考原文或虚假百分比。确认写入继续原独立幂等事务，流事件无写权限。

### D7 StatusMatcher 真实接入

接入现有 StepResearchService 而非旧 route researcher。装配显式 reviewed company 映射（规范 program ID → verified_url/verified_at/验证来源），页面别名与报告身份注册表从可维护目录构建；未知身份不猜测匹配。正常 CLI 与预览使用同一构造入口，预览显式启用，正式默认 false。

核实真实公司页面、列表与详情 DOM，修正解析器并保存去隐私的结构样例回归。按源/目标项目、等级、日期与匹配方式区分精确/部分可比；保留案例 URL/时间/限制。目标步骤与卡片关联；同一工作区相同调查缓存复用并受 TTL 限制。官方条件冲突只触发核对，经验不写官方事实库。

沿用域名/路径许可与总请求/字节/20 秒预算，禁止绕过挑战、认证；500/403/超时是 unavailable，不当无案例。结果明确 mapping_unverified、http_error、parse_error、no_reports、insufficient_comparable。真实核实后 Royal Jordanian 的有效公司页是 /company/royal-jordanian-airlines；旧 /company/royal-jordanian 的500仍记入首次失败，不代表全站不可用。至少一个项目真实列表→详情→可比筛选→Agent→卡片链路成功，至少两个项目覆盖及明确失败行为真实验收，不能把 mocked 网络当 live。

## Risks / Trade-offs

- 关闭思考可能影响选择质量 → 相同原始连续对话加新变体回归，真实模型重复测，不凭格式合法判正确。
- 校验后流式有缓冲延迟 → 分段验证，分别量首次反馈/正文/总时长，保留事实正确性。
- 网站变动/失败 → 展示真实范围与原因，可用项目单列，不宣称全站保障。
- 新状态占上下文 → bounded 展示摘要与任务状态、总输入对照、无额外状态模型调用。

## Migration Plan

先补观测与参数，再修任务状态和引用，随后自然回答/展示，最后流式与真实研究装配。每步测试并记录 evidence；全套连续真实验收后给隔离预览。可通过配置回退同步接口/关闭研究；保留工作区及确认日志。正式发布另行处理，不改既有 12.6/12.8 完成状态。

## Open Questions

无需要用户先决策的设计阻塞。外站可用页面、引用错误成因与实际延迟是实施验证项；出现真实不可用需记录范围，不伪造通过。

## Acceptance details

完整脚本、性能目标、冷/热缓存及阶段门槛见 acceptance.md。原始失败记录必须保留，复测不得覆盖第一次结果。对明确不限的公开机会短答，服务端可直接复用/执行已建立的规范查询，避免再让模型定位根本不需要的目录 ID；有显式目标的第一轮仍由模型定位。此为临时任务执行，不是长期记忆写入。


## 最终实施细化

- 普通问候直接以单次无思考请求流式回应；其余无业务读取的闲聊在动作确定后，以剩余调用预算输出正文，不再注入前一个业务话题。实际参数、正文首输出和整轮调用均计入指标。
- 路径/活动事实取得后，服务器先生成绑定版本的事实简要和卡图，再用剩余预算直接流式生成自然正文，替代原本最后一次大型动作 Schema 回答。常规事实共两次、常规路径三次；不再叠加审稿模型。原模板保留为内部事实基线和异常兜底，不无条件覆盖正常流式正文。
- 资格追问单独提供选定步骤 constraint_checks，移除重复价格和无关路径。泛问证件时只概述允许的签发国家和证件类型，完整国家名单留详情；明确问名单再展开。点击后“这个要什么证件”直接读取点击步骤所属展示的路线，避免模型重新选入上一张图的其他目标。明确比较/换目标不触发此窄范围解析。
- 句子发布前检查数值、币种金额配对、日期数字标准化、未知挑战/资格/总费用、证件签发地与居住地混淆及来源引用。未通过的片段不发布，保留诊断标记；全部未通过则使用已绑定事实简要，不展示错误原句。这是可测试的保守规则，不能宣称可穷尽验证一切自然语言语义。
- 单等级费用问答的活动卡按资料中的精确等级名筛选费用预览；完整活动详情不改动，不能把其他等级的低价显示成当前等级费用。展示上下文补充已有 cost/eligibility 短摘要，不复制完整图或条款。
- Provider 识别提前断流和非 stop 终止（如 length），保留已送正文并记录未完成；流式持续读取也受整轮剩余时间约束。请求失败仍记录实际 HTTP 时长。闲聊和事实流都不输出 reasoning_content。
- 异步工作者独立于 SSE 连接；刷新重放已有事件，断线带 after 游标续订。110秒无事件的运行标为失败，已失败/过期的排队任务不再执行。删除工作区显式清理两张事件表，同时保留 PostgreSQL 外键级联；应用关闭时停止接收后台任务。
- reviewed mappings 覆盖 Air Canada、Vietnam Airlines 和 Royal Jordanian 的真实公司页。报告按实际目标等级解析，修复目录重复身份导致的误判；列表/报告原始 HTML 仅单次研究运行内有界复用，工作区保存归一化报告、来源和可比限制。跨轮复查覆盖指标为实际新增 HTTP 数；命中缓存明确标记 cache_hit。
- 真实越航回放暴露 oversized material → NEEDS_INSPECTION 丢目录的死循环：降级包现在保留预算内 catalog 身份，事实仍按完整对象延后展开；裁剪 expansion 时不会把未披露候选偷偷跨页跳过。此修复有真实原失败资料包及预算契约回归。
- “这条路径还需要核实什么”在最近展示只有一条路径时直接 INSPECT；明确 subject_refs 的资格追问同理。多条路径仍不猜指代。资格说明只传 topic/result/reason/必要 actual 和待核对数量，减少重复 expected 原文；详细规则仍保留在步骤卡。
- 经验正文只保留本次调查发现和限制，过滤无关的用户资料追问。每条案例详情同时给出原始来源/目标、提交日期、申请日期（未知就写未知）及 EXACT/PARTIAL/INCOMPARABLE，后者不计入可比统计。
- 若研究目标尚未定位，明确“还未读取报告，需要定位步骤”，不能包装成“没有案例”；无可比案例只由实际报告筛选得出。

- 流式等待显示本地实际已用秒数；完成后在“回答依据”折叠区展示模型HTTP累计时间和资料读取累计时间。普通复查强制复用仍有效的工作区研究缓存，明确最新/重新联网/不要缓存时才刷新，不由模型自行绕过缓存。前端入口与共享模块带版本参数，确保旧页面刷新后加载本次变更。

## 已有会籍的全目标探索修正

目录身份定位增加 CATALOG 视图，与活动是否唯一、是否有已发布资料无关；有界返回真实项目及等级引用，不注入活动正文。不硬编码品牌或中文名特例：现有模型从用户语言提取官方项目检索词，语言转换只作候选检索，最终 ID 必须来自目录；已入库别名由通用目录查询处理。目录无命中与活动无命中明确区分，真正等级歧义才澄清。不得创建会籍或推断等级等价。ROUTES 的不限目标与 PUBLIC_OPPORTUNITIES 同样约束执行，但保留明确起点，不改成无会籍查询。已建立查询后的不限续问直接复用起点；尚未定位起点时通过历史继续定位，不能默认用其他已保存会籍。禁止把可选目标或起点活动作为全目标路径查询的必填项，真正目录身份不明仍可澄清。目录缺失的兜底明确身份缺口而不是要求选择活动。

### 通用身份检索与执行记录

- `CATALOG` 的 selector 支持原始项目名及最多 3 个确定的官方名、英文名或缩写（alternate_names），同一读取内查询并按真实 ID 去重，总返回至多 20 个项目；未知翻译不生成身份，空 selector 不枚举全目录。注册的中文别名与其他语言别名通过同一查询机制处理，代码不含品牌对照表。
- CATALOG_ONLY 与 CATALOG_NOT_FOUND 区分真实身份是否定位；包中携带本次搜索词。每次决策都能看到本轮已执行的工具、参数和结果状态，避免失忆式重复检索；同轮相同无命中目录请求缓存，服务失败不当作无命中缓存。
- 明确不限的已有起点查询复用实际查询中的 starting_tier_ids，不合并其他已保存会籍；换起点时重新定位。无关“所有歌曲”等表达不能触发业务预读，真正起点身份澄清继续允许。
- 全目标探索按页展示至多 8 条已披露路径，正文区分候选总数与当前页数量，费用和步骤放图卡，其余候选沿既有完整分页入口继续浏览。资料覆盖不完整和资格未核实仍明示，不把候选路径说成已获申请资格。

### 起点和目标的边界

- 目录检索词若只是现存等级名称（例如 Gold）而非项目精确名称，不得通过项目名子串匹配到其他计划。返回 `missing_input=SOURCE_PROGRAM`；当前起点未建立时直接说明需要所属项目，不能让防追问规则吞掉这一必需澄清。已给出项目但目录无命中，与缺少项目本身分别处理。
- TaskUpdate.source_changed 只在本轮明确更换、增加、清空起点或合并已存会籍时生效。已建立查询且未更换起点时，路线执行保留 starting_tier_ids；把新目标等级误填进起点数组的请求拒绝执行，并返回明确修正指令，不能输出从错误会籍出发的图。
- 用户仅说明持有某会籍，不得推断会籍通过正常积累取得，source_acquisition 保持 UNKNOWN；明确取卡方式后才设置对应值。
- 目录阶段显示“正在确认会籍项目与等级”，回答依据注明目录不含活动规则，缓存命中如实标记；正规活动查询继续使用原资料视图。

### 完成条件与协议容错

- 是否完成当前路径任务由临时任务状态和真实工具执行共同判定，不只匹配最新一句中的“路径”字样。带旧错误历史的“所有都要”仍有路径完成条件；把追问目标放在 ANSWER.text 中也不能绕过必须执行的路线读取。
- 仅在 Agent 工作区协议内，将具有空列表默认值的可选列表 null 视为省略（例如 preferences、route_refs）；必填 requests、非列表值、非法引用仍验证失败。不修改 workflow 的事实解析规则，不猜动作或制造身份。
- “展开其他路径”从当前展示实际覆盖的连续前缀之后开始，避免第一页已经展示 8 条却再次原样出现。非连续推荐子集不能按最大序号跳页，确保中间未披露候选不丢失；旧图的浏览不继承当前对话的来源范围叙述。

- 独立关系探索表单提交的是用户明确选择，必须清除旧对话的范围约束再按表单完整查询，不能让聊天中的不限状态清空表单目标，也不能拒绝表单明确更换起点。此入口不调用模型。

### 指定目标下补齐起点（2026-09-07 用户实测回归）

“所有路径”是结果覆盖要求，不自动等价于“所有目标”。仅无附加内容的明确不限短答可走已有查询预读；含项目或其他条件的句子由同一动作决策解释，不增加分类请求。TaskUpdate 的未提供范围在同任务内继承，SELECTED 可保留一个有界原话 target_text，表示尚未解析的目标条件而非目录身份；目录 ID 仍只来自真实披露。unresolved_question 随上下文传递，澄清只补缺失条件。改变或清除已选目标必须显式 target_changed；默认值不能取消它。

执行时真实提供的目标 ID 优先于陈旧 ANY 标记，不能被无条件清空；目标未改变且请求漏填时继承 query 中的目标。SELECTED 尚未定位时拒绝全目标执行，要求定位目标后查询。目标变化不得沿用原目标等级。必需起点澄清只问所属项目，不插入目标不限建议。同一批目录读取全部完成后再返回澄清，不因起点缺失跳过目标读取。验收检查数据库实际 query 和全部返回终点，允许真实无结果，不能用其他目标填充。

补充执行约束：
- 已选目标/类别下，“所有都要”指当前范围内的全部结果，不能自行扩大范围。仅完整且无其他限定的“目标不限”重置语句可直接复用既有起点执行；附带“所有航司/酒店”时保留对应类别。其他复杂语句继续在原动作模型内解释。明确取消目标与工具仍带旧目标冲突时拒绝执行，不能让旧 ID 覆盖本次取消。
- AskPayload.field 明确 SOURCE_PROGRAM / SOURCE_TIER / TARGET_IDENTITY / OTHER；短答结合该字段解释。用户补充身份后，再次询问同一身份前必须实际尝试目录查询；目录仍有真实歧义时可澄清具体等级，不强行猜测。
- source_identity_pending 只在工作区临时保存。已说明但未定位的起点不能回退已保存会籍或空起点；source_count 限制单个会籍不能展开成多个候选身份。用户明确多张会籍才扩大数量。
- 原始目录词仅为等级时，其 alternate_names 不能引入一个此前未知的项目（例如 Gold → 某品牌 Gold）；直接返回缺所属项目。明确项目后的同义名检索仍可用。
- 无结果简要绑定实际执行 query 的目录名称，明确起点和目标；无命中不补上其他目标的图，不声称现实中不存在该路径。正式会籍和知识库不写入；没有新迁移、分类调用或第四次模型请求。

### 2026-09-08 省略句切换与执行一致性（最终实施设计）

之前的“保留条件”规则未形成完整的修改协议：模型可以识别 source_changed，却继续提交旧起点；后续决策还能把新范围改回旧范围。只加强提示和清空旧 ID 的第一次修复未通过真实回放，因此以本节取代上文关于此类续问仍完全由原动作决策解释的描述。

1. HTTP 工作区启用 `plan_route_turns`。路径任务的第一轮决策改为一个小型 RouteTurnPlan，输入仅包含最新原话、有限历史、上次查询和临时任务。明确输出 source_action=KEEP/REPLACE、target_action=KEEP/SELECT/ANY、起点/目标检索身份及合并后的短请求。该调用替代原先第一次大型工具决策，不叠加第四次常规模型请求；低层 WorkspaceService 的兼容开关默认关闭，HTTP 产品入口显式开启。
2. 保留条件只适用于用户未修改的项目。A→B 之后“C 金呢”更新起点且保留 B；“把 A 所有匹配路径给我”恢复此前明确的 A 等级并取消目标；“所有都要”保留当前目标。“只看 C”只改目标。新起点使旧 starting_tier_ids 立即失效，不读取已保存会籍补缺；新目标清除旧目标等级。计划仅在本轮有效，后续 TaskUpdate 不得覆盖它，下一轮重新解释。
3. 身份查找有界执行：每个新身份携带原词及必填的规范检索词列表（1–3 个确定的英文品牌、正式名或缩写；未知则重复原词，不编造身份），在一次 CATALOG 读取内合并去重。额外同义词仅是检索提示，先去重并裁至 3 个，不因第 4 个检索提示消耗一轮格式修复；非法字段类型与身份引用仍严格验证。对中文原词未命中不能直接断言无该会籍。裸等级仍返回缺少项目，不能通过翻译猜项目。目标已明确但还没有 ID 时，即使 KEEP 也补做该目标的目录读取；独立目标读取不因起点缺失而跳过。待解析起点/目标的原词、规范检索词和等级随临时任务保留，不能下一轮只剩一个无法检索的中文展示名。混合“项目 等级”检索未命中时，至多尝试 4 个词边界，仅当后缀匹配候选项目的真实等级名或已登记等级别名才接受拆分，不任意删除未知后缀。
4. 第二次请求只使用 RouteIdentitySelection，从上述目录和现有 query 选择已披露引用，不再让模型自由决定重复读取目录或改查询范围。后端按固定计划合并 ID 并直接执行一次路线读取：新起点必须属于本轮读出的起点项目；目标必须属于新目标项目；KEEP 字段完全由后端保留，忽略模型对未修改字段的多余输出，不要求模型复写旧 ID。选择单个起点不能扩成多个。身份确有歧义时可以仅澄清该缺口。
5. CATALOG 的等级仅在有记录时附带至多 8 条名称别名与来源。请求等级与正式名/已登记别名精确匹配时，执行端校验所选等级，不允许模型在同一项目内选错档位。品牌对应关系属于目录数据，不写入对话逻辑分支；别名不能推导申请资格或联盟等级等价。测试库中按官方卡面资料登记的汉莎 Gold/Silver/Black 对应关系另见 verification.md，正式库不写入。
6. 第三次请求基于实际执行结果输出自然语言并流式交付，图卡来自同一真实结果。正常路径仍最多三次模型调用，标准链路不依赖用户第二次纠正。费用、条款、闲聊、经验调查等以 OTHER 交回原工具流程，使用剩余调用预算；这一分支会占用一次小型判断，应单独测试其调用预算和返回结果，不宣称所有任务均减少调用。
7. 验收同时检查第一句切换后的实际 query UUID、具体等级、图中全部起终点、无结果范围和模型调用记录，不能只检查文字提及目标，也不能把第二句“我是说”的纠正当作第一次通过。查询历史及单轮计划属于临时工作区，不新增长期用户记忆。
