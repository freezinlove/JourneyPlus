## Why

JourneyPlus 已经具备证据化会籍机会、申请路线、生命周期和统一会籍图，但仍缺少把这些能力交付给单个用户的最小产品闭环。当前机会范围也比最终产品更宽，路线费用仍以自由文本为主，无法稳定回答“我持有这些会籍，沿完整网络可以获得什么、每条地区路线对应目标等级要付多少钱”。

## What Changes

- 将用户侧个性化匹配范围收敛为 `STATUS_MATCH | OTHER`；直接匹配、挑战和 Fast Track 统一属于广义 `STATUS_MATCH`，`OTHER` 只退出个性化匹配结果，不改变现有简报生成、保存和展示。
- 为申请路线补充按目标等级表达的结构化原币价格和可用性，同时保留原始费用文本、地区条款和证据。
- 增加单用户本地 `StatusHolding`，从统一会籍图的规范化项目和等级中选择已有会籍，不建设账号或 TravelerProfile。
- 从所有已有会籍根节点构造不设业务深度上限的可达子图；保留闭环边并停止对应递归，保留多条到达边并用交叉引用避免重复展开。
- 匹配页面在完整可达响应上生成确定性最近路径树；每个会籍只绘制一次，隐藏闭环、交叉引用占位和非最近到达边。
- 默认按中国地区生成只读提醒；地区不参与过滤、阻止、排序、最低价替换或路径可达性判断。
- 增加产品 API，以及“我的会籍、个性化匹配图、机会简报、机会详情”四个轻量页面；简报页复用并展示全部现有简报。
- 将买分来源退出默认页面和每日自动调度，但保留现有代码、数据、命令和历史记录。

## Capabilities

### New Capabilities

- `status-match-opportunity-shaping`: 约束二值机会范围、路线目标等级价格、默认中国地区提醒以及现有简报不受机会类型过滤的行为。
- `personalized-membership-reachability`: 约束单用户已有会籍、无固定业务深度的可达子图、闭环和交叉引用以及机会事实组装。
- `personalized-status-match-product`: 约束产品 API 和四个用户页面的读取、导航与交互行为。

### Modified Capabilities

- 无。当前仓库尚未归档主规格，本变更以新增能力描述对既有实现的收敛和组合。

## Impact

- 数据与迁移：Pydantic 事实契约、SQLAlchemy 模型、Alembic 迁移、当前有效数据兼容与回填。
- AI 链路：只扩展现有普通文章和 StatusMatch 事实输出，不新增模型阶段；用户查询保持零 AI 调用。
- 图与读取：复用 membership contributions/provenance，新增个性化可达子图与机会详情组装。
- API 与界面：在现有 FastAPI 应用内增加稳定的 `/v1` JSON API、服务端页面和少量同源静态资源，不引入独立前端构建栈。
- 自动化：AwardWallet 买分来源停止自动选择，现有买分专属能力保留手工入口。
- 测试与文档：新增迁移、契约、提取、遍历、API、页面和真实代表性价格案例验证；产品范围以 `doc/personalized-status-match-product-direction.md` 为总方针。
