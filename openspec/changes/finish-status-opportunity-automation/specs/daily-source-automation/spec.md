## ADDED Requirements

### Requirement: 七个正式来源最终统一每天运行
在金标、时效、真实 Gmail 联调和受控初始化阶段门通过后，系统 MUST 对 FFB会籍Feed、FFB会籍汇总页、AwardWallet、StatusMatch/GetStatus Gmail、LoyaltyLobby、Frequent Miler 和很旅行七个来源统一配置一天采集周期并启用自动调度。StatusMatcher MUST 不参与任何自动周期。

#### Scenario: 自动调度正式启用
- **WHEN** 金标基线、必要调整、生命周期实现、真实联调和逐批初始化审核均完成
- **THEN** 七个正式来源的采集周期均为一天且自动标志启用

#### Scenario: 阶段门尚未通过
- **WHEN** 金标、生命周期、真实联调或逐批初始化验收尚未完成
- **THEN** 自动调度保持关闭，即使单轮命令和一天采集周期已经存在

### Requirement: 单轮自动化必须按北京时间自然日幂等且互斥
系统 MUST 提供可由外部定时任务调用的单轮命令，使用数据库租约防止并发执行，并以来源和 `Asia/Shanghai` 自然日建立幂等键。同一北京时间日期重复触发 MUST 复用已成功来源运行，且不得重复产生采集、文档、分析、事件或简报；失败来源 MAY 在当天安全重试。

#### Scenario: 同一北京时间日期重复调用
- **WHEN** 单轮命令在同一北京时间日期内被重复触发
- **THEN** 已成功来源运行被复用，失败或未运行来源可重试，且不会重复处理同一材料

#### Scenario: 上一轮仍在运行
- **WHEN** 新调用发现有效的自动化租约
- **THEN** 新调用安全退出并记录跳过原因

### Requirement: 单轮自动化必须完成采集、处理和生命周期推进
一次自动化周期 MUST 顺序采集到期来源、处理本轮新增和既有待处理文档、推进事件生命周期并输出运行摘要。系统 MUST 为单轮来源条目、待处理文档和模型调用设置可配置上限。

#### Scenario: 来源发现新文章
- **WHEN** 一个到期来源产生新的文档版本
- **THEN** 同一周期在上限内完成分类、事件聚合、事实、简报和生命周期更新

#### Scenario: 待处理数量超过上限
- **WHEN** 本轮积压超过配置上限
- **THEN** 系统处理上限内项目、保留剩余积压并在运行摘要中报告

### Requirement: 来源故障必须隔离并可观察
一个来源的发现、获取、授权或解析失败 MUST 不阻塞其他来源。系统 MUST 保存每个来源的最后成功时间、最近失败、连续失败次数、新文档数量和待处理数量，并在周期摘要中报告分析失败与 `NEEDS_REVIEW` 数量。

#### Scenario: Gmail授权失效
- **WHEN** Gmail访问令牌不能刷新
- **THEN** 邮件来源记录失败，其他六个来源继续采集和处理

#### Scenario: 单个Feed结构失效
- **WHEN** 一个Feed无法发现或解析正文
- **THEN** 该来源本轮失败被记录，其他来源和生命周期推进继续执行

### Requirement: Gmail真实联调必须保护私人内容
系统 MUST 使用当前全部同时符合标签和专用别名条件的 StatusMatch 邮件，在本地 PostgreSQL 验证发现、获取、清洗、入库、重复采集幂等和完整分析链路；2026-08-23 验证时共有四封。真实邮件标题、正文和可识别内容 MUST NOT 写入仓库夹具、金标或运行报告。

#### Scenario: 第二次采集当前合规邮件
- **WHEN** 已完成首次入库后再次运行邮件来源
- **THEN** 系统按 Gmail message ID 复用已有来源条目，不创建重复文档、事件或简报

#### Scenario: 尚无GetStatus真实邮件
- **WHEN** 邮箱中只有StatusMatch邮件
- **THEN** 当前真实联调可以完成，GetStatus案例留待收到邮件后补充且不阻塞自动化上线

### Requirement: 外部调度前必须完成受控初始化和逐批原文审核
系统 MUST 在安装或启用外部每日定时任务前，全量处理 FFB 会籍汇总列表，并将其他公开来源中 `published_at` 位于北京时间 2026-07-15 至 2026-08-22 的文章按两个自然日一批从旧到新初始化。每批 MUST 使用独立运行身份，处理完成后 MUST 回读真实原文审核文档标签、活动数量、事件关系、事实证据、简报和生命周期；未显式通过当前批次前 MUST NOT 开始下一批。

#### Scenario: FFB 汇总列表初始化
- **WHEN** 开始正式业务库初始化
- **THEN** FFB 会籍汇总列表不应用日期过滤并全量处理，使用当前时效流水线生成业务事件、事实、简报和生命周期

#### Scenario: 两日窗口顺序推进
- **WHEN** FFB 汇总列表初始化已通过审核
- **THEN** 系统从7月15日至16日开始按两个北京时间自然日一个闭区间顺序处理，最后剩余的8月22日作为单日批次

#### Scenario: 当前批次发现错误或新边界
- **WHEN** 原文审核发现分类、聚合、事实、证据、简报、生命周期错误，来源正文异常或尚未约定的产品边界
- **THEN** 系统记录材料、结果、原因和建议选项并停止，不得采集或处理下一批，直到用户决策、修复和回归验证完成

#### Scenario: 用户批准从原始材料重建派生数据
- **WHEN** 初始化审核失败且用户明确批准清理旧结果重新生成
- **THEN** 系统先创建并验证 PostgreSQL 备份，只删除可从现有原始文档重建的分析、事件、事实、简报、任务和初始化状态，保留来源、SourceItem、DocumentVersion、CollectionRun、Gmail OAuth 与原始正文，然后使用新版本规则重新处理

### Requirement: 自动化观察通过后才能开始下一主题
系统 MUST 在完整测试和严格 OpenSpec 校验通过、七个来源各自真实采集成功、受控初始化逐批审核通过且自动单轮连续观察至少三个北京时间自然日没有重复业务数据或未隔离故障后，才把会籍主题标记为可维护并开始下一个主题。

#### Scenario: 观察期出现重复事件
- **WHEN** 自动运行观察期间发现同一材料重复创建事件或简报
- **THEN** 会籍主题不得完成，必须修复并重新开始观察

#### Scenario: 观察期无阻塞问题
- **WHEN** 完成门槛全部满足
- **THEN** 会籍主题进入维护状态，项目可以开始买分或转分主题
