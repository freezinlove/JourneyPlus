## ADDED Requirements

### Requirement: 七个正式来源最终统一每小时运行
在金标和时效阶段门通过后，系统 MUST 对 FFB会籍Feed、FFB会籍汇总页、AwardWallet、StatusMatch/GetStatus Gmail、LoyaltyLobby、Frequent Miler 和很旅行七个来源统一配置一小时采集周期并启用自动调度。StatusMatcher MUST 不参与任何自动周期。

#### Scenario: 自动调度正式启用
- **WHEN** 金标基线、必要调整、生命周期实现和真实联调均完成
- **THEN** 七个正式来源的采集周期均为一小时且自动标志启用

#### Scenario: 阶段门尚未通过
- **WHEN** 金标基线或生命周期验收尚未完成
- **THEN** 自动调度保持关闭，即使单轮命令已经存在

### Requirement: 单轮自动化必须幂等且互斥
系统 MUST 提供可由外部定时任务调用的单轮命令，使用数据库租约防止并发执行，并以来源和小时分桶建立幂等键。同一小时重复触发 MUST 不产生重复采集、文档、分析、事件或简报。

#### Scenario: 同一小时重复调用
- **WHEN** 单轮命令在同一小时内被重复触发
- **THEN** 已成功来源运行被复用，且不会重复处理同一材料

#### Scenario: 上一轮仍在运行
- **WHEN** 新调用发现有效的自动化租约
- **THEN** 新调用安全退出并记录跳过原因

### Requirement: 单轮自动化必须完成采集、处理和生命周期推进
一次自动化周期 MUST 顺序采集到期来源、处理本轮新增和既有待处理文档、推进事件生命周期并输出运行摘要。系统 MUST 为单轮来源条目、待处理文档和模型调用设置可配置上限。

#### Scenario: 来源发现新文章
- **WHEN** 一个到期来源产生新的文档版本
- **THEN** 同一周期在上限内完成分类、事件聚合、事实、简报和生命周期更新

#### Scenario: 待处理数量超过上限
- **WHEN** 本轮积压超过配置上限
- **THEN** 系统处理上限内项目、保留剩余积压并在运行摘要中报告

### Requirement: 来源故障必须隔离并可观察
一个来源的发现、获取、授权或解析失败 MUST 不阻塞其他来源。系统 MUST 保存每个来源的最后成功时间、最近失败、连续失败次数、新文档数量和待处理数量，并在周期摘要中报告分析失败与 `NEEDS_REVIEW` 数量。

#### Scenario: Gmail授权失效
- **WHEN** Gmail访问令牌不能刷新
- **THEN** 邮件来源记录失败，其他六个来源继续采集和处理

#### Scenario: 单个Feed结构失效
- **WHEN** 一个Feed无法发现或解析正文
- **THEN** 该来源本轮失败被记录，其他来源和生命周期推进继续执行

### Requirement: Gmail真实联调必须保护私人内容
系统 MUST 使用当前三封符合标签和专用别名条件的 StatusMatch 邮件，在本地 PostgreSQL 验证发现、获取、清洗、入库、重复采集幂等和完整分析链路。真实邮件标题、正文和可识别内容 MUST NOT 写入仓库夹具、金标或运行报告。

#### Scenario: 第二次采集三封现有邮件
- **WHEN** 已完成首次入库后再次运行邮件来源
- **THEN** 系统按 Gmail message ID 复用已有来源条目，不创建重复文档或事件

#### Scenario: 尚无GetStatus真实邮件
- **WHEN** 邮箱中只有StatusMatch邮件
- **THEN** 当前真实联调可以完成，GetStatus案例留待收到邮件后补充且不阻塞自动化上线

### Requirement: 自动化观察通过后才能开始下一主题
系统 MUST 在完整测试和严格 OpenSpec 校验通过、七个来源各自真实采集成功且自动单轮连续观察至少24小时没有重复业务数据或未隔离故障后，才把会籍主题标记为可维护并开始下一个主题。

#### Scenario: 观察期出现重复事件
- **WHEN** 自动运行观察期间发现同一材料重复创建事件或简报
- **THEN** 会籍主题不得完成，必须修复并重新开始观察

#### Scenario: 观察期无阻塞问题
- **WHEN** 完成门槛全部满足
- **THEN** 会籍主题进入维护状态，项目可以开始买分或转分主题
