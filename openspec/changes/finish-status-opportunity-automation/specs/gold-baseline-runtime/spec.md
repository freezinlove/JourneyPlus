## ADDED Requirements

### Requirement: 第一阶段必须先运行冻结金标
系统 MUST 在任何活动时效实现或自动调度启用之前，校验并运行 `status_opportunity_phase1_v1.json` 及其冻结清单。运行器 MUST 不修改金标正文、标签、事件键、案例版本或数据集版本。

#### Scenario: 冻结清单有效后开始推理
- **WHEN** 金标文件的 SHA-256、Schema、数据集版本、案例版本和样本数量均与冻结清单一致
- **THEN** 运行器使用当前模型配置和生产提示词处理65份规范正文

#### Scenario: 冻结文件发生变化
- **WHEN** 金标文件与冻结清单不一致
- **THEN** 运行器在任何收费模型调用前失败，且不自动重建或覆盖金标

### Requirement: 金标推理必须缓存并支持续跑
系统 MUST 按金标文件摘要、案例与文档键、模型配置版本、提示词版本和 Schema 版本缓存每份结构化输出。重复运行 MUST 复用匹配缓存，中断续跑 MUST 只请求尚无有效缓存的文档。

#### Scenario: 基线中途停止后继续
- **WHEN** 一次65份文档的运行在部分完成后中断
- **THEN** 下一次运行复用已完成结果并从缺失文档继续

#### Scenario: 提示词版本变化
- **WHEN** 当前提示词版本与缓存记录不同
- **THEN** 旧缓存保留用于比较，但新基线不得把旧输出当作当前结果

### Requirement: 报告必须覆盖分类和事件分组
金标报告 MUST 包含文档标签混淆矩阵、Precision、Recall、F1、文档内活动数量匹配、ID 无关的 pairwise 事件分组指标、结构化输出失败和逐文档错误。事件分组 MUST 比较活动提示是否属于同一预测事件，不得要求数据库 UUID 与人工 `event_key` 相同。

#### Scenario: 多来源报道同一活动
- **WHEN** 多份金标文档的活动归属使用同一人工 `event_key`
- **THEN** 报告判断对应预测活动是否被聚合到同一预测事件

#### Scenario: 一篇文章包含多个活动
- **WHEN** 一份金标文档包含多个不同 `event_key`
- **THEN** 报告单独检查预测活动数量和每个活动的跨文档分组

### Requirement: 第一阶段报告不得评测实效性
第一期金标运行和报告 MUST 不要求或评分申请开始时间、截止时间、生命周期或归档状态。系统 MUST 不为了加入这些字段而修改第一期冻结金标。

#### Scenario: 金标没有事实与时间标签
- **WHEN** 第一阶段金标的 `facts` 为空且没有生命周期标注
- **THEN** 分类和事件分组报告仍完整生成，时间类指标明确标记为不在本期范围

### Requirement: 金标结果构成时效开发阶段门
活动窗口、生命周期和自动调度任务 MUST NOT 在第一期基线报告保存、错误完成分类且阻塞性分类/聚合问题完成必要调整和回归验证前启用。

#### Scenario: 第一轮基线尚未完成
- **WHEN** 仓库中没有当前模型和提示词版本对应的完整第一期报告
- **THEN** 实效性迁移与自动调度保持未实施或关闭状态

#### Scenario: 基线发现系统性错误
- **WHEN** 报告显示某类材料被系统性误判、活动持续误拆或不同活动持续误合并
- **THEN** 团队先修改相应提示词或聚合逻辑并用同一冻结集比较候选结果，再进入实效性阶段
