## Why

会籍机会纵向流水线已经能够手工采集、分类、聚合、整理事实并生成简报，但第一期冻结金标尚未真正运行，来源仍未自动调度，事件也没有独立的活动时效状态。需要先用现有金标发现并修正分类与聚合问题，再在不扩大事件字段的前提下补齐活动窗口、生命周期和每日自动运行，并通过分批真实材料初始化审核，才能把会籍主题稳定交付并开始下一个主题。

## What Changes

- 建立第一期冻结金标的真实模型运行、缓存续跑、分类与事件分组报告；本期金标不评测活动时效，且金标基线和必要调整完成前不得开始时效实现。
- 将正式来源从八组收缩为七组，**BREAKING**：移除 StatusMatcher 注册、CLI 入口、生产适配能力和相关文档；保留 FFB 两组、AwardWallet、StatusMatch/GetStatus Gmail、LoyaltyLobby、Frequent Miler 和很旅行。
- 移除没有独立业务价值的 `opportunity_type`；使用最小的 `program / target_status / summary`、来源权威项目名与完整材料判断活动关系，后续只新增可空的申请开始和截止窗口，不新增合作方、地区、入口指纹等事件身份字段。
- 明确同活动跨文章聚合、延期作为更新、同品牌不同活动与不同时期新活动拆分，以及不确定关系保守分开并进入复核的行为。
- 在金标阶段完成后增加与审核状态独立的 `UPCOMING / ACTIVE / EXPIRED / UNKNOWN` 生命周期；过期事件软归档后退出自动候选池且不得自动恢复。
- 为七个来源统一配置一天采集周期，增加单轮调度、北京时间自然日幂等、数据库互斥、失败隔离、处理积压、生命周期推进和运行状态报告。
- 使用邮箱中当前全部符合标签和专用别名条件的 StatusMatch 邮件（2026-08-23 验证时为四封）完成只读真实联调和幂等验证；真实邮件正文不得进入仓库测试夹具或金标，GetStatus 在收到真实邮件后补充联调但不阻塞首期上线。
- 在安装外部定时任务前，把 2026-07-15 至 2026-08-22 的公开来源文章按北京时间每两个自然日一批顺序初始化入库；FFB 会籍汇总列表不受日期限制并全量处理。每批完成后必须回读真实原文审核分类、活动关系、事实证据、简报和生命周期，发现错误或新边界时立即停止后续批次并等待用户决策。
- 初始化审核发现同一证据的模型改写会被误判为冲突，且同一活动的多个资格、地区、价格和入口无法用单值事实表达；增加稳定事实复用和有证据的申请路径列表，缺失地域保持未知，只有项目名的简略邮件与详细材料继续保守复核。汇总邮件中只说明“各品牌要求不同、请查看活动页”的通用通知归为注意事项，不得作为具体申请资格；简报不得引用任何未知事实字段。经用户确认后，先备份并仅清理可从原始文档重建的派生业务数据，再用当前规则重新生成，不删除来源、邮件或原始正文。
- 通过第一期金标、真实来源端到端检查和短期自动运行观察后，将会籍主题转入维护并允许开始下一个主题。

## Capabilities

### New Capabilities

- `gold-baseline-runtime`: 运行第一期冻结金标、缓存真实模型输出、报告文档分类和事件分组指标，并以结果作为后续时效开发的阶段门。
- `status-event-lifecycle`: 从有证据的活动开始/截止窗口计算独立生命周期、软归档过期活动，只允许截止前明确延期更新同一事件，并把过期后的延期或重开拆成新事件。
- `daily-source-automation`: 对七个正式来源执行统一的一天采集、处理、生命周期推进、故障隔离、受控初始化和运行状态报告。

### Modified Capabilities

- `status-opportunity-pipeline`: 从正式来源中移除 StatusMatcher，并用现有事件语义加最小活动窗口强化同活动聚合、活动更新和跨期拆分。
- `event-scoped-status-processing`: 对明确判定为活动延期的 `UPDATE_OF` 允许截止时间形成新的当前事实版本，同时保留旧事实历史；普通来源分歧仍按冲突处理。

## Impact

- 影响金标评测 CLI、AI 运行缓存和评测报告。
- 影响来源注册表、来源工厂、CLI、StatusMatcher 适配代码及其测试和说明文档。
- 影响 `EventHint`、`StatusEvent`、`FactSet`、事件候选召回、关系判断、聚合、迁移和复核数据展示。
- 影响 FactSet 的 JSON Schema、事实协调和简报事实引用；不增加数据库列，旧派生 FactSet 在备份后通过受控重建退出当前业务状态。
- 新增每日单轮编排 CLI、运行互斥/幂等、来源运行状态、受控初始化和生命周期推进。
- PostgreSQL 仍是自动运行目标；模型、现有正文、证据、事实和简报历史必须保留并可重放。
