## Why

JourneyPlus 第一版需要先验证一条足够小、可反复迭代的信息生产链路：从已选第三方来源中发现会籍获取机会，可靠去重，并产出有证据支撑的中文原创简报。此前围绕官方来源跟踪和重规则抽取的方案成本过高，因此本次改为“轻规则保障边界与数据质量，AI 负责语义判断”的解耦实现。

## What Changes

- 建立仅面向会籍获取机会的采集管线，接入已确定的网页、RSS、目录页和邮件来源；采集频率保持未配置，留待后续决定。
- 保存原始材料，执行不删除业务语义的轻量技术清洗，并完成来源内精确去重、跨来源语义去重与事件聚合。
- 使用阿里云百炼（北京地域）的 `deepseek-v4-flash`，判断材料是否属于会籍获取机会、识别同一事件或更新关系、整理可追溯事实并生成中文原创简报。
- 建立最小人工复核与金标评测入口，让模型、提示词和规则可独立迭代并可重跑。
- 采用模块化单体和稳定接口隔离来源适配、AI 供应商、主题判断、候选召回、事件聚合、事实整理与简报生成，为以后增加少量相关主题保留扩展点，但不在本次实现这些主题。
- 明确第一版不包含买分、转分、信用卡、超值积分票/积分房晚等独立主题，也不包含个性化会籍持有、路径规划、推荐、通知或面向公众的完整产品界面。

## Capabilities

### New Capabilities

- `status-opportunity-pipeline`: 从选定第三方来源发现会籍获取机会，经轻量清洗、AI 相关性判断、精确与语义去重、事实整合后，生成可人工复核且来源可追溯的中文原创简报。

### Modified Capabilities

无。

## Impact

- 新增 OpenSpec 约束下的第一版采集、分析、聚合、生成与复核模块及其数据契约。
- 新增第三方来源访问、邮件只读接入、后台任务、持久化和阿里云百炼 API 集成需求。
- 后续扩展通过适配器和主题策略接入，不要求第一版预建通用规则引擎、微服务、向量数据库或跨主题关系图。
