# 正常网页验收标准

状态：待执行。下表是最低覆盖范围，不代表已通过。审计后补充真实场景输入与预期、固定知识版本，并在执行前确定重复次数与完成标准；不继承旧 change 的次数要求。

## 共同方法

每个 Agent 场景均从最终正常网页发起，关联同一服务、数据库和运行版本。先只替换 ModelPort 做人工双视角检查，再接第三方模型复跑。第一视角在决策时只使用实际送入 ModelPort 的上下文；第三视角事后核对工具返回、真实数据库及页面。AIWorkflow 验收使用正常生产入口，结果从正常知识页面与 Agent 交叉核对。

| 场景 | 第一视角/用户结果 | 第三视角核对 |
|---|---|---|
| 问候、一般知识 | 可零工具完成，不编造实时活动 | 无无关数据库读取、隐藏模型或强制流程 |
| 已有会籍查全部可能 | 能看到覆盖范围、多跳路径、资格和未知项 | 分页/遍历完整性分别核对，与正式图和源证据一致 |
| 目标、地区、费用筛选与比较 | 不偷偷改变条件，未知费用不当免费 | 参数、费用适用范围、币种和条件来自同一版本 |
| 详情、证据、简报与完整图 | 引用可打开，内容对应问题与版本 | 简报不是临时生成，图与路径共用正式事实 |
| 多轮补充、纠正、换话题 | 最新约束生效，能展开此前证据 | 原话、焦点和压缩历史无错误混合或漏读 |
| 假设与真实会籍 | 假设不自动保存，授权操作有真实回执 | 数据写入范围、事务、幂等与冲突行为正确 |
| 会籍增改删、等待创建及取消 | 实际完成才说成功，取消后状态正确 | 使用明确测试记录；无重复写、无触发知识生产 |
| 空库、无结果、资料未覆盖 | 区分没有候选、未知及系统未就绪 | 查询范围和错误码与实际库存、连接状态一致 |
| 工具失败、无效参数、预算耗尽 | 可纠正或明确未完成，保留已有结果 | 错误完整回送，无伪成功和无限重试 |
| 取消、刷新、断连、服务重启 | 状态可理解、结果可恢复 | 无丢失回执、重复副作用或错误续跑 |
| 长历史、大结果、多页读取 | 保留约束并能继续读取 | 无静默截断、假完整、重复累积；记录实际 token |
| 新邮件、官方来源、最新文章 | 知识页面可见正确活动、简报和图 | 从真实来源经正常 Workflow 入库，证据链可追溯 |
| 来源变化、重复处理、生产失败 | 更新可辨识，旧简报引用稳定 | 幂等、短事务发布、失败保留有效版本，无半发布 |
| 两板块独立运行 | Agent 停止仍可浏览知识；Workflow 停止仍可问已发布资料 | 无反向导入、隐式采集或模型依赖知识页 |

## 每次记录的证据

记录场景输入、执行时间、运行代码/配置/数据库版本、会话与请求标识、模型可见输入、调用参数与返回、数据/简报版本、页面最终结果、数据库效果、耗时和 token。配置密钥不入记录。失败、重试及修复后复验保留关联，不仅挑成功轮次。

判定使用通过、失败、阻塞、未测；无法从真实来源核对的语义正确性不能标为通过。第一视角结论与第三视角结论分别写出，再给场景结论。

## 完成门槛

目标边界、数据契约、重新生产闭环和关键网页场景全部有证据；发现的问题完成修复及相关场景复验。真实模型必须覆盖多轮、读写、错误恢复及广泛查询，不以单个问候通过代替。验收使用的正常启动方式与交付启动方式一致，运行代码与待交付工作区一致。

最后再比较上下文优化前后结果：正确性、覆盖与操作一致是前提，报告实际 token、调用次数、延迟及取舍。交付报告区分已通过、未通过和仍有的限制；不得仅凭测试总数宣称整个系统完成。
