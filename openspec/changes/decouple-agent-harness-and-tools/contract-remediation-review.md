## 已实施的系统改造

| 范围 | 最终行为与边界 |
|---|---|
| 身份 | BOUND / CANDIDATES / TIER_REQUIRED / NOT_INDEXED / INVALID_REFERENCE 分开；引用种类错误可修复，候选不自动绑定、不等于现实不存在。 |
| 用户会籍 | `source_record` 保存服务器读取的用户原始陈述，模型提取和目录绑定分别记录；原文随回执/journal保全。UI可展开原始陈述，未绑定名称明确待核对。**这保证可追溯，不保证模型提取正确**。 |
| 等待 | 共用 `RouteQueries.prepare`，未绑定条件保存 NEEDS_RECONFIRMATION，只有可执行条件才 ACTIVE。删除所引用会籍等失效情况可持久化暂停；后台不调用模型。无匹配仍是 NO_HIT。 |
| 查询 | QUERY_CONTEXT 保存父查询、字段变更和来源；默认值不冒充用户要求。失败身份查询也保存 QUERY，允许 patch 修正身份而保留预算/其他条件；不生成虚假路线。 |
| 展示 | 筛选符合、个人资格、挑战分开。比较表的条件、申请窗口和有效期按不可变步骤生成，保留版本；显示对象数来自实际对象。 |
| 上下文和预算 | 同值只读结果去重；无容量压力保留本轮证据，避免反复找回。软预算仅提醒。模型输出和已知工具批次分别做收尾预留，过大批次在执行副作用前拒绝，已完成操作仍保留。 |
| 能力与验收 | 暴露实际联网/搜索配置状态；记录每次实际请求体及所有请求用量（含探针）。评测增加逐轮展示、比较列、查询条件、会籍字段、等待状态检查。 |

harness 只处理通用事件、资源、持久化和效应。身份、查询准备、谱系、用户业务、展示各在独立服务中；工具不串调工具，模型仍可替换。没有品牌特例、意图路由、隐藏分类模型、固定工具链或 Workflow 触发。新增迁移 0028 仅为两个用户业务实体增加 JSON 字段；历史 journal 在不重写 payload/checksum 的前提下兼容新增默认字段。

## 真实复验结论

确实改善：W01完整保存名称并NOOP去重；WAIT绑定正式项目后ACTIVE，后台检查NO_HIT；未收录目标不会假装可执行；修正预算后A05五轮均能收尾；R03日期修改没有改变等级；明确数据驱动比较表的事实直接对应数据库。

仍未达标：

1. **参数与用户意图不一致仍可能执行。** H02主动清除HOTEL限制；R03提取名称漏掉“验收”前缀，R02等待目标也漏前缀。原始陈述与谱系完整记录了这些差异，但没有把自然语言解释变成已验证事实。
2. **自由文本仍可能超出证据。** A04新增无来源的联盟、权益与政策说明；A16把个案经验外推成联盟/成功概率规则。数据库返回正确，不意味着最终表述已获证据支持。
3. **任务交付仍可能遗漏。** P01三个保留的尝试均未产生图卡回执。R01首轮只有Markdown表，第二轮虽展示但未选择所需条件列。此前整案例“出现过一次工具成功”会漏掉这种问题；现在逐轮与列检查能抓住。

因此，本轮只能确认数据保全、引用、就绪状态、可恢复上下文和确定性展示链路已加强，**不能声称“换任何模型都完全正常”或正确性已修完**。未覆盖剩余门禁的完整64次验收，不反复跑失败批次凑次数。
