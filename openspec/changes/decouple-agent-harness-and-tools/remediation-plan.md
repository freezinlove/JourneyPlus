# 审计问题修复方案

日期：2026-09-09。基线提交：`0dac715`。对应 [独立审计](independent-audit.md) 的 F01–F11、C01–C04；遵循 [实施总纲](charter.md)。本文件是待实施方案，不是修复完成记录。

## 1. 目标与改造尺度

15 项都建立明确关闭条件：功能缺陷通过实现和复验关闭；性能问题通过测量及必要优化关闭；证据缺口通过行为映射和补验关闭。既不为追求小 diff 保留不合理职责，也不为形式统一重建整个项目。

目标仍是可替换模型、通用 harness、独立工具、明确业务服务和数据访问。继续共享现有数据库、已发布知识与纯计算算法；本轮不引入微服务、消息队列、向量记忆、额外模型或分布式缓存，不改 Workflow 采集/提取/发布流程。

涉及公共返回字段的语义调整，先更新 tools/storage-context/runtime/presentation-api 对应约定，再同步实现和测试。需要新增持久字段/索引时创建 additive migration，不修改已经应用的 0026、不删除既有用户操作或原始证据。

## 2. 第一板块：运行与访问边界（F01、F02、C01、C02）

### F01：产品业务与模型启动解耦

- product 应用自行构建普通业务页面及路由，Agent 作为明确装配的能力接入；不再由 Agent 应用反向承载整个 product 生命周期。
- 区分 Agent 禁用、初始化中、可用、不可用。禁用/人工模式不创建模型客户端，不探测，不消费等待真实模型执行的 run。
- 正常启用模式下，模型初始化不阻塞普通页面对外服务；初始化失败保留可诊断状态，只有需要模型的新请求返回明确不可用。失败清理已创建资源，不无限自动重试或偷偷切换模型。
- 独立 Agent 与独立知识入口继续保留；共享装配代码，避免复制路由实现。
- 验收：无配置、配置错误、初始化失败、初始化慢、正常初始化五种情况，普通业务页面均可用；禁用模式客户端创建次数和探针次数为零。测试只使用本地替身。

### F02：建立真正可响应取消、超时和心跳的执行边界

- 网络工具维持原生异步；现有同步 SQLAlchemy/确定性业务计算通过有界执行器运行。每次操作在执行线程内创建、使用、关闭自己的 Session，只返回 DTO，不跨线程共享 Session 或 ORM 实体。
- harness 使用异步存储端口，适配器负责同步数据库工作的隔离；不能只处理 handler 而留下 checkpoint、snapshot、事件读取等阻塞主循环。
- 同一工具期限贯穿排队、获取连接、锁等待、语句和计算；配置 PostgreSQL statement/lock timeout 及连接池超时，计算循环检查期限。并发限制进入执行器前生效，避免无限排队。
- 取消后不启动新动作。已经开始的同步写入不能靠取消 await 宣称停止：通过持久 intent、执行所有权校验、原子回执确定实际结果；提交中的操作按真实 commit/rollback 收口。失去 lease 的旧执行者不得在新 owner 接管后另行提交，锁顺序统一并有期限。
- 运行终态和完成操作列表必须与最终数据库结果一致；不能先宣布未写入，再留下线程晚到提交。
- 验收：真实隔离 PG 锁等待/慢查询、三路业务读并行、排队取消、写入前取消、提交竞争、旧 owner 接管；同时验证 SSE 和心跳继续响应。固定 sleep 的假 handler 仅作辅助。

### C01：按真实职责补齐端口

- 补齐运行存储的 claim/checkpoint/heartbeat/cancel/intent/result/finalize 契约，使声明覆盖实际调用；模型生命周期与能力接口也明确声明。
- ExecutionContext 使用具体的授权读取、artifact、业务服务接口；工具不得经 authorization_port.factory 获得任意数据库事务。
- 笔记/展示的存储原子操作移入工作区存储适配器，展示服务保留确定性构建和对象验证。数据库事务、唯一性与并发留在适配器，不搬进 harness。
- 不做一个方法对应一个空类；端口只在真实替换边界和事务职责处建立。
- 验收：运行核心可替换存储/模型；业务服务可替换只读知识和用户数据端口；架构检查涵盖方法契约及禁止的具体存储穿透，不只检查 import 名称。

### C02：知识读取和用户数据读取各归其位

- 路线服务通过用户数据端口取得明确会籍快照，返回 holding ref/revision、解析和未解析范围；通过知识端口取得目录和发布版本，纯算法只消费明确输入。
- UserMemory 的目录解析使用知识端口；用户变更、journal、operation receipt 保持同一用户数据事务。避免为了跨层读取长时间持有用户锁。
- WaitingService 复用同一确定性查询服务，不互调工具 handler；保存查询、读快照、条件检查和提交结果分清责任，提交前校验目标 revision 未变化。
- 装配入口落实独立知识读取连接配置，默认仍可指向同库。支持同一库的受限只读凭据，不承诺本次实现任意独立数据库之间的一致性。
- 验收：知识凭据只获正式知识所需读取权限时，saved 路线及等待仍通过用户端口正常工作；用户操作/网络/展示均不改正式知识，Workflow 无需运行。

## 3. 第二板块：用户操作与展示一致性（F04、F06、F10、F11）

### F04：调用身份统一到工作区、轮次和调用

- 为工具产物保存明确 turn/call 来源；展示幂等、块 ID、事件和历史附件统一使用相同作用域。
- 同轮同调用同 payload 返回同结果，不重复创建；同轮同调用不同 payload 返回冲突；不同轮次复用 provider call_id 是合法输入，必须产生各自结果。
- 唯一约束仅用于应当唯一的展示/投影，不能给所有 artifact 的 kind/call 加通用唯一约束，因为一次读取可能产生多个物料。
- 旧产物优先从已有 ToolCall/结果引用恢复归属；无法唯一恢复的历史记录明确保留为历史未知，不能猜一个 turn 挂上。
- 验收：跨轮相同调用 ID、同轮重试、不同 payload、恢复和浏览器刷新；展示对象/顺序/附件归属均一致。

### F06：授权引用逐段绑定真实来源

- 保留模型负责授权语义的原则。服务逐段建立 quote 与消息来源的绑定，校验角色、工作区、原文和 legacy 属性。
- 用于授权的引用必须能落到非 legacy 用户原话；不能靠增加一个未被引用的新消息 ID 激活全部旧授权。
- 导入消息可提供会籍名称等背景；用户新说“保存上面那张”可授权，身份可来自背景，不要求重复所有信息，也不强制再次确认。
- 已存在操作重放仍按原授权快照验证幂等；不得用新的来源绑定规则改写历史成功事实。
- 验收：全 legacy、混合 refs 但仅旧 quote、伪造 quote、网页/笔记来源均拒绝；真实新授权引用旧对象成功。拒绝时 holding/goal/journal/receipt 零变更。

### F10：区分持久回执和临时读取视图

- 持久 operation_ref、操作类型、before/after、授权快照为业务事实；同 key/payload 重放不得变化。
- 大型历史路线通过临时视图展开。在同一存活工作区、同一 receipt、同一投影版本下复用引用，避免每次 list/retry 复制相同内容。
- 工作区过期或进入另一工作区时允许生成新的作用域引用；新引用必须明确关联同一持久回执，不要求临时 UUID 永久相同。
- 投影在用户事务提交后执行，读写重放走同一条路径；投影失败不把已提交操作说成失败或回滚，保留可读取的 operation_ref 和投影错误。
- 验收：同工作区重复调用引用稳定、无额外同内容产物；跨工作区不越权；提交后投影失败、取消/恢复、TTL 清理后持久回执仍真实可查。

### F11：身份更新冲突返回可操作的业务结果

- 更新身份时检查目标 program_key 是否被另一张会籍占用；保留数据库唯一约束作为并发兜底。
- 只把对应唯一约束冲突转成 CONFLICT，返回冲突记录 ref/revision 和原因；其他数据库故障不能伪装成业务冲突。
- 不自动合并、覆盖或删除另一张会籍；模型根据用户意图决定下一步。
- 验收：更新到现有项目、并发创建/更新、旧 revision、原身份不变；冲突无半条 journal 或成功 receipt，不标盲目 retryable。

## 4. 第三板块：结果与上下文保真（F03、F05、F07、F08、F09）

### F03：正常执行与恢复使用同一结果交付路径

- 分开完整存储结果和模型可见投影；缓存命中不再提前返回原始 payload。
- 完整结果引用、投影规则版本及必要恢复元数据持久化；恢复复用已有投影或按同一版本确定性生成，遵守单结果/单批预算。
- 验收：分别在结果保存前后、tool 消息追加前后注入故障；模型得到相同证据范围、call 配对及展开入口，无重复用户副作用。

### F05：解析范围属于不可变路线快照

- ROUTES 同时保存原查询、实际计算输入、holding 快照、resolved/unresolved、知识版本与覆盖限制。
- 首页、续页、inspect/compare、等待结果和展示均能回溯该来源范围；多条路线来自不同查询时分别表达，不合成隐式最新目标。
- 区分候选读取完成、已解析起点搜索完成和全部用户起点参与计算；旧快照缺失范围时标未知，不能默认完整。
- 验收：已解析+未解析会籍多页、读取期间会籍变化、历史恢复、跨查询比较，范围和版本不漂移。

### F07：裁剪与覆盖元数据联合生成

- 工具负责有语义的摘要和原子条目；关联的候选/ref/版本/限制必须成组投影，不能任意独立 pop 列表。
- 区分原始总数、工具页返回数与当前模型可见数；无法定义统一条目数量的混合结果使用明确分组统计，不虚构一个总 returned。
- 通用 harness 只执行预算及通用封装，不识别会籍业务字段。工具投影仍过大时返回明确索引/完整引用，不伪装已经读过正文。
- 源分页游标与投影内未读条目分开表示；不能让模型顺着 next_cursor 跳过本页被裁的记录。
- 验收：大条目、多列表、同批八工具、单页裁剪后继续读取；数量与实际内容一致，所有遗漏可定位，必要条件不被拆散。

### F08：所有 workspace.read 分支落实 limit 和字节上限

- history、artifact、notes、presentations 的分页单位分别写明；limit 限制条目/章节数，字节上限可进一步减少数量。
- 游标绑定工作区、原快照、refs/query 和分页规则；连续翻页无重复/缺失。单个过大章节保留来源和连续位置，不无限重复同一大对象。
- 验收：limit=1、多个小对象、一个大章节、query 搜索、笔记更新、跨会话/错游标，直接读取和续读语义一致。

### F09：解析结果携带原文覆盖信息

- REPORT 保留 PAGE 来源、版本/观察时间、下载/保留截断、可恢复范围；区分网页完整性、报告正文完整性和解析是否成功。
- 不把页面导航缺失一律视为报告不完整；能够证明正文完整时可保留其解析结论。不能证明时标明未知，限制成功/拒绝/挑战结论。
- 在当前保存快照内部继续读，不能声称找回从未下载的后缀；需要刷新则由模型选择 web.read，不由解析器隐式联网。
- 验收：正文中途截断、正文完整但页面尾部截断、缺字段、长报告、多个页面，解析结果及最终模型可见内容保留覆盖差异。

## 5. 第四板块：数据库效率和覆盖证据（C03、C04）

### C03：减少重复全量读取，按证据决定额外优化

- 先记录实际隔离库及固定扩大量级 fixture 的 SQL 次数、读取行数/数据量、服务耗时、事件循环延迟和模型输入字节。数据库性能与 token 开销分别统计。
- immutable artifact/cursor 查询直接绑定自身快照，不再为了重复调用检测重读整个发布库。
- 新查询指纹读取必要的 ID、版本、目录/观察状态等元数据，不加载全部历史 facts/payload。指纹必须识别相关新增/修改/删除，不能只用 MAX(updated_at) 冒充完整变更检测。
- 目录精确绑定使用数据库过滤；同批身份解析共享明确读取上下文。历史/产物检索把可执行过滤和分页下推数据库，并保留原来的邻接消息和快照语义。
- 若仍有瓶颈，再依据执行计划增加必要索引或复用一次请求内的数据；不预先引入跨进程缓存或新变更追踪系统。
- 验收：正确性结果不变；翻旧 artifact 页不扫描正式版本表；精确 ID 查询不全量装载目录；相关数据改变时检测仍正确。保存扩容前后数据，未达到可解释改善不得仅凭“代码更短”关闭。

### C04：补齐保留行为与新验收的对应关系

- 以基线父提交中删除的 197 个测试函数为索引，按行为标注：被新规格明确废弃、已有新验证覆盖、缺少覆盖。一个旧测试包含多个行为时拆开记录。
- 对缺少覆盖且仍有效的行为补测试；重要组合补人工 ModelPort/PG/浏览器验收。无需恢复旧固定工具顺序、关键词控制或固定确认流程。
- 将无敏感数据的审计复现转为正式回归，旧失败原始记录继续保留。F10 等断言按已经明确的业务契约校准，不机械追求让最初断言全绿。
- 验收：六项规格、S/T/W/R/P/I 与旧保留行为均有可检查证据；没有无说明的缺口，不以测试数量当完成率。

## 6. 执行顺序与最终验收

1. **建立修复基线**：冻结审计复现、开始 C04 映射、采集 C03 基线；在新日期目录保留证据，不能覆盖 20260908 失败。
2. **运行/端口边界**：F01/F02/C01/C02 一起处理，避免逐个打补丁后重复搬迁。
3. **操作/展示一致性**：F04/F06/F10/F11，真实 PG 验证事务、并发和恢复。
4. **结果/上下文保真**：F03/F05/F07/F08/F09，统一契约后复验每个工具，而非仅修改提示词。
5. **效率与证据收口**：C03 优化及测量、C04 映射补齐；每个板块完成即局部人工验收，不等最后才看真实输入输出。
6. **完整人工验收**：由实施者坐在真实 ModelPort 位置，依据每次实际输入决定下一次调用，使用修复后的 12 工具及多轮记忆；第三视角核对 PG、回执、版本、覆盖和 UI。自动故障注入与人工判断分开记录。
7. **重新交付审核**：全回归、真实 PG 故障/并发、浏览器、隔离哈希、OpenSpec strict；逐项报告已修复/自动验证/人工验证/待模型验证。任何系统阻塞项仍存在就继续修复，不提前移交模型排查。

第三方模型 API（包括探针）、Workflow 模型、生产发布和自动归档继续禁止。上一轮提交仅保存了基线；本方案和后续实施默认留在工作区，未经新的提交要求不自动提交。
