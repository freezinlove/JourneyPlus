# 系统侧审核包

> 2026-09-08 复核更新：本页原有“已具备系统侧交付条件”的判断已被 [当前工作区独立审计](independent-audit.md) 否决。原证据保留，但本轮发现 11 项可复现问题；当前应先修复和复验，不能进入第三方模型验收。

本页是 [实施总纲](charter.md) 对应的阶段交付，日期为 2026-09-08。范围是接入第三方模型之前的系统实现、人工 ModelPort 调试与本地验收。真实模型最终评测仍待用户审核批准，不能把人工执行结果算作模型成功率。

## 1. 当前架构

- `agent/harness` 仅负责消息、注册器、资源预算、运行状态、取消和恢复；不导入 SQLAlchemy、知识业务、旧 Controller，也不判断用户业务意图。
- `agent/adapters` 负责模型协议、流式传输、会话/工具日志、artifact 与回执持久化。模型通过 ModelPort 替换；人工 ReviewerModel 和无模型 UnconfiguredModel 已实际接入同一个运行核心。
- 12 个工具各自声明输入、输出、effect 和结果容量，通过显式服务协作。没有 handler 相互调用的隐藏工作流，没有 PLAN/RESOLVE、意图路由、强制目录前置或自动推荐覆盖。
- 用户会籍与等待服务执行确定性操作；用户原话引用、幂等键、修订号、journal 和 durable receipt 分工明确。工具验证引用与逐字原话的真实性；是否构成业务授权由模型理解，程序没有用关键词分类替代模型。
- Workflow 的提取、采集和发布仍归原业务链。每日 automation 已不再导入或唤醒 Agent。Agent 的等待检查与临时清理由独立 maintenance 负责，不调用模型。
- 知识、简报和完整图有独立只读 API/页面。Agent 读取已发布版本并保存版本引用，不触发 Workflow、不修改正式目录或发布记录。共享数据库不等于共享控制流程。
- v1/v2 Agent 写入口统一返回 410；旧会话仅保留原文读取与显式导入。导入不携带语义 flags，不执行旧 pending_action。原业务页面继续保留。

旧链清理删除 31 个不可达的旧 Agent 模块、旧工作区前端和旧评测脚本。相应 30 个旧行为测试文件退役；保留了私有源码/测试备份和删除映射，以新协议、历史导入、独立业务及数据回归替代。不能用新旧测试数量直接比较覆盖率。生产模块中最大的新增持久层为 393 个非空行，模型适配层为 312 个非空行；没有把旧 WorkspaceService 整体搬进新目录。

## 2. 人工输入输出发现与修复

| 问题 | 修复及复验 |
|---|---|
| 等待结果把整个图的步骤复制进 before，更新后 after 被投影挤掉 | 只存命中路线使用的步骤；历史结果通过带原查询的 ROUTES artifact 返回。复走创建→后台命中→查看→更新→取消，after 可见，旧结果不会充当新命中。 |
| 等待更新/取消残留旧 result_id 和签名 | 显式清空 pending/result/signature；旧格式结果只读保留，不按新路线结构解释；列表分页并绑定修订快照。 |
| 写参数可以提供实际未使用字段 | 按 operation 拒绝无效组合；到期日验证真实日历日期，省略与 null 区别明确，身份不能被 null 清空。 |
| 价格 evidence 一次塞入详情、映射和整组来源 | requested facts 与可展开原文分开；金额、适用等级、例外条件和版本仍随结果返回。完整工具结果从 40,328 字节降到 9,868 字节，人工重新核对 149/49 美元及“除非另有说明”。 |
| 资料检索命中整个 option 后返回无关字段，甚至 UUID 含数字也命中价格搜索 | 搜索使用带身份/版本的细分章节；UUID 不参与正文匹配。命中长来源保留整段的续读入口，不把剩余条件永久丢弃。 |
| 页面刷新把旧卡片放到所有新消息之后 | presentation/operation 通过原 call_id 关联到当时的 assistant 消息；浏览器确认卡片、正文、追问顺序正确。 |
| schema 去标题时误删名为 title 的业务字段 | 只去除 schema 注释，不删 properties 中的真实字段；协议契约回归覆盖。 |
| 旧入口在 rollback/unified 模式被其他错误掩盖 | 退役优先返回 410。无模型预览可启动；禁用网络时不运行搜索后端探针。 |
| 上下文装不下仅报笼统运行失败 | 明确返回 CONTEXT_CAPACITY/PARTIAL，保留完整历史、结果和已提交操作；不进行有损语义重写。 |

首次失败全部保留。`charter-final-tools` 的价格展开未完成，虽然运行正常结束，也不计任务语义通过。`charter-material-fixed` 的末条人工输入含未转义换行，导致本地 JSON 输入失败并结束为 PARTIAL；已修复人工输入提交方式并保留记录。`charter-material-final` 同类任务以及后续比较、等待分页、转闲聊四轮均实际完成。

## 5. 数据与上下文核对

真实隔离 PostgreSQL：`journeyplus_eval_review_20260908`；对照只读模板 `journeyplus_eval_formal_template_20260908`。44 张非 Agent、非用户操作业务及来源表逐行规范化哈希一致。四张新增运行表的外键、索引、唯一约束已核对；operation_receipts 不依赖临时 workspace 外键，避免清理工作区时删除成功操作凭据。

人工会籍创建、清空日期、删除的 before/after 链与三条 journal 一致，最终会籍记录不存在。修复后等待任务有三个用户操作回执和一次后台检查 journal，最终 CANCELLED、pending/result/signature 已清空。笔记、路径、调查和展示任务没有用户业务写入。artifact 内容哈希及工具结果工作区归属核对通过。

51 份本次人工请求的 wire 输入中位 31,134 字节、最大 61,023 字节，包含工具定义和所选历史；这是字节统计，**不是 provider token、价格或真实性能**。较复杂的证据对比仍比简单回答大；保留完整调用配对和必要条件，旧完整轮次通过 history 找回，没有额外摘要模型。预算可配置，达到容量后明确停止，不以删掉条件来降低统计值。

## 6. 审核边界与剩余工作

当前阶段不启动模型客户端或 provider 探针。无模型回放页仅展示人工运行已经产生的数据，输入新问题会报告 MODEL_NOT_CONFIGURED，不会后台换模型。

待用户审核批准后，才执行真实第三方模型协议确认、64 case-run、正确率/澄清/无效调用/真实 token/延迟统计和最终 UI 语义验收。优先使用百炼/千问的适当低价模型，不选 Max 等高价档。更换模型不会改变业务控制链，但其语义能力和协议支持仍需实测，不能承诺所有模型表现完全相同。

当前数据自身存在未发布活动、未知资格/费用/挑战、未收录别名，系统如实披露；本阶段没有启动 Workflow 回填数据让样例通过。通用搜索 provider 未配置，StatusMatcher 内置公开发现可用。此前默认本机库意外升级的披露仍在 verification.md，不能把本次隔离库哈希一致扩展为“历史上默认库从未变更”。

所有代码与文档保留未提交；不自动归档，不部署生产，不执行数据库 downgrade。
