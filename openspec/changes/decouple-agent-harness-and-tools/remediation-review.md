# 审计整改审核包（第三方模型接入前）

本轮在 `0dac715` 工作区基线上落实 F01–F11、C01–C04。所有第三方模型、探针和 Workflow 模型调用均为零；人工接入使用 `scripts/review_agent_harness.py` 的 ReviewerModel，每次读取实际输入后再提交下一次决策。公开网页仅由独立 web 工具读取。未提交 Git、未部署生产、未归档 change。

## 1. 当前架构与分工

- 模型通过 ModelPort 接收消息与工具定义，返回文本或工具调用。业务流程、查询顺序、展示选择不编码进 runtime，也不依据品牌或关键词决定下一步。
- harness 管理生命周期、预算、调用校验、执行隔离、租约、取消、恢复、历史编排和事件；数据库适配器实现事务与持久化。
- 工具以明确参数独立调用服务；会籍与等待任务通过用户数据侧读写，路线计算共同使用 RouteQueries。等待检查调用确定性查询服务，不调用模型或另一个工具处理器。
- 正式知识通过 KnowledgePort 只读查询。受限知识账号无需读取会籍或 Agent 表；用户会籍由独立连接形成 HoldingSnapshot。可配置同一数据库的不同凭据，不引入双库同步系统。
- Workflow、采集、发布、活动简报与关系探索有独立入口。Agent 读取已发布知识，并引用带版本的简报；普通页面启动不等待 Agent 模型初始化。没有将 Agent 重新做成固定 AIWorkflow。
- WorkspaceAccess 只暴露历史、引用验证、笔记、展示和回执查询能力；workspace/display 服务不再通过授权对象取得任意 SQL factory。并未引入插件框架、跨进程缓存或通用工作流引擎。

### 人工过程中真正发现并修复的问题

1. `manual-core` 第二轮比较/展示已经成功，但旧工具正文累积导致最终输入预算不足，最终为 PARTIAL。保留此失败；修复旧轮次投影后同任务两轮均完成。
2. `manual-context-fixed` 是人工未及时输入导致的超时，保留记录，不算模型或工具正确性失败，也不算成功验收。
3. `manual-research` 在工具执行前 FAILED。原因是快照将目录的字符串 query 当成路线对象；修复类型边界，增加完整 runtime 回归，`manual-research-fixed` 通过。
4. 身份解析失败最初可能默认 coverage.complete=true，已统一失败覆盖为 false；未解决来源与空检索明确区别。
5. 最后审查补足观察状态、当前窗口和日期变化的快照输入，避免过度优化使重复检测失真；完整当前 facts 未重新全量装载。

## 4. 上下文策略与效率边界

用户原话、当前轮工具配对和当前证据不被规则改写；完整工具返回持久化为不可变产物。仅已结束轮次中超过 3 KB 的工具正文按工具声明的原子条目关系生成有界投影；省略明确标为 index_only / older_turn，并提供 full_result_ref、原覆盖与遗漏。索引不证明事实完整。需要旧细节时重新 inspect/compare/workspace.read。本轮已实际恢复原话和被省略的第三条路线。

这不是摘要模型，也不从历史推导隐藏任务状态。小结果和未知事实仍保留；全局窗口按完整旧 turn 移出，并暴露历史入口。替换模型仅影响决策核心，不改变该协议。

核心失败轮在仅 3 次请求后已累计约 48,226 个**估算输入 token**，无法容纳最终回答请求。修复后相同两轮任务完成；具体每轮/每请求 bytes 与估算见原始 request 和 checkpoint。这个数字累计了多次请求，不是单次上下文，也不是供应商计费 token。固定工具 schema 仍有成本；没有通过隐去必要工具或压掉当前条款来追求最低 token。
