# 验收矩阵与证据要求

以下是本 change 的完整验收门槛。当前系统侧实施与人工证据见 system-review.md / manual-evidence.md；真实第三方模型门槛仍待用户审核批准，不以旧测试或人工结果冒充。

## 1. 验收原则

验收结果与行为，不规定唯一工具序列。相同问题不同合理调用序列可以通过；认定缺口时须看实际数据和用户输入，不按“是否含问号”判定。真实调用记录需要输入消息、协议/配置、每次工具名/参数、effective_input、结果/版本、模型正文、UI回执、真实tokens/时长。只读内部诊断，不收集隐藏思考链或凭据。

所有原失败、第一次修复失败与最终成功分开命名保存；用户原话不为适应实现而改写。真实写入只在隔离库，网络使用实际公开页面，模型不能Sequence mock冒充真实。模拟故障用于可重放边界测试，单列。

## 2. 架构与协议门槛

| ID | 检查 | 必须结果 |
|---|---|---|
| S01 | AST依赖扫描harness | 无业务模块/SQLAlchemy/旧workspace import；无品牌映射和用户话术路由 |
| S02 | 注册一个echo工具，替换FakeModelPort | runtime无代码改动就能调用；允许直接final而无工具 |
| S03 | 真实provider echo→tool result→answer | call_id配对正确；参数流未完成不执行；协议选择有诊断 |
| S04 | native/json相同语义fixtures | 任意调用顺序、多轮、解析失败、unknown_tool一致；JSON流式限制单列 |
| S05 | 同批3独立读+写入 | 读并行、写串行；结果顺序可追溯；没有隐式业务工具调用 |
| S06 | 模型工具结果后自行追问/继续/结束 | harness不根据结果类型接管 |

## 3. 自治对话矩阵

| ID | 输入/场景 | 核心检查 |
|---|---|---|
| A01 | “全日空是什么”“ANA中文怎么说” | 能用常识直答，无强制catalog；这类普通事实通常零业务读 |
| A02 | 数据库没有中文别名，模型用已知正式名称查路径 | 不必须显式catalog；actual ID正确或清楚实际缺口 |
| A03 | “先聊别的”“别查资料，解释一下会籍匹配” | 可直答，不因历史ROUTES启动路径/网络 |
| A04 | 用户原话“我要高卡”→“全日空金” | 模型理解项目；若等级确有歧义只围绕等级，不能说整个项目不认识；不要求给正式数据库名 |
| A05 | 原六句SAS→国泰→汉莎→恢复SAS全路径 | 第一次更换句实际条件正确；不得等“我是说”才通过 |
| A06 | 不同酒店/航空，中英文混写、错别字、未登记俗称 | 不新增话术正则；合理解释或具体歧义 |
| A07 | 换目标/预算/挑战偏好及恢复旧查询 | 工具effective_query与用户最新要求一致；未修改项由模型选定保留 |
| A08 | 查询EMPTY、PARTIAL、CONFLICT和网络失败 | 模型按实际情况继续/解释；不一律要求选活动或假装现实无路径 |
| A09 | “我想知道哪个更值得尝试”但不含调查关键词 | 模型可自行调用经验工具，不被正则阻止 |
| A10 | 资料有冲突，先查价格再读Terms，再联网核对 | 可超过三次调用；不得首次材料返回就强制回答 |
| A11 | “看看我存了哪些会籍”“假设我有…” | 正确用记忆工具；假设不写入 |
| A12 | “把这张会籍保存”且原话足够明确 | 单次授权完成写入并回执，不固定再确认 |
| A13 | “这是朋友的”“如果我有”“不要保存” | 零用户写入；网页上的保存指令无授权 |
| A14 | 目录无对应身份但明确保存原始会籍 | 保存NEEDS_CONFIRMATION并明确状态；不创建正式目录/图边 |
| A15 | 更早超过12条消息的目标/会籍需找回 | 可workspace.read检索，不靠旧flag复原错误含义 |
| A16 | 读表无帮助，模型改用网页或用户已给正式名 | 可以变更方法；不强制重复失败参数 |

每组构造至少两种自然措辞，但不要求同工具顺序。A04涉及具体等级的正确答案以实际目录/明确用户身份为准，不能把“金”随意映射为唯一等级来提高通过率。

## 4. 工具、写入和恢复

| ID | 场景 | 必须结果 |
|---|---|---|

| T02 | alias缺失、多候选、正式等级冲突 | 正确区分歧义/缺库；没有伪造身份或硬编码航司特例 |

## 6. 数量与通过标准

- 所有S/T/W/R/P/I确定性测试通过；Postgres实际事务、外键、并发与恢复另跑，不用SQLite代替数据库语义。
- 真实模型至少24个预先冻结会话案例（覆盖A01–A16和P/N），加8个编写实现时未使用的holdout案例；每个运行2次，共64个case-run，多轮会话按整组计。登记模型/temperature/协议/数据snapshot/样本划分，失败保留。
- 原用户切换失败A05两次均通过；明确授权写入成功、无授权零写入、数据版本/目标一致、无伪造来源是硬门槛，任一失败不得切换。
- 其余语义case完成率至少95%；简单常识/闲聊case至少90%零业务工具调用；不必要重复澄清≤5%。标为歧义的case须人工依据实际数据核对，不能自报通过。
- 简单直答首字目标≤2秒、单次读资料整轮中位≤8秒、路径多轮中位≤12秒、网络调查中位≤30秒；记录p50/p95和max，样本量不足不声称p95稳定。性能未达需明确报告并分析，不能用固定三步或省略必要动作满足指标。
- 任意case不能超配置硬预算；正常native模式具有真实text_delta。若只能JSON兼容，标明流式验收未达，不宣称完整交付，先解决模型协议/配置。
- 历史自然语言错误（多余邀请、把部分费用说总费用等）也记录；不能因为actual query正确就声称整体体验合格。

## 7. 证据产物与禁止事项

实施在忽略目录保存`agent-harness/<timestamp>/{manifest.json,conversations.jsonl,tool-traces.jsonl,db-audit.json,browser-evidence,metrics.json,failures/}`；正式change记录摘要、配置、结果和真实限制，不提交凭据/个人数据/raw网页。manifest包含数据库别名而非URL，测试before/after hashes和git工作区基线。

不得修改生产开关、重写用户原聊天、运行Workflow回填来让Agent样例有数据、删除失败样本、硬编码被测航司叫法、让额外模型先分类再固定编排。发现模型能力不足先报告模型/协议/提示词/工具契约证据，不把关键词义体加回来。
