## 第一视角与第三视角对应

- **工具数据与数据库**：对 32 个案例数据库和 1 个浏览器补验库做独立只读审计。44 张正式知识／来源表的内容哈希与冻结模板一致；原始两项会籍未变。21 个明确禁止用户写入的案例，journal 增量均为零。
- **路线事实**：独立 SQL 核对 18 份路线快照、98 条路线实例、124 个步骤实例、108 项费用、403 项条件。发布版本、活动、选项、映射起终点、步骤连接、费用币种／角色／金额和条件原文一致。该检查不证明外站政策当前仍有效，也不证明知识库覆盖整个现实世界。
- **真实展示**：从 A06 完成库复制浏览器专用库，真实页面显示模型指定的 3 条图卡和主／备选顺序。点击皇家约旦 Silver Jay 节点，服务端保存相同 step 引用。模型收到该焦点后读取同版本资料，回答对应酒店匹配、49 USD、证件限制；刷新后图卡与追问正文恢复。该补验只证明这一条焦点链路，不能抵消 P01 未展示问题。

- **等待任务**：真实 provider 只完成创建不能视为监控通过。另用禁模型检查器执行同一等待服务，确认 CATALOG_GAP，model_calls=0。

## 下一步优先级

1. 先修实际业务闭环：等待目标必须可绑定或明确处于未就绪状态；原始会籍名称与授权原文的联系需保留，不能静默改名。
2. 减少身份解析中的无效往返：明确 program/tier/holding 引用区别，返回可直接继续的候选及错误范围。保持模型自主选择，不添加航司话术路由。
3. 检查证据与语义约束：MATCH 不是挑战分类，未解析不是不存在，名单不能增补，查询约束不能静默放宽。以本轮原始失败对话复验，不用新增品牌特例绕过。
4. 处理影响完成率的上下文／收尾：避免相同目录和结果重复携带，为必要展开和展示保留空间，检查软预算后的协议遵守及最终正文。不能靠提高预算或删除关键条款掩盖问题。
5. 明确泛搜索配置与内置站点发现的能力边界，避免模型反复选不可用能力。

上述为本轮证据支持的整改方向，尚未实施。本轮没有更换更贵模型来掩盖失败，没有改生产开关，没有提交新 Git 记录，也没有勾选尚未通过的 G1–G5／64 次最终验收任务。
